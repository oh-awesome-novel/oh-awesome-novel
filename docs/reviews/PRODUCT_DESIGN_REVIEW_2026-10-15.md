# 定位与产品设计评估（2026-10-15）

> 性质：带日期的产品设计评估与决策记录，不替代稳定合同。实施状态以 [1330](../tasks/1330.md) 与 [1340](../tasks/1340.md) 为准。
> 范围：理念、功能与产品设计；不评估代码实现细节。

## 背景

2026-10-14 对 `docs/` 与 `wiki/` 做了一次产品设计评审。评审结论是：filesystem-first、Git 历史、人工审批、带原文证据的 `/整理本章` 与公开创作宪法值得坚持；但写作主流程存在断点，且定位与目标用户不清晰。

作者随后明确了真实意图：

- 项目没有商业化考虑，不以商业出版、网络连载或多人协作为目标。
- 主要用途是写同人综漫小说；涉及多部作品版权，基本不可能商业化。
- Play 模式按作者个人需求加入：可以在原作或他人作品上通过 Play 改写剧情发展（类似作者本人穿越），不需要从零写新小说。
- 有些脑洞仍需要从零写，因此核心写作闭环必须打通。
- 软件不再定位为“小说 IDE”；Play 保持高优先级。

## 新定位摘要

见 [PROJECT_VISION.md](../PROJECT_VISION.md)：个人同人/综漫故事创作工作台，Play 推演与 Writing 写作双核心。

```text
旅程 A（Play 优先）：素材 → Guided Start → 穿越/导演推演 → Outcome / Writing Reference → adoption → 写成章节
旅程 B（从零开写）：新建 → 规划 → 写下一章 → 审稿 → 定稿 → 整理本章 → 写下一章
```

## 仍保留的原则

- 所有 canonical 写入仍需 Accept；分级只改变审阅形态，不新增写入路径。
- Runtime 保持 Aider-style，单一 Sandbox Change Engine，不引入多 Agent。
- 小说事实只在文件树与 Git 中。
