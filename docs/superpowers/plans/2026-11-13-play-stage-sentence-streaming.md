# 1620 舞台模式逐句流式演出实施计划

对应 task：[1620](../../tasks/1620.md)。不改 settlement 协议、回合事务与最终解析；`workbench` 与缺省请求的行为和事件序列不变。

## 决定

- **请求字段**：回合请求与重演请求增加可选 `presentation: 'stage' | 'workbench'`，其他值返回 400。后端在请求开始时选定过滤器，整个回合不再变。Desktop 只在舞台模式发 `presentation: 'stage'`；专业模式不带这个字段，请求体与现在相同。发出时读一次当前模式，回合中途切换只改显示。
- **整句放行过滤器**（`createPlaySentenceStreamFilter`）：
  - 围栏出现前，按句放行：句末标点（`。！？!?…`，连同紧跟的收尾引号 / 括号）后面出现了别的字符，或遇到换行，这一句才算写完。还没写完的尾巴留在缓冲里，所以被拆在两个分片里的围栏不会漏出去。
  - 每句放行前与“刚放出的最后 256 个字符”拼在一起过 `isSafePlayNarrativePrefix`。不通过就关闭过滤器：这一句与之后的全部内容都不放行，即使后面出现合法围栏。同一分片里位于它之前的整句照常放行。
  - 遇到围栏（规则与现有过滤器相同：任意反引号 / 波浪线围栏或 settlement 标记）时，围栏前剩下的文字作为最后一句放行，之后不再放行。
  - 回复没有围栏就结束时，最后一句没写完的部分不放行。
  - 启用 1610 标注的会话传 `wholeTaggedLines`：以 `@` 开头的行要等到换行（或围栏）才整行放行，随后由草稿剥离器去掉标记。
- **仍成立 / 不再成立**：见 [规划 3.5](../../plans/PLAY_GALGAME_PRESENTATION_PLAN_2026-11-12.md#35-舞台模式逐句流式演出1620)，同样写在 `play-narrative-stream.ts` 的注释与 PLAY_MODE_SPEC 里。
- **显示队列**：舞台原本就按句走（`StageSnapshot.beats` + 句子下标）。草稿阶段新增自动前进：当前句显示完、后面已有下一句时，停顿后前进；后面还没有句子就停在最新一句等。新到的句子只是让序列变长，不改当前句。停顿：开着打字效果时取 `min(自动间隔, 600ms)`（打字本身已经给了阅读时间），关着时用 1590 的“自动间隔 + 句长”。开着“自动”时由原有的自动计时器负责，不重复计时。作者仍可点击提前前进。
- **撤下**：草稿始终带“正在演出草稿 · 尚未保存”。失败、停止、重演时 `provisionalText` 被清空（原有行为），标注行随之清空，舞台回到已提交的回合。提交后用正式回合替换草稿，阅读位置按 1590 的规则保留。

## 步骤

1. Core：`play-narrative-stream.ts` 增加过滤器并更新说明。
2. Backend：解析 `presentation`，按值选过滤器；重演请求同样接受。
3. Client：两个请求的 `presentation` 类型。
4. Desktop：`usePlayTurnStream` 读取当前模式；`usePlayWorkspace` / `PlayWorkspace` 传入模式；`VisualNovelStage` 的草稿队列。
5. 文档：PLAY_MODE_SPEC、用户手册、任务状态。
6. 测试：Core 逐字符 / 任意分片位置的放行与拦截；Backend 两种 presentation 的事件、注入片段、标注行、重演；Desktop 请求字段与快 / 慢两种到达节奏下的队列。

## 会失效的数据

无。
