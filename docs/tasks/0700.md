## Implementation Notes (2026-10-14)

- Core 的 `summary-document` / `summary-evidence` 定义严格受管 Markdown、来源绑定与共享冻结 evaluator。章级 evaluator 单独暴露 verifiedContent，防止作者批注/历史进入上层生成。段落必须引用直接来源并覆盖全部输入；来源 hash、派生 payload hash、章节清单和传递 fingerprint 分开记录。
- `/整理本卷` 由当前打开的编号章/卷信息/卷摘要推导目标，`/整理全书` 使用固定全书目标。模型只拥有 `summary.propose`；来源缺失、过期、未验证或超限时仅收到有界缺口报告，没有写工具。默认上下文与 project health 复用同一 evaluator，stale/损坏的受管摘要不作为当前事实发送。
- `summary-generation` deterministic producer 使用 `summary.edit` 的唯一精确 create/update 目标；严格 `summaryGeneration` origin 绑定目标和全部传递输入 fingerprint。Materializer 内建重验（不依赖进程内 producer），同时检查草稿来源、目标 baseline 与 Git；保留作者区块外文字，受管内容损坏时拒绝覆盖。
- 单次最多 4096 章、1024 直接来源、256 KiB 序列化来源输入、32 段/每段 2048 字符，受管文件最大 1 MiB；模型必要上下文预算仍独立生效。上限明确拒绝，不静默截断、不另起模型压缩。
- 完整逐段来源清单保留在 canonical 摘要中；默认消息和上层生成使用已验证正文的派生视图，不重复发送所有叶章节引用。原文件 hash 与派生 payload hash 分开记录。

## Review Corrections (2026-10-14)

- 保留整文件字节失效契约：每章正文、章摘要全文、章状态 `.yaml` / `.yml` 及缺失槽位均进入 fingerprint；全书还依赖各卷摘要全文。作者批注、状态注释和换行字节变化会向上失效。内容未进入模型输入，不代表它不参与来源绑定。
- 汇总生成只由有边界的斜杠命令或命令目录完整 prompt 触发。UI 复用浏览器安全的选择合同提前提示无效卷选择；通用 sandbox policy helper 不负责确定性生成目标推导。
- 已有目标损坏或身份不符时不暴露生成工具与已验证输入，诊断区别来源缺口、目标错误和超限；仍可调用模型解释诊断。缺失 H1 在待审候选中补齐，覆盖手工摘要和作者移除标题后的受管摘要。
- 普通标记字面量不会误触发卷/全书解析；实际受管注释保持版本、唯一性与内容严格校验。解析容忍块内 CRLF，但保留原字符串 offsets、作者 bytes 和原始来源 hash。
- 生成输入使用原始已验证正文，canonical Markdown 继续转义，不再逐层重复 HTML 实体。特殊字符使派生 payloadHash 改变时，已有上层摘要会 unverified，需逐层重新生成；旧 PendingAction 的派生来源不符也会在 Accept 拒绝。没有兼容 reader、迁移或自动改写。
- 超限输入按逐来源序列化字节计数，覆盖计数仍完整，但不保留超限 payload 集合。全书提示精简并重新接受各卷摘要，不能要求选择不存在的卷子集。提示明确一段可引用多个直接来源。
- 混合章节/卷摘要选择取活动卷并集，非活动卷使用准确省略原因。健康面板将从未建立的汇总折叠为可选完善项，stale/unverified 仍显示；无正文的孤儿卷摘要仍检查但不作为全书来源。
