## Goal

把 `/审稿`、`/去AI味`、`/整理本章` 从宽泛 prompt 升级为稳定 schema 驱动 workflow。

## Deliverables

- `ReviewFinding` schema
- review dimension checklist
- `ObservationLog` schema
- `SettlementBundle` schema
- evidence-only settlement prompt section
- hook operation taxonomy：mention / advance / resolve / defer / create
- `/去AI味` 保护规则
- tests 覆盖：
  - review 不隐式 settle
  - settlement 先 observation 后 patch proposal
  - unresolved ambiguity 不直接写 truth files

## Done Criteria

- `/审稿` 默认只输出 findings 和 dimension pass。
- 用户要求改写时，review finding 才能进入受限 sandbox edit / CandidateChangeSet 候选。
- `/整理本章` 先输出 observation log，再提出 summary / state / timeline / foreshadow / character PendingActions。
- settlement 只记录正文证据支持的事实。

## Constraints

- 不从大纲或计划中补正文没发生的事实。
- 不自动修改旧 hook，除非正文有证据。
- 不让去 AI 味删除剧情事实、伏笔、钩子、角色特征或必要转折。

## Historical Production Journey (2026-10-01)

单章“正文 hash/位置证据 → ObservationLog → summary/state CandidateChangeSet → 作者审批”已接通默认生产入口。`/整理本章` 必须由宿主提供唯一当前正文 `chapters/卷号/章号.md`；模型只有固定投影读取与 `settlement.propose`，不能使用普通编辑工具绕过结构化验证。见 [1230](1230.md)。

当前仅编译高置信度观察到 `summaries/chapter/<卷号>/<章号>.md` 与 `state/chapters/<卷号>/<章号>.yaml`，同一 CandidateChangeSet / PendingAction 经作者 Accept 后落盘。章节状态是保留逐行证据的局部记录，未自动合并全局状态，也未实现 timeline / foreshadow / character 的结构化结算，因此本任务仍为 Needs Review。

正文 SHA-256 保留原始换行字节语义；证据使用原文件一基行号，排除 frontmatter，quote 必须逐字匹配完整行。未知字段、重复 observation ID、非法类别/置信度、错误 hash、错位引用均拒绝；中低置信度与未解决歧义只出现在报告。系统保证结构与来源可核验，事实解释仍由作者审阅。

## Implementation Notes

### Multi-domain implementation (2026-10-02)

- 默认 `/整理本章` 固定投影现在包含所选正文、本章摘要/章级状态、四份领域 ledger 与既有角色文件。模型仍只使用 `readFile` 和 `settlement.propose`；没有通用编辑工具或模型自报路径。
- 严格输入增加最多 32 项 `domainChanges` 与 `unresolvedObservationIds`。每项意图绑定一个 observation ID，并核对领域类别；未知 ID/字段、非法角色 ID、重复目标和类别错配均拒绝。中低置信度、显式歧义及合并冲突的观察排除于全部 truth 候选，包括摘要和章级状态。同一观察的多项领域变更整体成功或整体跳过。
- `state/characters.yaml` 合并既有角色的受支持文本字段：hp、emotion、location、status、power、inventory、resources、information、relationships。精确核对旧值；`null` 仅代表字段不存在，不覆盖已有复杂值。逐字段保存来源，较早编号章节不能回退较晚章节状态。
- `timeline/events.yaml` 保留既有事件，有稳定证据身份的新事件追加顺序；回填较早章节会误序时只报告。`foreshadow/active.yaml` 和 `resolved.yaml` 支持 create/mention/advance/resolve/defer，核对生命周期旧值、保留作者字段与历史，resolve 在同一候选中移动条目。
- `characters/<id>/growth.md` 只向既有角色追加有证据的成长记录，不改写其人设。正文观察须匹配稳定 ID 或明确的名字/别名；不能消解的人物身份歧义只报告。
- 摘要保留作者正文，以有来源 hash 的证据快照和当前来源指针区分历史；章级状态保留历史来源和未建模作者字段。重复已接受证据不会重复生成事件/成长项；插行不改变同一引句的领域身份。改过的受管区块与不同解释发生冲突时不覆盖作者内容。
- `chapterSettlement` origin 必须带排序、去重、最多 128 项的 `inputFiles`，绑定全部七个固定输入及实际读取的人物组件；缺失文件也以 `null` 记录。`characterInventoryHash` 另外绑定角色文件集合，新增同名人物也会使旧提案失效。Client 和持久协议严格拒绝缺项/未知路径/坏 hash，未增加旧 origin reader。Accept 内建重新验证正文和完整合并依据，Backend 避免重复扫描；现有目标 baseline、Git HEAD、最终树引用、事务与 Git 行为继续生效。
- 本轮支持明确的受限合并；资源/物品/关系的任意复杂结构、人物卡任意字段重写和故事时间的自动语义排序不在本轮范围。引文与 ID 校验不等于自动证明模型解释，作者仍审阅全部差异。Extension 系统继续暂缓。
- 正文版本变化会更新本章当前证据并保留历史，但不会自动撤销以前已经 Accept 的全局事实；timeline 删除、人物成长撤回等仍需作者显式修正，不能从新正文中未提及某事推导它从未发生。
