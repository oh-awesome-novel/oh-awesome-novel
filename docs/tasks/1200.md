# 1200 Writing Profile Configuration And Prompt Reminders

> Status: Completed
> Milestone: Writing Profile W0 + W1

## Related Plans

- [Writing Mode Commercial And Fanfiction Upgrade Plan](../WRITING_MODE_COMMERCIAL_AND_FANFICTION_UPGRADE_PLAN.md)

## Goal

为 workspace 增加一个严格、可审阅、Git-visible 的 Writing Profile 配置层，
并用四个固定 reminder fragments 细化既有 Novel Copilot skill。Profile 只选择
拆书 outputs 与 Writing reminders，不引入题材类型、source binding、任意 prompt
或新的运行时控制器。

## Scope

- strict `WritingProfile` schema、只读内置 `commercialWriting` /
  `fanfictionWriting` 和 custom Profile CRUD / clone / activate。
- `.oan/config.yaml` 的 `writingProfile.activeProfileId` 与
  `.oan/writing-profiles/<safe-id>.yaml`。
- 配置原子写 helper，以及新 workspace 的默认 Profile 和目录初始化。
- Backend / Client strict API 与 Desktop Profile Manager、当前 Profile 摘要。
- Runtime `reminder` context kind；四个固定 fragment 按真实
  `novel.*` capability 注入。
- D5 selector 的 `techniques` Profile gate。
- Profile、prompt assembly、D5、API 与 UI 分层测试。

## Out Of Scope

- W2 的 quality gate `warned` 语义、Story Material analysis track、work plan /
  stage / manifest output kind 改造。
- W3 的 material review、adoption、PendingAction composition 与桌面旅程闭环。
- Profile snapshot、source-canon runtime、source binding、任意 prompt /
  scripts / tools 或第二套 deconstruction controller。
- 把 reference 原文或未采用 materials 注入正式 Writing。

## Done Criteria

- 新 workspace 显式默认 `commercialWriting`；缺失 Profile 配置也以它非持久化
  fallback。
- 内置 Profile 只读；用户可创建、克隆、编辑、删除和激活完整 custom Profile。
- `writingProfile` 子树和 custom 文件 unknown field、非法 output、非法 id 及
  id / filename 不一致均明确报错；其它 workspace config section 继续宽松读取。
- `reminder` 位于 `skill` 之后、`selected` 之前；四项全关时不产生 context item，
  原装配结果逐字不变。
- reminder 严格按计划中的 capability 表生效；未知 capability 不注入。
- D5 在 Profile 不含 `techniques` 时直接返回
  `profileExcludesTechniques`，不进入评分、预算或 fallback。
- Profile Manager 和 Writing 区域都显示当前 Profile 状态；所有配置 mutation
  都来自用户显式操作并保持 Git-visible。

## Prompt Golden Baseline

Profile prompt golden baseline 使用
`__test__/agent/src/message-assembly.test.ts` 中的 inline snapshot。

只有在 reminder 文本或装配合同被有意修改时才更新基线：

1. 先运行
   `npm run test:run --workspace @oh-awesome-novel/test-agent -- message-assembly.test.ts`
   查看语义差异。
2. 确认差异仍保持 shared skill 单份、`skill -> reminder -> selected` 顺序、
   capability mapping 和 non-blocking / Project Truth 边界。
3. 再显式使用 Vitest 的 `-u` 更新 snapshot，并人工审阅 Git diff；不得用更新
   baseline 掩盖意外 prompt 漂移。
4. 重新运行 agent 测试，以及受影响的 Core / Runtime / Backend 回归。

## Constraints

- Profile 配置操作不授权 AI 写入真实目标文件；MVP 只有用户显式 UI / API
  mutation。
- reminder 不改变 PendingAction / Human Approval，不产生 hard pass / fail，
  不自动修改正文。
- 不修改 Play Mode、既有 Technique Track schema、reference quality gate 或
  publish 完成性合同。
- 测试继续放在根目录 `__test__/` 对应 workspace。
