# 1220 Reference Material Adoption And Desktop Closure

> Status: Completed
> Milestone: Writing Profile W3a

- [Writing Mode Commercial And Fanfiction Upgrade Plan](../WRITING_MODE_COMMERCIAL_AND_FANFICTION_UPGRADE_PLAN.md)

## Goal

打通已发布 Story Material 到当前小说 Project Truth 的最小受控链路：作者显式
选择单份 reference 的材料条目和 workspace 目标，模型只读取选中材料与目标
baseline，生成 `create | update | skip` 结果，随后经 diff、PendingAction 和 Human
Approval，在 Accept 后成为普通当前小说文件。

## W3a Scope

- 读取并严格校验当前、未 stale 的 `materials/*.yaml`，展示完整 entry、confidence、
  assertion type、uncertainty 和已发布 warning。
- selected entry 到受限 workspace target 的显式映射；单次操作只使用一份
  reference，允许多目标并生成一个 multi-file PendingAction。
- adoption prompt 只包含选中材料和当前 target baseline，不包含 `sources/*`、
  `deconstruction/*`、未选 entry 或 reference 原文。
- 严格 structured output：每个目标只能返回 `create | update | skip`，非 skip
  结果转换为 SemanticPatch。
- `world`、`characters`、`timeline` 使用既有 Object / Collection patch；
  `relationships` 使用角色对象的 `relationships.yaml` 整文件候选；`outline`
  使用仅支持整文件候选的 Narrative `outline` domain。
- prepare preview 与 promote PendingAction 分离；preview、reference material 与
  target baseline 任一变化均 fail closed。
- Backend / Client strict API 与最小 Desktop Material Review / adoption 入口。
- Core、Agent、Tools、Backend、Client、Desktop 分层测试。

## Deferred W3b

- 大批量材料的筛选、搜索、折叠、拖拽映射或智能批量目标建议。
- warning 到具体重叠文本的高级可视化定位。
- adoption 历史、模板、跨 reference 合并和自动冲突消解。
- 新 relationship patch domain、细粒度 outline patch 或 0800 的完整执行器扩展。

## Done Criteria

- 只有 accepted、current、hash 闭合的 `materials/*` 可以进入 adoption catalog。
- 未选 entry、`deconstruction/*` 和 `sources/*` 永不进入 adoption model input。
- Preview 前后材料、目标 baseline 或 fingerprint 变化都会阻止 PendingAction 创建
  或 Accept；Accept 前真实 workspace 文件保持不变。
- 一个 preview 可以对多个唯一目标生成单个 PendingAction，结果逐目标展示
  `create | update | skip`。
- Accept 后 world / character / relationships / outline / timeline 目标成为普通
  workspace 文件，正式 Writing 仍不读取 reference `materials/*`。
- reference 后续发布或变化不自动同步已经 Accept 的文件。
- 相关分层测试、build、renderer smoke（如环境可用）与 `git diff --check` 通过。

## Constraints

- 不建立 source binding、canon checkpoint、多 source manifest、Story Material
  selector、数据库或第二套 runtime/controller。
- 不把材料采用伪装成普通 Writing；它是用户显式发起的独立编辑操作。
- 测试继续放在根目录 `__test__/` 对应 workspace。

## Implementation Notes

### 2026-08-01

- Core 新增 current published material catalog、显式 selection / target 约束、baseline
  snapshot、context fingerprint 与逐目标 `create | update | skip` strict normalizer。
- Agent 使用独立 bounded structured-output prompt，只接收已选择 entries、对应材料文件
  identity 与当前 target baseline；不提供 tools、source text、`sources/*`、
  `deconstruction/*` 或未选 entry。
- Tools 把五类结果映射为受限 SemanticPatch：world / character ObjectPatch、角色
  `relationships.yaml` 整文件候选、outline `replaceFile`、timeline `yamlSet`；YAML
  候选在 preview 阶段继续严格解析。
- Backend 保存 hash 绑定的 adoption preview，将 prepare 与 PendingAction promotion
  分开；创建 PendingAction 和 Accept 前复核 catalog、source identity、material hash
  与目标 baseline，漂移返回冲突且不覆盖用户文件。Client 提供 strict request /
  response guards。
- Desktop References 旅程新增 Material catalog、entry/target selector、warning、
  create/update/skip、multi-file diff 和二次确认入口；最终 Accept 复用全局 Review。
- `FILESYSTEM_SPEC.md` 登记 `outline/` Project Truth 与 W3a 整文件边界；`0800` 登记
  后续不得另建同义 outline domain。W3b 的批量筛选、搜索、拖拽、历史和细粒度
  patch 继续延后。
- 验证通过：Core 41 files / 330 tests；Tools 8 / 85；Agent 9 / 62；Backend
  7 / 108；Client 9 / 118；Desktop UI 45 / 217。受影响 package builds 与 Desktop
  production build 通过；后端 HTTP 集成覆盖 preview → PendingAction → Accept 及
  Accept 前目标漂移的 `409 stalePreview` 保护；真实 Electron renderer smoke 与
  `git diff --check` 同步通过。
