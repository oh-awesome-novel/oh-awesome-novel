## Implemented Corrections

- A01：新建工程初始化独立 Git 仓库和仅含生成配置的首个基线；缺 Git/identity/HEAD 可见，导入已有 dirty 工程不自动提交。真实默认 sandbox 可创建候选并 Accept。
- A02：accepted 文件清理与 Git 对账分阶段；receipt 持久化后清除 journal，Git 失败不会要求作者文件永久保持当时内容。真正未完成清理仍严格恢复；quick commit 仍精确校验。作者 unrelated staged state 的 preflight guard 保留。
- A03：Git status/name-status 使用 NUL 协议；中文、空格、引号、rename 双路径保持原样。diff 覆盖用户选定的 staged/unstaged/untracked 内容，失败不伪装为空 diff；不改真实 index。
- A04：基于最终树的类型化引用校验接入 sandbox、deterministic proposal/preview/promotion 和 Accept；支持同候选新建引用，拒绝悬空删除和 namespace 错配。文档示例通过真实 validator。
- A05 第一阶段：目标附近/最新摘要选择、完整 Constitution/state、逐文件来源与 payload hash、每个 provider step 的保守预算检查、实际 maxOutputTokens 接线。完整标准Agent治理现由 `1110` 交付，见本轮续作。
- A06 resume：与当前固定投影比较 hash，作者与模型同时收到变化/删除提示，提示进入会话结果；mtime-only 不当作正文变化。`1030` 已在 2026-10-02 交付受限多领域证据结算，见下方续作记录；不能再将该生产链列为未实现。
- A07 存储与流式恢复：stage 文件与目录、ready、backup rename、publish 和 cleanup 的持久化顺序；进程中断恢复测试。最小 durable run receipt、重启后真实 artifact ID/hash 对账、明确 unknown、120 秒 generation deadline、2 MiB SSE 队列与 graceful shutdown 接入，并验证等待 commit barrier。断电设备/文件系统矩阵仍未验收。
