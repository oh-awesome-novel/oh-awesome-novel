## Scope

Implement A08 after measuring the current filesystem cost: snapshot-bound, rebuildable summary/head and paged selected-history read models; reuse unchanged immutable artifacts during staged writes. Preserve cooperative locks, revision CAS, complete-graph mutation validation, atomic directory swap, fsync and crash recovery.

## Done Criteria

- Summary reads do not load full artifacts; selected-window reads do not load sibling history.
- Deleted indexes can be rebuilt from canonical Play files; stale, corrupted or mismatched projections fail closed.
- Existing cursors, hidden event projection and v4/v5 selected-detail DTOs retain their behavior.
- Unchanged turns are not rewritten from serialized bytes; supported filesystems may clone their data blocks, with safe copy fallback.
- Real reader/writer instrumentation compares file counts, bytes, lock time and write/copy costs; no physical-I/O claim from logical bytes alone.
- Full graph validation, CAS and process-crash tests remain passing. No new database or append-based transaction.
- Prefix transcript extensions write only their suffix into a verified private staged clone; non-prefix changes and missing/corrupt derived transcripts regenerate completely. Cold index reconstruction hashes the bytes consumed by its full validating reader without rereading every source.

## Constraints

Read models are disposable and never novel/Play truth. Old sessions without an index remain readable and gain an index only on a normal save. All tests live under root test workspaces.

## Implementation Notes

### 2026-10-01

- `play-storage-read-model.ts` stores content-addressed 32-item transcript/event/evidence pages and 32-child tree nodes inside the same staged snapshot. The bounded head stores summary, current snapshot hash, counts and tree roots, including a tree of all source content hashes; it does not embed the sibling artifact inventory. The current snapshot retains the existing selected IDs/state/observation DTO contract, so its size still depends on the selected branch and current state.
- Reserved `session.yaml.storageReadModel` binds a portable content root: normalized base metadata, source hashes and derived pages. Filesystem device/inode/size/nanosecond mtime/ctime are only a bounded process-local witness, never part of that root or persistent truth. A new process/path, copied workspace, changed source identity or witness eviction triggers one full validated reconstruction under the session lock. Only identical source content can reproduce the anchor and rebind the witness; this does not rewrite the canonical anchor or revision. Content-identical touches and copying a workspace therefore remain supported. Window pages additionally re-read and hash only their referenced source turns. Untouched sibling artifacts are not claimed to be revalidated on warm reads; mutations, Retry/Restore and full reads continue complete graph validation.
- `listPlaySessionSummaries` now reads metadata + head per session. `readPlaySessionSelectedDetail` follows only the requested selected-window tree paths; Backend detail uses this new entry point. Existing cursor identity and hidden event presentation semantics come from shared projection/window helpers.
- Deleting the whole index or one page triggers a full validated reconstruction under the same session lock; it must reproduce the committed anchor before atomic cache publication. Corrupt bytes, changed metadata/content or nonmatching reconstruction fail closed. The source inventory tree detects even structurally valid sibling edits during reconstruction. Unindexed sessions stay on the original reader until a normal save; list/detail do not silently migrate them.
- When revision CAS has supplied an authoritative prior session, unchanged immutable turns are compared structurally and cloned/copied rather than serialized and rewritten. Every reused staged file is hashed against the prior validated bytes before publish. Derived pages whose hash is unchanged are reused too. `COPYFILE_FICLONE` requests private copy-on-write blocks where supported and safely falls back to copying; hardlinks are not used. Existing directory swap/fsync order is unchanged. Ordinary mutable ledgers and `transcript.md` are still whole snapshot writes.
- New tests cover all cursor pages, missing/corrupt indexes, changed source with restored mtime, selected/sibling corruption, hidden visibility tampering, private clone semantics and stale cursor/CAS. Copying a complete workspace with/without its index and touching identical source bytes retain the anchor and restore warm reads after one validation; altered sibling content cannot rebind. Existing SIGKILL boundary tests also verify the indexed projection after recovery. Core build and the final targeted storage/durability/projection run pass (3 files / 31 tests, including 13 storage tests). The final full Core run passes 48 files / 412 tests, including the portability regressions and the other delivery tracks.

## Snapshot Write-cost Follow-up (2026-10-02)

- An update with a fully validated CAS baseline now clones `transcript.md` into the private stage only when its newly derived text extends the old text. The cloned prefix is hashed against text derived from the old validated graph, then only the suffix is appended inside the stage. The published snapshot is never appended to. Missing/corrupt derived transcripts regenerate from the graph; Restore, Retry and title/header changes that break the prefix use a complete rewrite. COW requests still have an ordinary private-copy fallback, never hardlinks.
- A save shares its newly validated facts with projection and summary instead of materializing the candidate graph three times. Public projection and summary functions retain full validation. Selected artifact lookup uses a map instead of a selected-chain-by-all-artifacts nested scan. Metadata is serialized to disk once, with its final portable index anchor.
- Missing/cold index reconstruction captures source hashes from the raw bytes consumed by the full reader. The old second source-content pass is removed. File identity checks around that read and before witness publication reject concurrent changes; these checks do not replace future mutation/CAS validation. Rebuilding still reproduces the committed portable anchor exactly.
- The complete stage/fsync/ready/backup/swap/cleanup protocol is unchanged. The SIGKILL update fixture now starts with existing multibyte transcript content and exercises the clone/suffix path at all six durability boundaries. Added coverage includes private transcript clone independence, source/candidate sibling corruption, derived transcript repair, Restore, Unicode, real suffix/metadata write counts, single-pass rebuild source reads and drift during source validation.
