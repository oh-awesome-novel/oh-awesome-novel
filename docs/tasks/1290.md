## Goal

让长篇小说的默认上下文不随全部章级结算历史持续增长，并把摘要/章级状态的来源新鲜度用于健康提示与上下文选择。

## Scope And Constraints

- 共用接收固定文件快照的纯 evaluator，区分 current / stale / missing / unverified；正文原始内容 hash 是依据，mtime 不是剧情版本。
- 复用已接受结算的来源标记；缺失、矛盾或不能验证的来源不得宣称 current。作者手写摘要仍可明确标为未验证参考，不阻断写作。
- 当前全局状态及明确选定的章级当前证据保持 protected；其它章节历史按需从同一固定投影读取，提供有界的来源/覆盖说明。
- 摘要上下文区分当前证据与历史；派生 payload 与 canonical source 分别记录 hash。
- 不删除或改写既有 canonical 证据，不引入隐式模型压缩、数据库或新写入链路。
- 卷/全书摘要生成不属于本任务。

## Done Criteria

- 正文改动可见 stale；只 touch 文件不误报；不存在来源依据的文档可见 unverified。
- host health 与 Agent 固定快照采用相同规则，保留只读 soft warning。
- 百章/五百章及多次修订 fixture 验证默认 protected 上下文不包含所有章级历史。
- 明确选择的内容、当前全局状态、Constitution 与来源证据边界保持；目标回归与相关模块验证通过。

## Implementation Notes

- Core 新增 `chapter-evidence-freshness.ts`：冻结输入、正文原始内容 SHA-256、精确引文、当前摘要/章级观察对应校验；元数据身份冲突、编辑过的受管块、`.yaml` / `.yml` 重复来源均不宣称 current。
- `evaluateProjectHealth` 为 host 与 Agent 的共用纯入口。host 捕获复用安全文本读取并保留 BOM，拒绝超限与读取漂移；mtime 只用于展示时间，不再判断事实陈旧。
- `workspace-context` 默认保留当前全局状态，目标章使用明确 derived 的当前证据和作者字段；历史记录不自动注入。显式选择的原文件保持完整保护，手写章/卷/全局摘要作为 unverified 参考。
- 覆盖报告最多列出 12 章，健康消息最多 20 条问题，模型侧 ContextPackage 来源/trace 清单有界；完整审计数据仍保留。省略的历史可通过同一 fixed projection 读取，不删除文件，不触发额外模型压缩。
- 新测试覆盖 100/500 章、多次修订、正文换行/BOM、touch、元数据损坏、作者字段与完整显式选择。范围限定为默认消息规模：固定投影的磁盘捕获仍受既有总大小限制，不声称整轮文件读取成本恒定。
