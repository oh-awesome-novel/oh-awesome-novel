## Goal

完成评审建议第4项：把严格类型检查和回归测试接入发行门禁，保证显式 Git 提交只提交作者预览过的内容，并用真实打包应用验收写作审批与持久化旅程。

## Scope

- 修复所有有生产 TypeScript 源码的 package/app 的类型检查；保留 strict / erasableSyntaxOnly，区分类型检查与构建。
- 单一本地质量命令与 PR/main/发行共用的 CI；发行构建依赖通过质量门禁的同一源码 commit。
- Git diff 预览绑定工作区、HEAD/分支、index、选定路径与内容/模式；预览变化后要求重新审阅，提交不得重新读取未预览内容。
- 在本机打包应用中运行隔离的默认 Backend、真实 SDK/HTTP/SSE、候选/diff、Accept、Git、导出与重启持久化旅程。
- 文档按验证证据更新，历史验证记录保留日期。

## Constraints

- 保留单一 Sandbox Change Engine 和作者确认；不改自动 PendingAction 提交的审批语义。
- 不新增 bundled Git、分支管理或自动网络同步；不提交/推送本仓库，不发布新版本。
- 模型验证使用本地可控服务，不使用个人密钥或收费 provider。
- 本机 macOS 打包验收不冒充其他平台已运行；将相同 smoke 接入四平台发行流程。

## Done Criteria

- 生产源码严格 typecheck、相关构建、七个测试 workspace 和文档检查通过。
- 发布需要质量 job 成功，不能只凭安装包构建成功发布。
- 旧预览、目标文件变化、index/HEAD 变化被拒绝；预览后晚到的编辑不能进入已批准 commit。
- 正常提交、特殊路径、rename/delete、前端异步切换与失败重审有回归覆盖。
- 打包应用旅程验证审批前 canonical 不变、审批后 Git/导出一致，重启后可以读取已持久化结果。

## Implementation Notes

- 10个有生产源码的 workspace 均有独立 typecheck；补齐实际 Node/Electron 支持的 ES2023/Node 声明，修复 Play/Materializer/SDK 联合类型和完整/partial output 合同，保留严格选项。顺带修复隐藏 Play 事件状态影响返回错误形状的运行时缺陷，并增加回归。
- `npm run quality` 统一拓扑构建、生产 typecheck、七个显式测试 workspace 顺序执行、文档检查与 Wiki 构建。测试入口不使用 `--if-present` 静默跳过必需 suite；生产源码覆盖检查拒绝缺少 typecheck 的 workspace。
- PR/main 与发行复用 `quality.yml`；发行构建依赖通过质量门禁的精确 commit SHA。原四平台发布链路和人工决定版本的流程保留，本轮没有发布新版本。
- Git 面板绑定短期预览凭证，按预览 raw bytes/tree 提交；重新验证 HEAD、branch、index、文件/mode。原生 `update HEAD → prepare → 锁内验证分支 → commit` 同时处理同 OID 分支切换和并发 HEAD 修改。index 锁不误删其他进程后来获得的锁。
- index 收尾失败返回 committed + warning，同进程仅重试收尾；读取有界并拒绝 symlink/特殊文件和不支持的 index flags。签名、hooks/filters、sparse checkout 等外部 Git 工作流有明确说明；不宣称手动提交已有跨进程 durable recovery journal。
- 打包 smoke 使用真实 renderer/preload、Backend、默认 SDK、HTTP/SSE、sandbox、materializer 和 Git。两个独立应用进程覆盖新建、导入、写作/diff/Accept、导出、重启读取和 Reject。目录选择与模型响应采用隔离本地 fixture，清除继承的 Git/provider 配置，测试不会修改个人工程或密钥。
