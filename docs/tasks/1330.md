## Goal

让 Writing 能从空作品开始独立完成“规划 → 写下一章 → 审稿 → 定稿 → 整理本章 → 写下一章”的核心闭环，满足 [REQUIREMENTS F20](../REQUIREMENTS.md#f20-core-writing-loop-closure)。作者不需要先在文件树里选中“正确的文件”，也不需要手工新建章节文件或复制聊天内容。

## Scope

- `/写下一章`：host 根据章节索引推导下一个章节路径（空作品为 `chapters/0001/0001.md`，否则为最新卷最新章的下一章），授予该精确路径的 `chapter.edit` create 能力。作者选中了某个已存在的正文章节时仍可改写该章（保持既有行为）。
- `/生成角色卡`：选中 `characters/<id>/` 下的文件时授予该角色的标准对象文件；未选中时由作者在界面中输入角色 ID，host 授予 `characters/<id>/` 下标准对象文件的精确路径。
- `/规划大纲`、`/规划下一卷`、`/规划下一章`：未选中大纲文件时，host 授予 `outline/main.md` 与当前卷 `outline/volumes/<卷>.md`。规划默认仍只输出草案，作者明确要求保存时才提出修改。
- 写章与规划的默认上下文包含 `outline/main.md`、当前卷大纲与上一章正文。
- Writing 显示章节进度引导（规划 → 写 → 审 → 整理），章节正文 Accept 后提示整理本章。

## Constraints

- 目标路径只由可信 host 推导；模型参数、聊天文本或 diff 不能扩大写入范围。
- 不新增写入架构；所有修改仍经 CandidateChangeSet / PendingAction / ChangeMaterializer。
- 不自动发送整理请求；提示只是一个作者可点击的入口。

## Done Criteria

- 新建空作品后，`/写下一章` 生成创建 `chapters/0001/0001.md` 的 PendingAction，Accept 后章节出现在章节导航中。
- 已有章节时，`/写下一章` 目标为最新章的下一章，不覆盖已有正文。
- 角色卡、大纲目标推导有单元测试；路径非法或角色 ID 非法时拒绝。
- Backend/agent 测试覆盖目标推导与上下文选择；wiki 写作指南同步更新。
