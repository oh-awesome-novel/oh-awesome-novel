## Goal

让 Writing 能从空作品开始独立完成“规划 → 写下一章 → 审稿 → 定稿 → 整理本章 → 写下一章”的核心闭环，满足 [REQUIREMENTS F20](../REQUIREMENTS.md#f20-core-writing-loop-closure)。作者不需要先在文件树里选中“正确的文件”，也不需要手工新建章节文件或复制聊天内容。

## Scope

- `/写下一章`：host 根据章节文件推导下一个章节路径（空作品为 `chapters/0001/0001.md`，否则为最新卷最新章的下一章），授予该精确路径的 `chapter.edit` create 能力。只有请求开头的斜杠命令触发；“改写这一章”等关键词请求仍以选中文件为目标（保持既有行为）。
- `/生成角色卡 <id>`：命令后的 ASCII 角色 ID 优先，否则使用选中的 `characters/<id>/` 文件；host 授予该角色标准对象文件的精确路径。两者都没有时本轮只读。
- `/规划大纲`、`/规划下一章`：host 授予 `outline/main.md` 与当前卷（选中文件所属卷，否则最新卷）`outline/volumes/<卷>.md`；`/规划下一卷` 授予 `outline/main.md` 与下一卷大纲。规划默认仍只输出草案，作者明确要求保存时才提出修改。
- 写章与规划的默认上下文包含 `outline/main.md`、当前卷大纲与上一章正文。
- Writing 显示章节进度引导（规划 → 写 → 审 → 整理），章节正文 Accept 后提示整理本章。

## Constraints

- 目标路径只由可信 host 推导；模型参数、聊天文本或 diff 不能扩大写入范围。
- 不新增写入架构；所有修改仍经 CandidateChangeSet / PendingAction / ChangeMaterializer。
- 不自动发送整理请求；提示只是一个作者可点击的入口。

## Done Criteria

- 新建空作品后，`/写下一章` 生成创建 `chapters/0001/0001.md` 的 PendingAction，Accept 后章节出现在章节导航中。
- 已有章节时，`/写下一章` 目标为最新章的下一章，不覆盖已有正文。
- 角色卡、大纲目标推导有单元测试；路径非法或角色 ID 非法时拒绝。
- Backend/agent 测试覆盖目标推导与上下文选择；wiki 写作指南同步更新。

## Implementation Notes

- `packages/agent/src/writing-targets.ts`：`resolveWritingCommandTargets` 从真实章节目录推导目标；`0000.md` 视为卷信息；卷号/章号越界、非法角色 ID 抛出 `WRITING_COMMAND_TARGET_INVALID`，Backend 返回 400。
- Backend `handleAgentChat` 在 capability 选择前用命令目标替换 `exactWritablePaths`；沙箱仍只授予这些精确路径，未存在的目标以 create 提出。
- System prompt 列出本轮授予的可写目标，或声明本轮只读；不再让模型猜测保存位置。
- 上下文新增 `outline`（主线 + 目标卷大纲）与 `previousChapterText`（目标章之前最后一个非空章节的结尾，最多 3,000 字符），并进入 baseline context package。
- Writing Copilot 显示章节进度引导：当前章已定稿未整理时提供「整理本章 / 审稿」，其它章节未整理时提供跳转，已整理时提供「写下一章 / 规划下一章」。章节 Accept 后健康状态刷新即出现整理提示；按钮只填写请求，不自动发送。
