## Goal

在保留“所有正式写入需要作者确认”的前提下，减少审批疲劳并让长篇记忆不悄悄失效，满足 [REQUIREMENTS F21](../REQUIREMENTS.md#f21-proportionate-review)。

## Scope

- 审批列表区分“派生记录”（只涉及 `summaries/`、`state/`、`timeline/`、`foreshadow/` 与角色 `growth.md` 的 PendingAction）与其它修改，并提供“接受全部派生记录”。
- 整批接受按顺序对每个 PendingAction 执行普通 Accept；任一项失败或过期即停止，并报告已接受与未处理项。
- Workspace 健康页与 Writing Copilot 显示尚未整理的章节数（章级摘要缺失或过期），并提供打开最早未整理章节的入口。
- 新建作品与未配置 Profile 的作品默认使用同人二创 Writing Profile。

## Constraints

- 不新增 materialization 路径；整批接受不跳过 baseline、origin 或 freshness 校验。
- 正文、角色人设、Constitution 与 Play/Reference adoption 不进入整批接受。
- 未整理统计复用既有章级来源新鲜度判定，不建立第二套记忆状态。

## Done Criteria

- 派生分类、整批接受停止语义与默认 Profile 有测试覆盖。
- 首页未整理计数与既有 freshness 结果一致。
- wiki 审阅与设置指南同步更新。

## Implementation Notes

- Client `isDerivedRecordPendingAction`：pending、非空、无删除，来源为 agent turn、章节整理或摘要生成，且全部路径属于 `summaries/`、`state/`、`timeline/`、`foreshadow/` 或 `characters/<id>/growth.md`。
- Client `acceptPendingActionsInOrder`：逐项调用普通 Accept，首个失败即停止并返回已接受、失败项与未尝试项；`Approval` 页在两项及以上时显示「接受全部派生记录（N）」并给出结果说明。
- Core `ProjectHealth.unsettledChapters`：非空正文中章级摘要状态不是 `current` 的章节，复用 `evaluateChapterEvidence`；健康页显示数量并可打开最早一章、填写 `/整理本章`，Play 中点击会切回 Writing。
- 新建作品写入 `activeProfileId: fanfictionWriting`，缺失配置回退为同人二创；内置列表同人二创在前。
