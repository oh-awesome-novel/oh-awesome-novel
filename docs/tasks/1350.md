## Background

2026-10-22 评估过是否把底层从 Vercel AI SDK + Aider-style Runtime 切换为 pi agent（`@earendil-works/pi-agent-core` / `pi-ai`），结论是不切换：现有 `RuntimeSession` 已承载 PendingAction、顺序工具执行、上下文预算、usage 记录与 fail-closed finalizer，换框架收益小、迁移面大。评估中 pi 唯二值得吸收的能力是 **steer / followUp**（运行中插话与排队）和 **统一的推理过程（thinking）**。本 task 在现有架构内实现这两项，不引入新框架。

开工前提：依赖升级适配分支（`chore/deps-upgrade-adapt`）已合入 `main`。本 task 不与其并行改代码。

## Goal

1. **推理过程**：Copilot 中流式展示推理模型的思考内容（默认折叠）；Play 主界面不展示思考，改由新增的 Play 消息日志界面查看；允许按模型配置推理强度。对话消息与思考过程以 JSONL 调试日志保留，历史会话重新打开后仍可查看。思考内容永远不进入 canonical 文件、PendingAction、Play 产物、证据、模型上下文（跨轮）或 Git。
2. **Steer**：作者在一轮 Copilot / Play 生成尚未结束时补充一句话，影响本轮剩余部分。
3. **Follow-up**：作者在一轮运行时预先排队下一条请求，本轮结束后按顺序自动发出，可编辑、可取消，也可以把排队中的消息一键转成插话。运行中按 Enter 默认排队。
4. **Play 消息日志**：一个日志式界面，按时间顺序列出一个 Play 会话的全部消息（作者行动、Director 干预、插话/排队、actor 与 referee 的请求与输出、思考过程、取消与错误），主要用于调试。

## Scope

- Runtime：`RuntimeModelStreamEvent` / `RuntimeEvent` 增加 reasoning 事件；`RunTurnInput` 增加可选 steering 来源，在工具批次之间和"无工具最终回答"之后轮询。
- Agent：AI SDK adapter、Play actor / referee 消费 SDK reasoning 流；provider resolver 让 OpenAI 兼容类 provider 能解析 `reasoning_content`；按模型配置传递推理强度。
- Backend：Copilot 活跃 turn 注册表与 steer 端点；Play world-referee turn 的 steer（取消未提交生成并以补充文本重发）。
- Client / Desktop UI：Copilot 思考过程折叠块；Copilot 与 Play 输入框在运行中保持可用，Enter 排队、另有"插话"发送；follow-up 队列显示、编辑、取消、转为插话；Play 消息日志界面。
- 调试日志：Copilot 在已有 `.oan/sessions/<id>/messages.jsonl` 中保留 assistant 思考内容；Play 新增按会话的 JSONL 消息日志，同样放在已被 `.gitignore` 忽略的 `.oan/sessions/` 下。
- Core：`LlmProviderModel` 增加可选推理配置字段；usage 中已有的 `reasoningTokens` 在 Usage Inspector 中展示。

## Constraints

- 不引入 pi agent、AI SDK Agent 或任何新 agent 框架；Runtime 仍是单一 Aider-style loop（ADR 0002）。
- 工具执行保持顺序；steer 不打断正在执行的工具，只在工具批次边界生效。
- Steer 文本不得改变本轮 trusted host 选择：capability、`exactWritablePaths`、skill、allowed tools、上下文包来源都在 turn 开始时冻结。
- 一轮 turn 仍只有一个 `turnFinalizer` 批次；follow-up 是新的 turn，有自己的 PendingAction 批次，不合并进上一轮。
- 思考内容只用于展示、本轮内必要的 provider 回传和 JSONL 调试日志；不写入 Play `PlayTurnArtifact`、rehearsal evidence、context trace、adoption、memory、导出或 Git。`play-rehearsal-turn.ts` 中"private model reasoning is forbidden"的约束保持不变。
- JSONL 日志是只写的调试记录，不是事实来源：Copilot 历史上下文、Play 状态和 projection 不从日志中的思考内容重建；删除日志不影响任何功能；日志中的思考内容不回送给模型。
- Play 已提交（settled）的 turn 不因 steer 被改写；steer 只作用于尚未 settle 的生成，并沿用现有 cancel 路径与 `baseRevision` 校验。
- Play schema 不为本 task 升版本；steer 记录以"取消 + 带补充文本重发"表达，不新增 artifact 字段。
- 无真实 provider key 的测试不冒称联网验收。

## Non-goals

- 工具并行执行、自动重试、自动压缩、多 agent。
- 在 Play rehearsal 里新增 Director mutation 类型（运行中插话复用已有 `redirectStep`）。
- 把思考内容作为可采纳素材或写作参考。
- 跨应用重启保留 follow-up 队列。

## Done Criteria

- 配置了支持推理的模型时，Copilot 回复在正文之前显示默认折叠的思考过程，重新打开历史会话后仍可查看；Play 主界面不显示思考，Play 消息日志界面可查看；未配置或模型不支持时界面与现在一致。
- 思考内容只出现在 `.oan/sessions/` 下的 JSONL 日志中，不出现在 Play 会话文件、PendingAction diff、context trace、导出与 Git 跟踪文件中；跨轮请求不含历史思考（测试断言）。
- DeepSeek 等要求在同一轮工具调用中回传 `reasoning_content` 的 provider，多步工具调用不报错（mock provider 回归覆盖）。
- Copilot：运行中 steer 在下一次模型请求前作为 user 消息进入上下文，并在 transcript 中标记为"插话"；工具执行中的 steer 等工具结束后生效；turn 已进入 finalize 时 steer 被拒绝并提示改为排队。
- Copilot：运行中 Enter 把消息加入 follow-up 队列；follow-up 在本轮 `message_finish` 后按序发出；本轮失败、取消或产生待审批 PendingAction 时队列暂停，由作者决定继续；排队消息可转为插话，转换时 turn 已结束则保持排队并提示。
- Play world-referee turn：运行中 steer 取消当前未提交生成并以"原行动 + 补充"重发，不产生孤立 artifact；follow-up 在 settle 成功后以新 `baseRevision` 提交，revision 冲突时暂停队列。
- Play rehearsal：actor 生成中 steer 映射为当前 step 的 `redirectStep`，Director 约束校验不放宽。
- 相关 Runtime / Agent / Backend / Client / Desktop UI 回归通过；`npm run docs:check` 通过。

- Play 消息日志界面按时间顺序显示该会话所有日志条目，含思考过程（默认折叠），支持按类型筛选；日志缺失或损坏行时界面仍可打开并标出跳过的行。

## Decisions (2026-10-22)

- 运行中 Enter 默认排队；排队消息可转为插话。
- 思考过程默认折叠。
- Play 主界面不展示思考，新增 Play 消息日志界面展示全部消息与思考。
- 保留历史思考过程：对话消息与思考过程以 JSONL 保存，主要用于作者调试。

## Implementation Notes

本 task 分三期，各自一个 PR：Phase 1 推理过程与 JSONL / Play 消息日志；Phase 2 Copilot steer / follow-up；Phase 3 Play steer / follow-up。三期全部合入后状态改为 Completed。

### Phase 1（推理过程、调试日志）

- Runtime：新增 `reasoning_delta` 事件与 `RuntimeMessage.reasoning`。工具步骤的 assistant message 在本轮内带思考回传；turn 开始时去掉输入历史中的思考，结束时 `doneMessages` 也不保留，`RunTurnResult.messages` 保留本轮思考供 session store 写入 `messages.jsonl`。
- Agent：AI SDK adapter 消费 `reasoning-delta`，assistant 工具步骤转回 `reasoning` part；UI stream 输出 `reasoning-start/delta/end`。非 OpenAI 官方且有 `baseUrl` 的 provider 改用 `@ai-sdk/openai-compatible`（`includeUsage: true`）以解析和回传 `reasoning_content`。Play rehearsal actor / referee 收集思考，只放在终态事件 / 结果的 `reasoning` 字段，不混入叙事。
- 配置：与计划不同，模型配置只加一个可选字段 `reasoningEffort`（`none`/`minimal`/`low`/`medium`/`high`/`xhigh`/`max`），映射为 AI SDK `streamText` 的顶层 `reasoning` 选项；不另设 `supported` 开关，未设置即不发送。Desktop 模型编辑器新增“思考强度”下拉。
- 上下文预算不改：`maxOutputTokens` 已包含思考 token，Usage Inspector 原本已展示 `reasoningTokens`。
- Play 消息日志：`packages/backend/src/play-message-log.ts` 写 `.oan/sessions/.play-logs/<session-id>/messages.jsonl`（目录 0700、文件 0600、拒绝 symlink、单条文本上限 512K 字符），写入失败不影响回合。world-referee 记录作者行动、完整请求、思考、原始输出与提交 / 取消 / 失败；rehearsal 记录每次 actor / referee 调用。新增 `GET /api/workspace/play-sessions/:id/message-log` 与 client `getPlayMessageLog`；Desktop 在 Play inspector 中加入“消息日志”弹层（分页、按类型 / 角色筛选、思考和请求默认折叠、提示跳过的损坏行）。Play SSE 与主界面不含思考。
- Copilot 时间线在回答前显示默认折叠的“思考过程”，复制只复制正文。Copilot UI 本身仍不跨应用重启恢复对话，历史思考保留在 `messages.jsonl` 供调试查看。
- `recoverLatestSession` 跳过不是合法 session id 的目录（如 `.play-logs`）。
- 顺带修复：world referee 经 agent turn 运行时未指定 capability，referee prompt 中的 `oan-play-settlement` 会被关键词推断为 `novel.settle_chapter`，导致真实模型模式的 Play 回合失败；现固定传 `novel.play_scene`。
- 测试：`__test__/runtime/src/reasoning.test.ts`、`__test__/agent/src/reasoning.test.ts`（含 DeepSeek 式 `reasoning_content` 回传的 fetch 级回归）、rehearsal / session-store 补充用例、`__test__/backend/src/play-message-log.test.ts`、`__test__/desktop-ui/src/reasoning-display.test.ts`。均为 mock provider，未做真实 provider 联网验收。
