## Background

2026-10-22 评估过是否把底层从 Vercel AI SDK + Aider-style Runtime 切换为 pi agent（`@earendil-works/pi-agent-core` / `pi-ai`），结论是不切换：现有 `RuntimeSession` 已承载 PendingAction、顺序工具执行、上下文预算、usage 记录与 fail-closed finalizer，换框架收益小、迁移面大。评估中 pi 唯二值得吸收的能力是 **steer / followUp**（运行中插话与排队）和 **统一的推理过程（thinking）**。本 task 在现有架构内实现这两项，不引入新框架。

开工前提：依赖升级适配分支（`chore/deps-upgrade-adapt`）已合入 `main`。本 task 不与其并行改代码。

## Goal

1. **推理过程**：支持推理模型的思考内容在 Copilot 与 Play 中流式展示（默认折叠），并允许按模型配置推理强度；思考内容永远不进入 canonical 文件、PendingAction、Play 产物、证据或长期上下文。
2. **Steer**：作者在一轮 Copilot / Play 生成尚未结束时补充一句话，影响本轮剩余部分。
3. **Follow-up**：作者在一轮运行时预先排队下一条请求，本轮结束后按顺序自动发出，可编辑、可取消。

## Scope

- Runtime：`RuntimeModelStreamEvent` / `RuntimeEvent` 增加 reasoning 事件；`RunTurnInput` 增加可选 steering 来源，在工具批次之间和"无工具最终回答"之后轮询。
- Agent：AI SDK adapter、Play actor / referee 消费 SDK reasoning 流；provider resolver 让 OpenAI 兼容类 provider 能解析 `reasoning_content`；按模型配置传递推理强度。
- Backend：Copilot 活跃 turn 注册表与 steer 端点；Play world-referee turn 的 steer（取消未提交生成并以补充文本重发）。
- Client / Desktop UI：思考过程折叠块；Copilot 与 Play 输入框在运行中保持可用，提供"插话"和"排队"两种发送；follow-up 队列显示、编辑、取消。
- Core：`LlmProviderModel` 增加可选推理配置字段；usage 中已有的 `reasoningTokens` 在 Usage Inspector 中展示。

## Constraints

- 不引入 pi agent、AI SDK Agent 或任何新 agent 框架；Runtime 仍是单一 Aider-style loop（ADR 0002）。
- 工具执行保持顺序；steer 不打断正在执行的工具，只在工具批次边界生效。
- Steer 文本不得改变本轮 trusted host 选择：capability、`exactWritablePaths`、skill、allowed tools、上下文包来源都在 turn 开始时冻结。
- 一轮 turn 仍只有一个 `turnFinalizer` 批次；follow-up 是新的 turn，有自己的 PendingAction 批次，不合并进上一轮。
- 思考内容只做展示和本轮内必要的 provider 回传；不写入 agent session 持久化、Play `PlayTurnArtifact`、rehearsal evidence、context trace、adoption、memory 或 Git。`play-rehearsal-turn.ts` 中"private model reasoning is forbidden"的约束保持不变。
- Play 已提交（settled）的 turn 不因 steer 被改写；steer 只作用于尚未 settle 的生成，并沿用现有 cancel 路径与 `baseRevision` 校验。
- Play schema 不为本 task 升版本；steer 记录以"取消 + 带补充文本重发"表达，不新增 artifact 字段。
- 无真实 provider key 的测试不冒称联网验收。

## Non-goals

- 工具并行执行、自动重试、自动压缩、多 agent。
- 在 Play rehearsal 里新增 Director mutation 类型（运行中插话复用已有 `redirectStep`）。
- 把思考内容作为可采纳素材或写作参考。
- 跨应用重启保留 follow-up 队列。

## Done Criteria

- 配置了支持推理的模型时，Copilot 回复和 Play 生成在正文之前显示可折叠的思考过程；未配置或模型不支持时界面与现在一致。
- 思考内容不出现在 session 文件、Play 会话文件、PendingAction diff、context trace 与 usage 以外的任何持久化位置（测试断言）。
- DeepSeek 等要求在同一轮工具调用中回传 `reasoning_content` 的 provider，多步工具调用不报错（mock provider 回归覆盖）。
- Copilot：运行中 steer 在下一次模型请求前作为 user 消息进入上下文，并在 transcript 中标记为"插话"；工具执行中的 steer 等工具结束后生效；turn 已进入 finalize 时 steer 被拒绝并提示改为排队。
- Copilot：follow-up 在本轮 `message_finish` 后按序发出；本轮失败、取消或产生待审批 PendingAction 时队列暂停，由作者决定继续。
- Play world-referee turn：运行中 steer 取消当前未提交生成并以"原行动 + 补充"重发，不产生孤立 artifact；follow-up 在 settle 成功后以新 `baseRevision` 提交，revision 冲突时暂停队列。
- Play rehearsal：actor 生成中 steer 映射为当前 step 的 `redirectStep`，Director 约束校验不放宽。
- 相关 Runtime / Agent / Backend / Client / Desktop UI 回归通过；`npm run docs:check` 通过。
