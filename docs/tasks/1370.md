## Background

Full deconstruction analysed a book as one serial chain of 12,000-character chunks, each waiting for the previous chunk's rolling summary. A 1,000,000-character novel needed 85+ sequential provider calls per track. Modern models have far larger context windows and the aggregate tree already merges findings across chunks, so the chain cost wall-clock time without buying coverage.

## Scope

1. Chapter chunks are independent work units: no predecessors and no rolling summary in the model output.
2. One reservation runs up to `MAX_REFERENCE_FULL_PARALLEL_UNITS` (4) ready units in parallel. The analysis quality gate always runs alone. `settleReferenceFullDeconstructionReservation` settles every unit of the round at once; a failed or interrupted unit keeps its completed siblings, and retry re-queues every unfinished unit.
3. Chunk size follows the configured model's context window: a quarter of the window in characters, clamped to 12,000–96,000. Unknown windows keep 12,000. The size is frozen into the work plan at approval.
4. Follow-up in [1380](1380.md): reduction stages read the source through bounded read-only tools, and a question-driven entry explores the source freely.

## Invariants

- Evidence still uses host-issued opaque pointers revalidated by Core.
- Stored formats stay readable: the reservation keeps its lead unit fields and adds optional `batchUnits`; chapter outputs from earlier chained runs keep their `rollingContext` and fingerprints.
- One active reservation and one provider lease per run, unchanged.

## Implementation Review (2026-11-06)

- `packages/core/src/reference-deconstruction-full.ts` 创建无 chapter predecessor 的独立 chunk；`resolveReferenceChapterChunkChars` 按模型窗口的四分之一选择 12,000–96,000 字，未知窗口保持 12,000，批准时纳入冻结 work-plan fingerprint。
- `reference-deconstruction-store.ts` 的单一 reservation 最多选择 4 个 ready units，quality gate 独占；整批 settlement 保存已完成兄弟单元，失败/中断单元可单独重排，重启采用已持久化 receipt。

- Agent 的新 chapter output 不要求 rolling summary；旧产物的 optional rolling context/fingerprint 仍保留原校验。根目录 Core/Agent/Backend tests 覆盖独立计划、边界、并行屏障、部分失败、重试与 crash adoption。
