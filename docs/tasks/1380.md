## Background

After 1370 the model still only saw what the host handed it: one chunk at a time, then findings only. Current models search and read well on their own, so reductions and one-off questions can explore the source themselves while the host keeps evidence closed.

## Scope

1. `createReferenceSourceExplorer` gives a model two read-only, in-memory tools over host-selected chunk windows: `searchReferenceSource` (all terms on one line, at most 20 hits) and `readReferenceSource` (a line range inside one pointer, at most 4,000 characters). Every result names the host pointer that holds it, and the explorer records which pointers the model opened.
2. Technique aggregate units receive the chunk windows they cover. The aggregate may cite opened windows through `sourceEvidenceRefs` (at most 8) next to `sourceFindingRefs`. Core accepts only pointers inside the covered windows, and the agent accepts only pointers the model actually opened. When exploration fails, the aggregate retries once without tools. Style, distillation and Story Material stages are unchanged.
3. `POST /api/workspace/references/:referenceId/questions` answers one craft question. The whole source is split by the 1370 chunk sizing, the prompt lists only the pointer table of contents, and the model explores with the same tools for up to 12 steps. The answer carries findings, uncertainties, resolved evidence lines and a `copyRisk` flag for exact source runs of 80 or more characters, including non-aligned and cross-window runs. The full source stays host-only for this overlap check. Nothing is written: no run, bundle, PendingAction or project file.
4. The reference tab shows an "Ask about this reference" panel for the selected reference.

## Invariants

- Tools are read-only and see only the windows the host passed in; there is no filesystem or shell access.
- Evidence stays host pointers revalidated by Core; the quality gate includes `sourceEvidenceRefs` in its closure check.
- Stored aggregate outputs without `sourceEvidenceRefs` stay readable.
