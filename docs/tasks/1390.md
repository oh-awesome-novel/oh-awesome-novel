## Goal

在 Play 回合和 Reference 拆解任务内查看实际输入、缓存字段、耗时、阶段与来源，回答“为什么这一轮慢/贵、是否缺了上下文”，并为长篇整理和缓存优化提供实测基线。

## Existing Baseline

[1110](1110.md) 已有标准 usage/egress、Inspector、JSONL 和 G7 跨管线记录；[1180](1180.md) 有 Play context trace；[1350](1350.md) 有消息日志；[1360](1360.md) 有冻结前缀和 cache-point 测试。本任务补专用展示、关联和缺失的时间证据，不重建统计系统。

代码入口：`packages/core/src/agent-usage.ts`、`packages/agent/src/usage-governance.ts`、Backend 的 governance/Play/Reference routes，以及现有 Desktop usage/context/log 组件。

## Scope

- Play 回合、Rehearsal step 与 Reference run/unit 的稳定关联；重复/取消/失败调用不重复累计。
- 展示 estimated/actual/partial/unavailable、input/output/cache read/write tokens，以及 selected/omitted 来源。
- 记录并区分请求开始、模型首包、UI 可见首段、终态时间；不能把服务端隔离等待当成模型 TTFT。
- 显示固定前缀/工具 schema 的 fingerprint 与变化原因；缓存字段缺失不显示为 0 或“未命中”。
- 保留当前回合视图与重启后的有界历史，敏感信息沿用现有脱敏规则。
- 建立可控长会话 fixture 和作者显式启动的 provider 对照入口；不自动调用付费模型。

## Out Of Scope

- 价格抓取、法币账单系统、通用遥测平台或重新设计 prompt/cache runtime。
- 为了 Inspector 暴露 raw bash args、凭据、内部 draft 路径或扩大消息日志权限。
- 将参考项目的缓存限制、收益比例或 SDK 参数当作当前供应商事实。

## Done Criteria

- 从 Play/Reference 当前任务进入即可定位本次调用，切换 workspace/session 后不会展示迟到的旧结果。
- usage 缺失、失败/取消、并行 unit、重试和重启均有分层回归；统计口径不伪造实际值。
- 能解释预算组成与来源遗漏，并分清前缀稳定性和 provider 返回的实际缓存数据。
- 至少一条真实默认 SDK → HTTP/SSE → Desktop Inspector 的可控旅程通过；Core/Agent/Backend/Client/UI 检查通过。
- 记录本地 fixture 与真实 provider 验证边界；没有真实账单证据时不宣称节省比例。

## Implementation Notes

Play 回合、排演 actor/referee 与 Reference 拆解调用已绑定宿主生成的操作和阶段身份。检查器复用有界 JSONL，展示估算、实报字段、来源取舍、指纹变化和重复/冲突记录。模型首包与客户端首次可见分别观测。缺少缓存字段或时间证据时显示缺失。

生产 Client、HTTP/SSE、默认 SDK 适配器和 Desktop Inspector 使用受控 provider 验证了回合关联、重启回读和显式两次合成对照。千次调用 fixture 验证有界合计和观察记录保留。分层测试覆盖 Reference 多步读取、失败、取消、重试及 Player 来源脱敏。

真实 provider 的命中率与账单留给作者选择模型后实测。检查器入口本身不会发起模型调用。
