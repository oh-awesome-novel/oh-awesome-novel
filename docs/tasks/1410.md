## Goal

从大量已发布拆书材料中快速选出要采用的角色与设定，提前看懂目标冲突，再进入已有多文件审批。

## Existing Baseline

[1220](1220.md) 已有单 reference、多目标、create/update/skip、preview/promote/Accept、source/target freshness。`ReferenceMaterialEntrySelector.vue` 已支持按领域分组、多选和默认目标；这些不属于新功能。

复用 Core/Backend/Client/Tools `reference-material-adoption` 及 Desktop `ReferenceMaterialEntrySelector` / `ReferenceMaterialAdoptionPreview`。

## Scope

- 按文本、材料类型、置信度、warning 和选中状态筛选；大量列表有界分页/折叠，筛选不丢选择。
- 生成前批次 preflight：重复目标、已有对象、非法路径、失效来源、领域不匹配与本批数量/体积。
- 基于可信文件清单提示合法目标；作者可以重映射或移除条目，不能由模型自报扩大目标权限。
- 预览以作者语言显示新增/修改/跳过及原因，保持多文件 diff 和明确 Review 入口。
- 从已存在 origin/receipt/Git 派生采用记录；未知/已清理证据显示缺失，不能伪称从未采用。

## Out Of Scope

- 跨 reference 自动合并、同名人物自动消歧、自动冲突消解、长期原作绑定或新材料数据库。
- 新关系/大纲编辑协议、第二套 preview/materializer、绕过 PendingAction 的目标写入。
- 把全部 reference 原文或未选 entry 送进采用模型；本轮每次操作仍只消费一份 reference。

## Done Criteria

- 至少 500 条合成材料可筛选并选择一批，目标冲突能在模型调用前解释并手工解决。
- 成功采用、全部 skip、Reject、source/target drift、重启和重复点击均有生产链回归。
- 筛选/分页及 workspace/reference 切换不串用选择或迟到预览。
- Accept 前 canonical 不变，关闭 auto commit 不 commit/sync；采用记录只读且可重建/可解释缺口。
- 分层测试和完整“筛选 → 重映射 → diff → Accept”Desktop 旅程通过。

## Implementation Notes

2026-11-10 交付主要功能，状态为 Needs Review。1220 保持 Completed；本任务承接 W3b 中明确选定的子集，其余 W3b 候选仍暂缓。

已实现：

- **批次预检**（Core `preflightReferenceMaterialAdoption`）：确定性检查，不调用模型、不写文件。一次列出全部问题：材料目录已变更、条目未发布、重复选择、路径不合法、目标与材料类型不匹配、同一文件混用类型或 YAML 路径、目标不可读、超过 64 条或 32 个目标。另给出不阻断的说明：目标已存在将被修改、角色已存在将新增文件、多条合并到同一文件、批次过大。预检对非法目标不报错而是返回问题，所以接口只做长度限制。
- **合法目标提示**（Core `listReferenceMaterialAdoptionTargetSuggestions`）：宿主有界列出每类材料可用的现有文件（跳过隐藏名与符号链接，每类最多 200 条），随材料目录一起返回，在目标输入框里作为候选。它只是提示，预检与预览仍各自校验。
- **采用记录**（Backend `listRecords`）：从 PendingAction 的 origin、状态、Git 提交结果和已保存的采纳预览重建。预览记录缺失或不匹配时标为明细缺失，只保留它涉及的文件。界面写明记录只来自仍保留的审批数据。
- **Desktop**：材料列表支持文本、类型、把握、范围（有不确定说明 / 已选 / 采用过 / 无记录）筛选，每页 30 条，筛选不影响已选；可选中筛选结果（到 64 条为止）与清空；每条可改目标或移出这一批，问题显示在对应条目下；预检通过后才出现“生成采纳预览”；预览用中文说明新增 / 修改 / 跳过及原因；从预览返回时保留选择和已改的目标；采用过的条目标出去向。
- 接口：`POST .../material-adoption-preflight`、`GET .../material-adoption-records`；`GET .../materials` 增加 `targetSuggestions`。

验证：`LC_ALL=C npm run quality` 通过。新增 Core 2、Client 3、Backend 1、Desktop UI 8 项测试（另改写 2 项）。Backend 用例走真实 HTTP 与完整发布流程，覆盖预检的阻断与通过、预检期间模型零调用、接受 / 拒绝后的记录，以及删除预览记录后的明细缺失。Desktop 用例覆盖 500 条材料的筛选分页与选择保持、切换参考后丢弃迟到的预检。

尚未完成或未验证：

- 没有走真实后端的完整 Desktop 旅程测试（筛选 → 重映射 → diff → Accept）；界面测试在组件层。也没有在真实应用里目视检查过布局。
- 预检的 `mixedTarget`（同一时间线文件使用不同 YAML 路径）和 `targetUnreadable` 没有专门的测试。
- 全部跳过、Backend 重启、重复点击、关闭自动提交等场景沿用 1220 已有的回归，本轮没有针对新入口重新验证；切换 workspace 时的选择隔离没有测试。
- 采用记录的 Git 信息只取 PendingAction 记录的提交结果，没有另外从 Git 历史反查。
- 预检接口最多接受 512 条选择；500 条材料可以筛选，但一批仍最多采用 64 条。
