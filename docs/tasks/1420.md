# 1420 Play To Chapter Writing Flow

> Status: Planned
> Priority: P1
> Updated: 2026-11-06

## Related Plans

## Goal

把“选择一段当前世界线 → 说明保留/改写意图 → 生成下一章 → 审阅并保存”做成连贯旅程，减少作者在 Outcome、附件、Copilot 与章节目标之间反复搬运信息。

## Existing Baseline

[1150](1150.md) 已有 Outcome、角色 footprint 和请求级 Writing Reference；[1170](1170.md) 的 `chapterDraft` 已能创建/更新章节；[1330](1330.md) 已有下一章目标推导。本任务不把章节创建或 Play adoption 重新当成缺失能力。

复用 `play-outcome.ts`、`play-writing-reference.ts`、`play-adoption.ts`、`play-adoption-change-producer.ts`、Agent external context 与现有章节 workflow。

## Scope

- 从当前 selected branch 的有界片段/Outcome items 发起转写，清楚显示选中证据与范围。
- 收集轻量转写意图：必须保留的事件、允许调整的表达、POV、章节目标和篇幅方向；不强制复杂任务书。
- Host 自动确定下一章路径并展示；首版只创建一个章节，已有章修订走现有 revision/1430。
- 模型只消费选中 Play 素材和可信的当前小说上下文；产出完整合法章节候选，不直接复制聊天记录作为默认结果。
- 预览/提案/Accept 绑定分支、报告/附件、输入 hash、目标不存在和章节目标推导依据；需要时扩展现有 producer 的严格 origin，不另建引擎。
- Accept 后显示章节入口与“整理本章”建议；不自动启动整理、后续章节或更多模型调用。

## Constraints

- Play 素材仍是 non-canonical；不得将全部 Play state 自动合并到正式人物/世界/时间线。
- 未选兄弟分支、草稿回合、被隐藏的 Player 内容不能进入模型输入、标题、预览或迟到响应。
- 必须复用 CandidateChangeSet、prepared preview/PendingAction、ChangeMaterializer 和 Git 配置。
- 目标冲突或来源变化要求重新选择/生成，不静默沿用旧确认或改换写入路径。
- 所有原始 Play 记录保留；该入口是可选动作，不把 Play 结束绑定为必须写小说。

## Done Criteria

- 空作品和已有作品均可从选定 Play 素材生成唯一下一章候选，无需手工建文件。
- Preview/Reject/取消时 canonical 不变；Accept 后正文可读，auto commit 的开/关行为正确。
- Restore/Retry、来源修改、附件 detach、章节槽位冲突、Backend 重启后都能拒绝失效提案。
- 转写意图与所选证据可追溯，未选/hidden 内容有反例；文本质量与“事实引用可验证”分别评估。
- 真实默认 SDK → HTTP/SSE → Desktop diff → Accept → 显式整理入口旅程通过。
