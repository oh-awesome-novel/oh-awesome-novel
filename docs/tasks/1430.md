## Goal

让作者逐项对照原文和设定审阅问题，决定处理/保留/待定，再只对选定范围生成修订候选；审稿不隐式写作或结算。

## Existing Baseline

[1030](1030.md) 已有 `ReviewFinding`、dimension checklist、formatter 与 report-only 指引；[1360](1360.md) 已有 11 类 LINT、段落锚定和局部建议。当前一般审稿主要依赖 Copilot 指令与报告合同，缺少统一的结构化报告生产链和问题选择面板。

复用 `packages/core/src/writing-review.ts`、Novel LINT、固定投影、`chapter.edit` policy 与现有审批 UI。

## Scope

- 冻结章稿与依据，生成带稳定 finding id、source hash、行/段范围、字面引文、规则来源和置信边界的严格报告。
- 连贯性、人物、世界、剧情、伏笔、节奏、文风、证据八维明确为 pass/issues/notChecked。
- 问题面板能跳回原文/依据，作者选择处理、保留或待定；选择绑定该份报告和正文版本。
- 作者明确要求修订后，只授予对应章稿和选中范围；范围外内容由候选校验保证不变。
- 保存有界、可重开的报告和本次裁决；它们是 `.workspace` 中的审阅记录，不是小说事实或永久风格规则。
- 字数等可计算指标由代码计算；只读审稿与修订是分开的明确操作。

## Constraints

- 普通 `/审稿` 使用只读能力，不自动 settlement、不默认二次调用模型修稿。
- 文学判断保持 advisory，不以总分、固定句长/禁词比例或外部 AI 检测器决定是否准许写作。
- 只有结构/来源/权限等可机械证明的错误阻断候选；模型自报 blocking 不能创造新的权限或强制写作门槛。
- 报告过期必须重验/重新审稿，不能仅依赖旧行号；扩大修订范围需作者重新选择。
- 不新增多 Reviewer Agent、隐藏修复循环、完整规则编辑器或新的 canonical 风格域。

## Done Criteria

- 只读审稿结束不产生 canonical 修改，未检查维度不能冒充 pass。
- 所有可定位 finding 的原文/设定引文通过 hash 和范围核验；无法验证的推断明确标识。
- 单项/多项局部修订只生成 PendingAction，未选范围保持；重复文本、交错锚点和正文漂移有反例。
- Reject、取消、重启、workspace 切换与迟到结果不丢失作者裁决或混用来源。
- 作者可完成“打开报告 → 查看依据 → 选择问题 → 审阅修订 → Accept”；Core/Agent/Tools/Backend/Client/Desktop 分层回归通过。
