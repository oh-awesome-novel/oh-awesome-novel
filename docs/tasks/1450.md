## Goal

重演一回合时，作者可以说明“这次希望有什么不同”，行动本身不变；建议行动不够用时，可以再要一批。

## Existing Baseline

[1120](1120.md) 的原子 Retry 只接受 `baseRevision`，行动文本与类型从原 `worldSettlement` artifact 读取，结果是同一父节点下的 sibling。[1350](1350.md) 的插话是“取消后合并补充文本重发”，不适用于已提交回合。会话内只读提问通道已由 [1360](1360.md) 提供。

代码入口：Core `play-turn-retry.ts`、`play-turn-artifact.ts`；Backend `play-context-question.ts` 与 Retry SSE 路由；Desktop `PlayHistoryControls.vue`、`PlayComposer.vue`。

## Scope

- Retry 请求增加可选的重演指引，上限 500 字。行动文本和类型仍由宿主从原 artifact 读取，调用方不能覆盖。
- 指引只进入本次重演的消息尾部，不进入冻结前缀，不延续到后续回合。
- 指引写入新 sibling artifact 的可选作者视角字段（规划中的方案 B），使分支可自解释。旧 artifact 没有该字段时读取结果不变。
- “再给几个行动建议”：一次只读调用，结果只在界面临时显示，点击后填入输入框。不写会话快照，不推进 revision。
- 场景试演沿用已有的 Modify / 插话，不在本任务范围。

## Constraints

- 实施前先在 [PLAY_MODE_SPEC](../PLAY_MODE_SPEC.md) 写明 artifact 新字段的合同与旧数据兼容规则；不得为此放宽 v4 严格读取。
- 指引是 Director 信息：Player 视角的存档点摘要、世界线预览与采纳表单不得显示。
- 旧回合、其后代、事件、观察与采纳记录全部保留；取消、provider 或 schema 失败、revision 漂移保持零写入。
- 补充建议每次点击最多一次模型调用，失败不影响会话。

## Done Criteria

- 首回合、祖先节点、带到期计划事件的回合都能带指引重演，并产生正确的 sibling。
- 指引不出现在下一回合的模型请求中；不带指引的重演行为与现在逐字段一致。
- Player 视角看不到指引，有反例测试。
- 补充建议不改变 revision、建议列表快照与选中分支；生成中或其他操作占用时入口禁用。
- 默认 SDK → HTTP/SSE → Desktop 的“带要求重演”旅程通过。
