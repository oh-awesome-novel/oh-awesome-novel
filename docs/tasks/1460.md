# 1460 Play Adoption Forms And Chinese Author Language

> Status: Planned
> Priority: P0
> Updated: 2026-11-10

## Related Plans

- [Play 模式强化规划 · I2、I3](../plans/PLAY_MODE_ENHANCEMENT_PLAN_2026-11-10.md#i2-采纳表单去-json)

## Goal

把推演结果带回写作时填表单而不是手改 JSON；Play 界面统一使用中文作者语言。

## Existing Baseline

[1170](1170.md) 的采纳链路（证据闭包、预览、PendingAction）完整可用，但表单以 “Editable JSON payload” 表达待采纳数据。Play 界面的按钮与标签多为硬编码英文，例如 `PlayComposer.vue` 的 `Act` / `Advance`。

代码入口：Desktop `PlayAdoptionDraftForm.vue`、`PlayAdoptionPanel.vue`、`usePlayAdoptionPreview.ts` 及 `components/play/` 下各组件；用户文档 `wiki/guide/play.md`。

## Scope

- 章节草稿、状态、时间线、伏笔四个采纳目标各有一张类型化表单，产出与现有后端合同相同的 payload。
- 表单保留只读的“查看 JSON”展开；校验错误定位到具体字段。
- Play 的按钮、标签、空状态与错误提示统一为中文，采用规划文档中的术语表；界面、用户文档与提示语共用同一套说法。
- 更新 `wiki/guide/play.md` 的操作名，并补齐其中三处“截图待补”。

## Constraints

- 纯界面与文档改动：不改采纳 payload 合同、预览、PendingAction 与 Accept 链路。
- 协议字段名、文件名、日志中的英文标识保持不变。
- 不引入新的国际化框架，除非现有界面已有可复用的机制。
- Player 视角的表单仍不得显示隐藏内容或 canonical baseline。

## Done Criteria

- 四个目标都能不接触 JSON 完成“填写 → 预览 diff → 创建 PendingAction”。
- 表单产出的 payload 通过现有后端校验；非法输入在提交前有字段级提示。
- Play 主要旅程（开局、推进回合、历史控制、试演、结果报告、采纳）中不再出现英文操作名。
- 用户文档与界面用词一致，Wiki 构建通过。
