# 1470 Play Launch Reuse And Relationship Panel

## Related Plans

## Goal

用旧会话的开局设置再开一局；在长局里看清人物关系是在哪一回合、因为什么变化的。

## Existing Baseline

[1140](1140.md) 的 Launch Package 冻结了来源、入场点、身份与参与者，但没有从已有会话预填向导的入口。[1120](1120.md) 已有 `relationshipChanged` 事件与 `relationship` 类 Pressure，变化散落在事件流中。

代码入口：Core `play-launch.ts`、`play-launch-session.ts`、`play-session-read-model.ts`；Desktop `components/play/launch/`、`PlaySessionRail.vue`、`PlayWorldHud.vue`。

## Scope

### 开局复用

- 会话列表与详情提供“以此开局再开一局”，用该会话冻结的 Launch Package 或快速开局表单预填向导。
- 预填后按当前文件重新校验来源；内容变化或缺失的来源在创建前标出，由作者决定沿用新内容或移除。
- 确认后创建全新会话，与旧会话没有分支关系。

### 关系与态度面板

- 从当前选中分支的 `relationshipChanged` 事件与 `relationship` 类 Pressure 派生只读面板。
- 按人物对列出变化的先后，每条链接到事件卡片与回合。

## Constraints

- 不做开局模板库，不新增具名开局的存储。
- 关系面板是可重建投影：不新增事实文件，不引入好感度数值。
- 面板只读当前选中路径；Player 视角按现有可见性规则过滤隐藏事件与原因。
- 复用开局不得把旧会话的 Play-local state、事件或认知带入新会话。

## Done Criteria

- 预填后不经修改即可创建；来源缺失或变更时在创建前给出诊断。
- 新旧会话互不影响，旧会话 revision 不变。
- 切换分支后关系面板只反映当前选中路径；有隐藏事件不泄漏的反例测试。
- 两项功能各有 Desktop 旅程测试。

## Dependencies And Sources

- 复用 1120、1140；可在任意批次穿插交付。两部分互相独立，可分开合入。

## Implementation Notes

### 2026-11-11（两部分同时交付）

前置任务核对：1140 已 Completed；[1120](1120.md) 仍为 Needs Review，但未关闭项是设备断电、跨平台与真实 provider 的外部验收，以及离线 tombstone 清理，本任务用到的 `relationshipChanged` 事件、`relationship` Pressure 与分支快照均已落地，不构成阻塞。

**开局复用**

- Core `play-launch-reuse.ts`：`readPlayLaunchReuseSeed` 只读旧会话。引导开局返回去掉 setup id 与冻结证据的预览输入，并逐个来源对照当前文件给出 `unchanged / changed / missing / invalid`；快速沉浸推演返回表单字段，快速场景试演返回场景与人物。种子里没有 transcript、事件、Play-local state 或认知记录。
- Backend `GET /api/workspace/play-sessions/:id/launch-reuse`，Client `getPlayLaunchReuseSeed`，带严格解析。
- Desktop：会话列表每一项与工作区顶栏（当前会话）都有“以此开局再开一局”。引导开局直接进入向导并预填；来源 id 按路径重新生成，不沿用旧 setup 的 id。来源都没变时直接落在“确认”步骤，不经修改即可创建；有变化时停在“来源”步骤，列出每个变化，变化的文件默认沿用现在的内容并可移除，已不存在的文件自动移除并说明。快速开局预填对应表单。
- 创建走现有的预览 → 保存开局包 → 开始会话，得到新的 setup 与新的会话，旧会话没有任何写入。

范围内的两处取舍：

- 快速开局只带回表单能表达的内容。世界动向种子取开局时的第一条压力与第一条动向（表单本身只能填一条）；由阶段归档续开的会话不带动向种子，因为它的起点状态是上一阶段的推演结果。
- 引导开局里一个参与者有多条初始认知时，预填合并为一条（向导目前只支持一条）。

**关系与态度面板**

- Core `play-relationship-timeline.ts`：`projectPlayRelationshipTimeline(session, lens)` 沿当前选中路径读取 `relationshipChanged` 事件与 `relationship` 类 Pressure 的状态变化，按人物分组、按回合排序。不写任何文件，不含数值。
- 人物归属从事件标题与摘要里出现的已知人物名得出（会话人物、人物名册、试演参与者）：提到两人及以上归为这几人，只提到一人归为“此人与参与者”，一个都没提到归入“未指明人物”，不做猜测。
- 参与者视角去掉 `playerUnknown` 的事件与压力以及全部起因；导演视角显示起因。Client 解析时再校验一次参与者视角不含隐藏条目。
- Backend `GET /api/workspace/play-sessions/:id/relationships?lens=`，Client `getPlayRelationshipTimeline`。投影在服务端基于完整分支计算，不受 Desktop 事件窗口分页影响。
- Desktop `PlayRelationshipPanel.vue` 位于世界面板下方，随会话、分支头与视角变化重新读取；每条可跳到事件卡片（未加载时自动向前翻页）与世界线上的回合。回合提交瞬间的读取会被会话锁拒绝，面板做有限次重试并提供手动重试。

**验证**

- Core：`play-launch-reuse.test.ts`（5 项）、`play-relationship-timeline.test.ts`（4 项，含 Restore 后只反映选中路径、隐藏事件与隐藏压力不泄漏的反例）。
- Backend：`play-launch-reuse.test.ts`（默认 SDK 经 HTTP 复用开局、来源变化诊断、旧会话 revision 不变）。
- Desktop 旅程：`play-launch-reuse-journey.test.ts`（4 项：未变化直接创建、变化与缺失的诊断和移除、快速表单预填、读取失败）；`play-relationship-panel-sdk-journey.test.ts`（默认 SDK → HTTP/SSE → Desktop：两回合、参与者与导演视角、跳转、Restore 后面板收缩）。
- 未做：真实模型下关系事件的命名质量。人物归属依赖裁判在事件文字里写出人物名，写得含糊时会落入“未指明人物”。
