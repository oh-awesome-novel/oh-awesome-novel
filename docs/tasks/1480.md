## Goal

让沉浸推演知道原作接下来会发生什么，并记录作者改掉了什么：哪些原作事件照常发生、被改写、被阻止或不再适用。

## Existing Baseline

Guided Start 可以选择 `timeline` 来源，但它只作为普通上下文进入裁判提示；Play 中没有原作节点或偏离状态的类型。`worldMomentum` 已示范了“放在 Play-local state 固定键下、随分支快照保存”的做法。

代码入口：Core `play-world-momentum.ts`（参照）、`play-referee-protocol.ts`、`play-launch.ts`、`play-outcome.ts`；Desktop `PlayWorldHud.vue`、`components/play/launch/`、`components/play/outcome/`。

## Scope

- 引导开局的入场步骤增加“原作节点”：从已选 `timeline` 来源勾选入场点之后的事件，上限 24 条；每条冻结来源路径、内容哈希与逐字引文。
- 允许作者手写节点；手写节点没有来源引文，明确标为作者提供。
- 开局时选择穿越者是否知道原作，决定节点对参与者视角是否可见。
- 新模块 `play-canon-beats.ts`：类型、编解码、状态迁移纯函数与校验。节点表存放在 Play-local state 的固定键下。
- 回合结算增加 `canonBeatChanges`：每条带理由并引用本回合事件；宿主校验节点存在、迁移合法、引用属于本回合。
- 世界 HUD 增加“原作走向”面板，按五种状态分组，状态变化链接到回合与事件。
- 导演视角可手动更正节点状态，作为 `manual` 来源的变更记录。
- 待发生节点可一键转为计划事件，使用现有触发类型。
- 结果报告增加“与原作的差异”分组，可用于写作参考与采纳。

## Constraints

- 节点表属于会话，不修改 `timeline/` 正式文件。
- 不做自动推进原作的引擎：没有被转成计划事件的节点不会自己发生。
- 宿主不判断自然语言剧情是否“算发生”；状态变化由裁判提出或作者更正。
- 终态不能回到待发生；非法变更使整回合失败且零写入。
- 首版只支持沉浸推演（v4），且只对新建会话启用；旧会话的冻结前缀不含该协议，不追加启用。
- 实施前在 [PLAY_MODE_SPEC](../PLAY_MODE_SPEC.md) 明确结算协议新字段，并核实是否需要 session schema 或 watermark 变更。
- 节点被阻止后的连锁后果由裁判提出，受现有事件预算约束；宿主不自动生成。

## Done Criteria

- 新建会话选择节点后，五种状态都能通过真实回合到达，并体现在 HUD 与结果报告中。
- 非法迁移、伪造节点 id、引用非本回合事件都使回合失败且零写入。
- Restore / Retry 后节点表回到对应分支的状态；归档开启新阶段后节点表完整带入。
- 穿越者不知道原作时，Player 视角的 HUD、建议行动与采纳表单都看不到节点内容，有反例测试。
- 来源文件变化走现有来源漂移流程，节点保留冻结时的引文。
- 未启用节点表的会话在存储与请求上与现在一致。
- 默认 SDK → HTTP/SSE → Desktop 的“选节点 → 推演 → 查看偏离 → 生成结果报告”旅程通过。

## Implementation Notes

### 2026-11-11（交付）

前置任务核对：1140、1150、1160、1400 已 Completed；[1120](1120.md) 的未关闭项是外部环境验收与离线 tombstone 清理，不阻塞本任务。

实施前先写了[实施计划](../superpowers/plans/2026-11-10-play-canon-beats.md)并在 [PLAY_MODE_SPEC](../PLAY_MODE_SPEC.md#canon-beats-and-divergence-ledger) 写明合同。核实结论：不需要 session schema、artifact schema 或 watermark 变更；节点表是 Play-local state 的保留键 `canonBeats`，是否启用在创建时决定，由历史校验强制，旧会话不能追加。

**已交付**

- Core `play-canon-beats.ts`：类型、codec、迁移纯函数、历史校验、视角投影、候选节点提取。
- 开局：Launch Package 增加可选 `canonBeats`。来源节点的引文必须是所选 `timeline` 文件当前内容的逐字子串，冻结路径、内容哈希与引文；找不到引文时给 `canonBeatQuoteMissing` 诊断并阻止创建。手写节点标为作者提供。上限 24 条，只对沉浸推演有效。候选节点由宿主从时间线文件提取（结构化 `events` / `timeline` 条目的 `title`，否则逐行），全部是原文。
- 结算：可选字段 `canonBeatChanges`，用本回合 `events` 的 1 起始位置引用事件。节点协议只进入启用会话的冻结前缀，回合尾部列出全部节点。
- 导演操作：手动更正与“转为计划事件”各写成一条导演记录（`transcriptAppend`，说话人 `director`）。Core 的 `play-session-facts.ts`、`play-event-schedule-history.ts` 与 Client 的重放校验按同一规则放宽，且只对导演记录生效。
- 结果报告新增 `canonDivergence` 条目，界面分组为“与原作的差异”；采纳默认目标为时间线。
- 阶段归档：宿主克隆带入；归档提示与 `resourceState` 审计不含节点表。
- Backend：`POST /api/workspace/play-setups/canon-beat-candidates`、`POST /api/workspace/play-sessions/:id/canon-beats`。Client：对应方法、严格解析、`projectPlayCanonBeatTable`。
- Desktop：向导入场步骤的“原作节点”（勾选、手写、是否知道原作），确认步骤列出节点；世界面板“原作走向”按五种状态分组，链接到回合与事件；导演视角可更正状态、把待发生节点转为计划事件。

**与规划的出入**

- 规划里的数据模型没有变更记录列表。实现增加了只增不改的 `changes`，因为“手动更正记录在案”与历史校验都需要它。
- 裁判只能把 `pending` 改成终态。导演更正可以在终态之间改写，但同样不能改回 `pending`；要撤销裁判的判定只能重演那一回合。这是对“终态不能回到待发生”的字面执行。
- “转为计划事件”时由作者选择事件发生时的可见性，默认沿用节点的可见性。穿越者不知道原作时默认是隐藏的，否则计划列表会在参与者视角提前露出节点内容。
- 节点表在分支快照里，每个 turn artifact 都带一份。24 条带引文的节点最坏情况下每回合多十几 KB，属于 [1120](1120.md) 已登记的“快照随历史增长”范围，没有另做优化。

**验证**

- Core `play-canon-beats.test.ts`（24 项）：冻结引文与诊断；五种状态经回合到达；八种非法变更使回合失败；无节点表的会话拒绝节点变更；篡改历史（给旧会话加表、改写已结算节点）读取失败；Restore 与 Retry 回到对应分支状态；归档续开后节点表完整且可继续结算；导演更正与转计划事件，含落盘再读回、到期后经普通回合结算；两种“是否知道原作”下的投影与结果报告。
- Backend `play-canon-beats.test.ts`（7 项）：默认 SDK 经 HTTP/SSE 走完“选节点 → 推演 → 查看偏离 → 生成结果报告”；四种非法变更下回合失败且 revision、状态、事件与 `turns/` 目录文件都不变；导演操作的 revision 检查与 Restore；未启用会话的前缀与请求不含节点协议。
- Desktop `play-canon-beats-sdk-journey.test.ts`：默认 SDK → HTTP/SSE → Desktop 的完整旅程，含参与者视角看不到面板、节点文字与理由的反例。
- 既有回归：Core 全量通过；最终门禁结果见[任务索引](README.md)。

**没有验证的**

- 真实模型是否稳定给出正确的节点判断、是否在“不知道原作”时守住叙述不泄漏。这两点由提示约束，宿主只能校验结构，不能校验叙述文字。由作者用真实模型验收。
- 采纳表单没有单独的界面反例测试；它的数据来自结果报告的参与者投影，该投影已在 Core 与 Backend 测试里验证不含节点内容。
