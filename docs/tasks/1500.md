## Goal

综漫开局时，来源带有作品归属，不同作品的角色默认互不知情，规则冲突有作者写明的裁定。

## Existing Baseline

`PlayLaunchSource` 只有 `role`、`trust`、`budgetLayer` 等字段，没有来源作品标识；Play 中没有综漫相关概念。[1160](1160.md) 已有分支内认知存储与显式揭示，[1190](1190.md) 有按参与者授予认知，[1130](1130.md) 的场景试演使用逐角色感知包。

代码入口：Core `play-launch.ts`、`play-knowledge.ts`、`play-rehearsal-knowledge.ts`、`play-context-trace.ts`；Desktop `components/play/launch/`、`components/play/context/`。

## Scope

- 引导开局的来源步骤可为每个来源标注所属作品；Launch Package 的来源记录增加 `originWork`。
- 有可用的材料采纳记录时预填作品归属，作者确认后生效；没有时全部手标。
- 选择两部以上作品时，向导增加融合契约一步：作品列表、融合方式（世界融合 / 单向来客 / 并存叠层）、认知默认（隔离 / 互知）、规则裁定条目。契约冻结在 Launch Package 并进入会话的冻结前缀。
- 认知隔离：角色初始认知边界只含本作品来源。场景试演体现在感知包；沉浸推演作为带类型的边界交给裁判，并复用分支内认知存储。跨作品得知信息必须是显式认知变更，带来源回合。
- 开局诊断新增两类警告：综漫会话中有来源未标注作品；两部作品都提供世界规则来源但没有裁定条目。
- 上下文追踪按作品分组显示本轮实际使用的来源。

## Constraints

- 契约只属于会话；不新增正式事实域。长期保存的融合设定照常写成 `world/` 文件并在开局时选中。
- 不自动合并同名角色，不自动认定跨作品人物同一性，不做跨 reference 自动融合。
- 宿主只做结构检查，不判断设定在语义上是否冲突；两类诊断是警告，不阻断创建。
- 单作品会话的行为、存储与请求与现在一致。
- 认知隔离是初始边界加可追溯的变更，不承诺模型绝不在叙述中说漏；与现有隐藏信息保护的边界相同。
- 实施前在 [PLAY_MODE_SPEC](../PLAY_MODE_SPEC.md) 明确 Launch Package 新字段及其版本兼容规则。

## Done Criteria

- 两部作品各两名角色的合成工作区：隔离模式下角色感知包不含另一作品来源。
- 跨作品认知只能通过显式变更出现，并可追溯到来源回合；Restore / Retry 后认知回到对应分支状态。
- 未标注作品、缺少裁定时出现对应警告，仍可创建。
- 旧 Launch Package 可正常读取；单作品会话有回归证明无变化。
- 默认 SDK → HTTP/SSE → Desktop 的“标注作品 → 填写契约 → 开局 → 查看按作品分组的来源”旅程通过。

## Dependencies And Sources

## Implementation Notes

2026-11-12 已交付，字段与兼容规则见 [PLAY_MODE_SPEC](../PLAY_MODE_SPEC.md#综漫融合契约1500)。来源可标注 `originWork`，多作品开局必须由作者确认融合方式、认知默认和规则裁定；契约、来源 hash/摘要和人物初始来源边界冻结在 Launch Package / 会话中，进入冻结前缀。缺少作品归属、多个世界规则来源无裁定仅警告。未启用契约的旧包、单作品默认前缀与行为保持不变。

场景试演按所属作品创建初始知识证据，并过滤另一作品的 source-backed 场景字段；显式 Director 知识授予复用原有分支记录。沉浸推演的 `learnSource` 必须引用已冻结来源、已知人物和本回合 informationSpread 事件，宿主生成 sourceGrant，保存在原有 playKnowledge 快照中。重复授予、未知来源/人物和无事件依据会使本回合失败；Restore/Retry 不继承兄弟分支认知。没有融合契约的会话不接受此变更。

Desktop 来源步骤可手动标注或从仍保留的 accepted 采纳记录预填（最多检查 32 部参考作品；多个出处或无记录时留给作者）。预填仍需作者检查、预览和确认。多作品时增加融合契约步骤；开局复用保留归属与契约。实际回合上下文追踪按作品分组，参与者视角使用匿名作品标签，导演视角显示作品名。

新增 Core 7、Backend 1、Client 1、Desktop 2 项回归，覆盖两作四角色感知隔离、显式 Director 跨作品授予及来源回合、沉浸认知保存/重启/Restore/Retry、旧包/单作品、非阻断诊断、严格 DTO、采用记录预填与默认 SDK → HTTP/SSE → Desktop 的标注/契约/开局/来源分组旅程。模型使用受控响应验证协议与接线；自然语言的角色/设定质量仍由作者在实际创作中判断。

门禁：macOS / Node 24.22.1，build、lint、typecheck、docs:check、docs:build 全部通过；七个测试 workspace 共 287 文件 / 2,144 项通过。最终补充阶段续局 DTO 验证和预填期间的向导等待后，重新构建、Client/Desktop 类型检查及对应两项回归通过。未执行真实 provider 文学质量或原生 Electron 打包验收。
