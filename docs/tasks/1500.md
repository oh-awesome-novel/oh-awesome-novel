## Goal

综漫开局时，来源带有作品归属，不同作品的角色默认互不知情，规则冲突有作者写明的裁定。

## Existing Baseline

`PlayLaunchSource` 只有 `role`、`trust`、`budgetLayer` 等字段，没有来源作品标识；Play 中没有综漫相关概念。[1160](1160.md) 已有分支内认知存储与显式揭示，[1190](1190.md) 有按参与者授予认知，[1130](1130.md) 的场景试演使用逐角色感知包。

代码入口：Core `play-launch.ts`、`play-knowledge.ts`、`play-rehearsal-knowledge.ts`、`play-context-trace.ts`；Desktop `components/play/launch/`、`components/play/context/`。

## Scope

- 引导开局的来源步骤可为每个来源标注所属作品；Launch Package 的来源记录增加 `originWork`。
- 有可用的材料采纳记录时预填作品归属，作者确认后生效；没有时全部手标。
- 选择两部以上作品时，向导增加融合契约一步：作品列表、融合方式（世界融合 / 单向来客 / 并存叠层）、认知默认（隔离 / 互知）、规则裁定条目。契约冻结在 Launch Package 并进入会话的冻结前缀。
- 认知隔离：角色初始认知边界只含本作品来源。场景试演体现在感知包；沉浸推演作为带类型的边界交给裁判，并复用分支内认知存储。跨作品得知信息必须是显式认知变更，带来源回合。
- 开局诊断新增两类警告：综漫会话中有来源未标注作品；两部作品都提供世界规则来源但没有裁定条目。
- 上下文追踪按作品分组显示本轮实际使用的来源。

## Constraints

- 契约只属于会话；不新增正式事实域。长期保存的融合设定照常写成 `world/` 文件并在开局时选中。
- 不自动合并同名角色，不自动认定跨作品人物同一性，不做跨 reference 自动融合。
- 宿主只做结构检查，不判断设定在语义上是否冲突；两类诊断是警告，不阻断创建。
- 单作品会话的行为、存储与请求与现在一致。
- 认知隔离是初始边界加可追溯的变更，不承诺模型绝不在叙述中说漏；与现有隐藏信息保护的边界相同。
- 实施前在 [PLAY_MODE_SPEC](../PLAY_MODE_SPEC.md) 明确 Launch Package 新字段及其版本兼容规则。

## Done Criteria

- 两部作品各两名角色的合成工作区：隔离模式下角色感知包不含另一作品来源。
- 跨作品认知只能通过显式变更出现，并可追溯到来源回合；Restore / Retry 后认知回到对应分支状态。
- 未标注作品、缺少裁定时出现对应警告，仍可创建。
- 旧 Launch Package 可正常读取；单作品会话有回归证明无变化。
- 默认 SDK → HTTP/SSE → Desktop 的“标注作品 → 填写契约 → 开局 → 查看按作品分组的来源”旅程通过。
