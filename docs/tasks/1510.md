# 1510 In-character Check

## Goal

作者对某一回合或试演步骤发起检查，得到“哪句话不像这个角色”的意见，每条都附叙述原句和角色资料中的依据。

## Existing Baseline

认知边界由宿主强制（[1160](1160.md)），Novel LINT 用正则检查正文套话（[1360](1360.md)）。声线与动机是否贴合角色卡没有检查入口。会话已冻结角色来源与名册档案；[1400](1400.md) 的历史回忆示范了“宿主构造固定只读窗口、逐字核对引文与哈希”的做法。

代码入口：Core `text-speaker-parser.ts`、`play-outcome.ts`（过期判定参照）；Agent `play-phase-recall.ts`（参照）；Backend `play-frozen-context.ts`、`play-context-question.ts`；Desktop `PlayTranscript.vue`、`components/play/rehearsal/`。

## Scope

- 已提交回合与试演步骤上提供“检查角色贴合度”，每次点击是一次显式只读模型调用。
- 宿主构造固定材料：该回合叙述，加出场名册角色在会话中冻结的角色来源（角色卡事实、互动样例、名册档案）。
- 意见结构：角色、叙述原句、类别（声线 / 动机 / 认知 / 关系）、依据原句、说明。
- 宿主逐条核对两处引文能逐字找到；核对不过的意见丢弃并显示丢弃数量。
- 每条意见的出口：带着这条意见重演（进入 [1450](1450.md) 的指引框，可改写）；记为观察笔记。
- 报告保存在会话侧，绑定回合与分支；分支变化后标为过期。

## Constraints

- 结果仅供参考：不打分，不阻断任何操作，不自动重演或改写。
- 报告不进入 turn artifact、采纳证据闭包、导出或 Git。
- 模型只读宿主给出的固定材料，不获得其他会话内容、兄弟分支或内部路径。
- Player 视角发起检查时，材料与结果不含隐藏内容。
- 没有角色来源的临时角色显示“无可对照资料”，不得显示为“没有问题”。
- 调用有输入体积上限；放不下时明确说明省略了什么，不按字符硬截断。

## Done Criteria

- 伪造或改写引文的意见被丢弃，有回归测试。
- 取消、provider 失败或格式错误不留下半份报告，不影响会话 revision。
- Restore / Retry 切换分支后旧报告标为过期，过期报告的“带意见重演”入口禁用。
- Player / Director 隔离有反例测试。
- 默认 SDK → HTTP/SSE → Desktop 的“检查 → 选一条意见 → 带意见重演”旅程通过；意见的文学质量由作者用真实模型另行验收。

## Implementation Notes

### 2026-11-12（交付）

前置任务核对：[1450](1450.md)、1160、1400 已 Completed；[1360](1360.md) 仍是 Needs Review，但未关闭项（Forge 草稿锁、handoff 漂移复核、真实模型验收）与本任务使用的冻结前缀和名册无关，不阻塞。本任务没有关联的 superpowers 实施计划，按 scope / constraints / done criteria 直接实施；合同写在 [PLAY_MODE_SPEC](../PLAY_MODE_SPEC.md#角色贴合度检查in-character-check)。不需要 session schema、artifact schema 或 watermark 变更。

**已交付**

- Core `play-character-check.ts`：固定材料构造（回合 / 试演步骤）、按整块取舍的体积上限、提示与材料格式、回复解析与逐字核对、报告类型与严格读取、过期判定。
- Agent `play-character-check.ts`：一次无工具的 `generateText` 调用，只发送宿主材料，记入用量（`stage: characterCheck`）。
- Backend `play-character-check.ts`：`POST` / `GET /api/workspace/play-sessions/:id/character-checks`；报告存 `.oan/sessions/.play-checks/<session-id>/character-checks.json`。
- Client：`requestPlayCharacterCheck`、`listPlayCharacterChecks`、严格解析（拒绝多余字段、别的会话或视角的报告）、`formatPlayCharacterCheckGuidance`。
- Desktop：推演记录里已提交叙述下的“检查角色贴合度”；试演步骤上的同名按钮；“角色贴合度”面板；两个出口分别预填世界线的重演指引框（试演为“修改 → 改变走向”）与观察笔记表单。
- 用户文档：[推演指南](../../wiki/guide/play.md)“检查角色贴合度”。

**与规划的出入**

- “冻结的角色来源”取自会话创建时写入 `frozenSystemPrompt` 的角色块和 `characterRoster`，不重新读取 `characters/` 文件。这样材料就是裁判当时看到的内容，来源漂移不影响检查；代价是创建时因预算被截断或省略的来源，检查时同样看不到。
- 场景试演会话（v5）没有冻结前缀，角色资料用 sidecar 里的试演设定与角色已知事实。
- Desktop 的有界读模型只有消息编号，没有回合编号，所以请求增加了 `turnMessage` 目标，由宿主解析到选中分支上的回合。
- 沉浸推演里已提交叙述和冻结角色来源本来就对参与者可见，两种视角的材料相同；隐藏内容的差别只出现在试演步骤（仅导演可见的段落与事实）。报告仍按视角分开保存和列出。
- “记为观察笔记”只对沉浸推演提供：宿主不接受场景试演会话的 observation，这是既有合同。
- 没有可对照资料的角色不调用模型，直接给出“无可对照资料”。
- 过期是读取时按当前分支计算的标记，不回写报告文件。重演后回到原结果（Restore 到被检查的回合）时报告重新有效，因为它检查的叙述没有变。

**验证**

- Core `play-character-check.test.ts`（10 项）：材料只含被检查叙述与冻结角色块；临时角色标为无资料且不接受针对它的意见；整块省略并说明、全部省略记为 `omitted`、叙述过长拒绝；不在分支上的回合拒绝；伪造或改写引文、借用别的角色资料、未知类别与重复意见被丢弃；格式错误使整次检查失败；Restore / Retry 后过期；试演步骤在参与者视角不含隐藏段落与隐藏事实，且隐藏引文无法混入结果。
- Backend `play-character-check.test.ts`（7 项）：默认 SDK 调用经 HTTP 走通；模型请求不含其他回合、作者行动、裁判前缀或工作区路径；会话 revision、快照与 `turns/` 文件不变；格式错误、provider 失败、取消后没有报告文件；Retry / Restore 后 `stale`；导演视角报告不出现在参与者列表；无资料角色不调用模型；非法请求在调用模型前 400 / 404；试演步骤的两种视角与取消 attempt 后过期。
- Client `play-character-check.test.ts`（4 项）：请求体只有 `target` 与 `lens`；拒绝别的会话、目标、视角、带分数或多余字段的响应；指引文字不超过 500 字。
- Desktop `play-character-check-panel.test.ts`（10 项）：过期报告的重演入口禁用；“无可对照资料”文案；试演报告不显示观察笔记出口；只在已提交叙述和仍在使用的试演步骤上提供入口；重演指引框与试演重定向表单被预填且可改、不自动提交；切换视角先清空再加载；失败或取消不留报告。
- Desktop `play-character-check-sdk-journey.test.ts`：默认 SDK → HTTP/SSE → Desktop 的“检查 → 选一条意见 → 带意见重演”旅程，含伪造意见被丢弃并显示数量、重演后旧报告过期且入口禁用、两种视角互不显示的反例。
- 质量门禁结果见[任务索引](README.md)。

**没有验证的**

- 意见的文学质量，以及真实模型是否稳定按要求逐字摘抄（摘抄不准的意见会被丢弃，表现为丢弃数偏高）。由作者用真实模型验收。
- 没有在真实应用窗口里手动走一遍；界面行为由组件测试和 happy-dom 下的旅程测试覆盖。
- “记为观察笔记”的预填由组合函数实现，没有单独的界面旅程测试；保存仍走已有的观察笔记流程。
