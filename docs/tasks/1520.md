## Goal

沉浸推演的每个回合结束后，像 GalGame 一样给出几条方向不同的候选行动。作者可以直接选一条、改一改再选，或者写一条全新的行动。

## Existing Baseline

候选项的数据通路已经存在，但没有被当成一等体验：

- 结算 JSON 有 `suggestedActions`，宿主截断为最多 6 条字符串，随分支快照保存（[1120](1120.md)）。
- 裁判协议只在字段清单里列出这个字段名，没有要求数量、形式或彼此的差异，所以经常为空或几条大同小异。
- 文本工作台把它们显示成输入框上方的小标签，点击只填入输入框。
- 视觉小说演出在最后一拍显示选项，点击或按 `1`–`9` 立即提交，但不能修改，也不能在演出内输入自己的行动（[1360](1360.md)）。
- 行动类型（说 / 看 / 走 / 做 / 等）由界面用前缀正则从文本猜测，猜不中一律当作“做”。
- 结算可见性为 `playerUnknown` 的回合，候选项被清空。

代码入口：Core `play-referee-protocol.ts`、`play-turn-prompt.ts`（本轮回合要求）、`play-session.ts`（结算规范化）；Desktop `PlayComposer.vue`、`VisualNovelChoiceOverlay.vue`、`PlayWorkspace.vue`、`usePlayWorkspace.ts`（`inferActionKind`）。

## Scope

### 让每回合都有像样的候选项

- 在本轮回合要求中加入候选项规则：给出 3–4 条，站在参与者立场、可直接执行；彼此在做法或态度上明显不同；只写尝试，不预设结果；不得包含参与者不知道的信息。
- 规则放在每回合的消息尾部，不改冻结前缀，因此已有会话也生效，前缀缓存不受影响。
- 候选项不足 2 条时回合照常提交，界面显示“本回合没有候选项”并提供“生成候选项”，复用 [1450](1450.md) 的只读补充建议。不因候选项质量让整回合失败。
- 隐藏结算回合同样走“生成候选项”，生成材料只含参与者可见内容。

### 三种用法

- **直接选**：点击候选项或按数字键立即作为本回合行动提交。
- **改了再选**：每条候选项有“改一改”，把文本放进输入框并聚焦，作者修改后提交。
- **自己写**：候选项列表末尾固定一项“自己写”，聚焦空输入框。
- 文本工作台把候选项从小标签改为输入区上方带编号的选项列表；输入框未聚焦时支持 `1`–`9`。
- 视觉小说演出的选项浮层补上“改一改”与“自己写”，在演出内完成输入，不必返回工作台。
- “换一批”复用 1450 的补充建议，结果只临时显示。

### 行动类型不再靠猜

- 第一步：候选项文本采用固定的类型前缀约定，由宿主确定性解析为行动类型与等待时长；没有可识别前缀的旧候选项沿用原有的措辞推断，推断不出归为“做”，并在界面上可改。前缀不显示给作者。宿主不从措辞猜测等待时长。
- 第二步（单独决定）：把候选项升级为带类型、态度标签的结构化字段。这需要新增 artifact 与快照字段，先在 [PLAY_MODE_SPEC](../PLAY_MODE_SPEC.md) 明确合同再做。

## Constraints

- 第一步不改 session / artifact schema：`suggestedActions` 仍是最多 6 条字符串。
- 候选项只是输入辅助。提交的行动仍是普通的作者行动，走现有回合事务、Stop、插话、排队与 Retry，不新增提交通道。
- 作者选了哪条、是否改过，不进 turn artifact；如需记录只能写入消息日志（本轮未做）。
- 生成中、历史回看、结果未知或其他操作占用时，选择与数字键全部禁用；数字键在任何输入框聚焦时不触发。
- 候选项属于当前选中分支的快照；Restore、Retry 与分支切换后显示对应节点的候选项，不混入兄弟分支。
- 首版只覆盖沉浸推演；场景试演是导演逐步操作，不在范围。
- 不做好感度、选项锁定条件或预设的分支剧本树；候选项每回合由裁判根据当前局面给出。

## Done Criteria

- 受控模型给出 3–4 条候选项时，工作台与演出视图都能完成直接选、改了再选、自己写三条路径，提交的行动文本与类型正确。
- 候选项为空、只有 1 条或为隐藏结算时，界面给出“生成候选项”，回合本身已正常提交。
- 类型前缀解析有单元测试：五种类型、带时长的等待、无前缀回退、恶意或超长文本。
- 生成中或输入框聚焦时按数字键不会提交；误触后可用现有 Stop / Retry 恢复。
- 已有会话无需升级即可得到候选项规则；冻结前缀逐字节不变，有回归测试。
- 默认 SDK → HTTP/SSE → Desktop 的连续三回合旅程通过，三回合分别使用三种用法。候选项的文学质量与区分度由作者用真实模型另行验收。

## Dependencies And Sources

- 复用 1120、1350、1360。“换一批”与“生成候选项”依赖 [1450](1450.md) 的只读补充建议；可以先交付协议与界面部分，1450 完成后接上。
- 与 [1460](1460.md) 共用中文术语；会话启用 [1480](1480.md) 时，候选项只能引用参与者可见的原作节点。
