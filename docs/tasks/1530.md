## Goal

综漫作品里有哪几部原作、每个角色出自哪一部，写在作者可读的正式文件里，开局与采用都从这里读。

## Existing Baseline

[1500](1500.md) 的 `originWork` 只存在于 Play Launch Package；开局预填来自仍保留的 accepted 采纳记录，记录缺失、多个出处或手写角色时由作者每次手标。[FILESYSTEM_SPEC](../FILESYSTEM_SPEC.md) 的角色 `meta.yaml` 没有作品字段，工作区也没有作品清单。

代码入口：Core `play-launch.ts`、`reference-material-adoption.ts`、`reference-work.ts`；Desktop `components/play/launch/`。

## Scope

- 新增作品清单文件：每部作品有稳定 id、显示名、可选别名、对应的参考作品 id（零到多份）。
- 角色 `meta.yaml` 增加可选的作品归属；世界设定的归属写法在更新 FILESYSTEM_SPEC 时确定，默认写在对象自身。
- 原创人物可不标或标为原创，两种都不算缺失。
- 作品清单与归属的编辑入口；创建与修改生成 PendingAction。
- 从已绑定作品的 reference 采用并新建角色时，候选自带归属。
- Play 开局预填先读正式归属，没有时回退到 1500 现有的采纳记录。
- 项目体检：有两部以上作品时，列出尚无归属的角色（非阻断）。

## Constraints

- 实施前先更新 FILESYSTEM_SPEC；作品清单与扩展后的角色 meta 必须有完整 final validator（id 唯一、引用的作品存在、同 id 不得有不同显示名）。
- 一个角色只属于一部作品。不建集中的“路径 → 作品”索引。
- 宿主只做结构检查，不判断角色实际属于哪部作品，不自动补标。
- 没有作品清单的工作区行为、存储与请求不变；旧 Launch Package 照常读取。
- 预填仍需作者在开局向导中确认；Launch Package 的字段合同不变。

## Done Criteria

- 两部作品、各两名角色的合成工作区：登记作品 → 标注归属 → Accept 后，开局来源步骤自动带出归属，无需采纳记录。
- 删除采纳记录后预填结果不变。
- 引用不存在的作品、重复 id、同 id 不同显示名在候选校验阶段被拒绝。
- 从已绑定 reference 采用的新角色在 diff 中可见归属。
- 无作品清单的工作区有回归证明无变化。
- 默认 SDK → HTTP → Desktop 的“登记作品 → 标注角色 → Accept → 开局预填”旅程通过。
