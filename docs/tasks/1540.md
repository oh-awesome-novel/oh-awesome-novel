## Goal

从第二部参考作品采用人物时，预检指出可能已存在的角色，作者裁定是同一个人还是另一个人，再合并到已有角色或另建。

## Existing Baseline

[1410](1410.md) 的批次预检遇到已存在的角色只给“将新增文件”的说明，作者可手改目标路径；跨 reference 合并与同名消歧在 1410 明确不做。[1220](1220.md) 的采用链路已支持对已有文件的 update 候选。

代码入口：Core `reference-material-adoption.ts`（`preflightReferenceMaterialAdoption`、目标提示）；Desktop `ReferenceMaterialEntrySelector`、`ReferenceMaterialAdoptionPreview`。

## Scope

- 预检增加“可能是已有人物”：来料人物名与已有角色的显示名、别名在规范化（Unicode 兼容归一、大小写、空白）后完全相等时命中。
- 每个命中由作者选择：同一人物（目标改为已有角色目录）、不同人物（另建，建议 id 带作品后缀）、本次不处理（移出这一批）。未作选择时不能生成预览。
- 作者可手动把未命中的来料人物指到某个已有角色。
- 裁定前的只读对照：已有角色文件与来料条目并排。
- 人物对应记录：哪部 reference 的哪个人物对应这个角色，写在角色自身的正式文件里，随同一次采用的候选一起审批；再次从同一 reference 采用时用作默认目标。
- 关系材料中的对方人物按人物对应解析为角色 id；解析不了的逐条列为未解决，由作者指定或移出。

## Constraints

- 匹配是确定性的；不做模糊匹配、简繁或译名归并，不调用模型判断同一性。
- 每次生成仍只消费一份 reference；合并是既有采用链路上的 update 候选，不新增写入路径。
- 不自动消解设定冲突：两边说法不一时都进入候选，由作者在 diff 中取舍。
- 模型只收到选中的来料条目与目标已有文件，不收到其他 reference 的原文或未选条目。
- 实施前核对材料条目标识在重新拆解后是否稳定；不稳定时人物对应以人物名为准，材料变更后要求重新确认。
- 人物对应的字段格式先写入 [FILESYSTEM_SPEC](../FILESYSTEM_SPEC.md) 并有完整 validator。

## Done Criteria

- 两份 reference 含同名人物的合成工作区：先采用 A，再采用 B 时预检给出命中，三种选择各有生产链回归。
- 选“同一人物”时候选只修改或新增已有角色目录下的文件；选“不同人物”时不触碰已有角色。
- 接受后再次从 B 采用，预检直接给出已记录的目标。
- 关系材料中无法解析的人物被列出，预览在解决前不可生成。
- 预检与对照期间模型零调用；Accept 前正式文件不变。
- 走真实后端的“采用 A → 采用 B → 裁定 → diff → Accept”Desktop 旅程通过。

## Implementation Notes

已实现（2026-11-13），先补齐 1410 的默认 SDK → HTTP → Desktop 筛选、重映射、预检、diff、Accept 旅程，再接人物裁定。

- 已核对材料 ID：含 run/unit 身份，重新拆解后不稳定；正式对应采用 `referenceId + 规范化人物名`，并绑定条目内容指纹。Unicode NFKC、小写、空白归一后精确匹配显示名/别名；新材料变化要求重新确认，不做模糊或模型身份判断。
- 预检返回只读文件对照、已有对应及新人物 ID 建议；作者可选同一人物、不同人物、移出，或手选已有角色。默认 SDK 与真实后端的 Desktop 旅程分别覆盖三种选择、Accept 前不落盘、diff 目标范围及再次采用的默认对应。
- 对应记录与新角色归属由宿主生成，随既有采用候选审批；模型不能覆盖这些字段。被模型跳过的条目不写入新对应。模型只接收所选条目和目标正文；合并必须保留原正文及关系字段，冲突追加后供作者在 diff 中审阅。
- 现有关系材料只有自然语言，没有可直接解析的结构化端点。作者先列出对方人物名，宿主按当前来源的有效对应解析；缺失对应可显式指定角色 ID。未解决的条目阻断预览，生成结果只能引用已确认或原有关系 ID。
- Core 覆盖重新拆解后的条目 ID 变化、材料失效与无清单行为；Backend 覆盖预检零模型调用、关系解析、重启恢复、基线变化后拒绝 Accept；Tools 覆盖原有说法保留和非法覆盖拒绝。

受控模型验证协议、接线与写入边界；真实模型的改写质量仍由作者审阅。没有作品清单、人物对应或显式裁定的旧请求仍走原有采用行为。
