# 1550 Reference Material Revision Compare And Re-adoption

> Status: Planned
> Priority: P1
> Updated: 2026-11-12

## Related Plans

- [综漫多来源素材规划 · 3.3](../plans/CROSSOVER_SOURCE_MATERIAL_PLAN_2026-11-12.md#33-参考材料版本比较与重新采用1550)

## Goal

参考作品重新拆解后，作者能看到材料改了什么、哪些已采用的角色和设定依据的条目变了，并能带着这些条目重新采用或把材料退回旧版本。

## Existing Baseline

采用预览绑定材料的 `manifestRevision`，来源漂移会使旧预览失效（[1220](1220.md)）。[1410](1410.md) 的采用记录从 PendingAction 的 origin、状态和保存的预览重建，但不与当前材料版本比较。[1440](1440.md) 已有“确定依赖 / 可能相关 / 证据不足”的影响分级。

代码入口：Core `reference-material-adoption.ts`、`reference-deconstruction-publication.ts`；Backend 采用记录接口；Desktop 材料采纳工作台。

## Scope

- 同一份 reference 两次已发布材料的条目级比较：新增、删除、内容变化。
- 受影响清单：采用过且来源条目此后变化的正式对象；采用记录缺失的归为证据不足。
- 每个受影响对象的显式入口：打开文件；带着相关条目与原目标进入 1410 工作台重新采用。
- 回滚已发布材料到所选历史版本：确定性 producer 生成候选，预览后 Accept。

## Constraints

- 版本来源是 Git 历史中的已发布材料；没有提交历史或中间版本未提交时显示无法比较及原因。
- 比较默认不调用模型；只比较已发布材料，不比较拆解中间产物。
- 不自动重新采用，不因材料变化改动正式角色或设定。
- 回滚只作用于参考材料本身，不连带撤销由它采用出去的正式内容；关闭自动提交时不 commit / sync。
- 不新建版本数据库。条目对应关系无法确定时显示为删除加新增，不猜测。

## Done Criteria

- 合成 reference 发布两版后，新增 / 删除 / 变化条目与预期一致。
- 采用过变化条目的角色出现在受影响清单；删除采用记录后同一对象显示为证据不足。
- 从清单进入工作台时选择与目标已预填，后续仍经预检、预览和 Accept。
- 回滚候选 Accept 后已发布材料与所选版本逐字节一致；Reject 后无变化。
- 无 Git 历史的工作区给出明确说明。
- 走真实后端的“重新发布 → 比较 → 重新采用”Desktop 旅程通过。
