## Goal

同一个 Play 会话有两种呈现：沉浸的舞台模式（只看对话、立绘和选项）与完整的专业模式（现有工作台），随时切换，草稿与进行中的回合不丢。

## Existing Baseline

[1360](1360.md) P3 的 `VisualNovelStage` 由 `PlayWorkspace.vue` 的 `visualNovelOpen` 开关嵌在推演舞台中，下方的 `PlayComposer` 与各类面板常驻；舞台高度受工作台布局限制。v5 场景排练另有只读“视觉小说回放”按钮。会话与回合状态大多已在 `usePlayTurnStream`、`usePlayWorkspace` 等 composable 中。

代码入口：Desktop `components/play/PlayWorkspace.vue`、`VisualNovelStage.vue`、`PlayComposer.vue`、`composables/usePlayTurnStream.ts`、`usePlayWorkspace.ts`。

## Scope

- 把 `PlayWorkspace.vue` 拆成共享会话状态 + 舞台外壳 + 专业外壳；专业外壳保持现有全部能力。
- 舞台外壳：占满 Play 主区域；背景、立绘、对话框、选项、“改一改 / 自己写”；停止、重演、存档点跳转的简化入口；回到专业模式的按钮。
- 行动输入整合进舞台，不再依赖下方 `PlayComposer`；插话 / 排队以舞台内小入口保留。
- 舞台模式固定玩家视角：进入时关闭导演视角，舞台内不提供切换。
- 模式偏好按会话记在应用界面偏好中；从会话列表或外部请求打开会话时按偏好进入。
- v5 场景排练在舞台模式只读回放，不出现输入入口。

## Constraints

- 不改 Play 协议、会话存储与后端接口；打开与切换模式期间模型零调用。
- 输入草稿、进行中回合（含 provisional 草稿）、选中分支、选项状态属于共享状态，切换不丢、不重复提交。
- 舞台模式下不得出现 `playerUnknown` 信息或导演视角数据。
- 模式偏好不写入小说工作区文件。
- 保持现有不变量：草稿未保存前不可选、回看与切分支时清空、Restore / Retry 使用各自冻结的 `StageSnapshot`。

## Done Criteria

- 回合进行中在两种模式间来回切换，草稿输入、provisional 文本与选项保持一致，回合只提交一次。
- 舞台模式中选项、改一改、自己写、停止、重演可用，键盘全程可操作。
- 导演视角开启时进入舞台模式会被关闭；舞台中不渲染隐藏事件。
- v5 会话在舞台模式只读。
- 现有 Play Desktop UI 测试在专业模式下全部通过。

## Dependencies And Sources

- 复用 1360（视觉小说舞台）、1350（插话与排队）、1520（回合候选项）、1190（导演视角）。
- 后续 [1590](1590.md)、[1610](1610.md)、[1620](1620.md) 建立在舞台外壳上。

## Implementation Notes

2026-11-12 交付，只改 Desktop UI。

- `PlayWorkspace.vue` 现在是容器：创建一次 `usePlayWorkspace`（`PlayWorkspaceState`），整体交给 `PlayStageShell.vue` 与 `PlayWorkbenchShell.vue`。草稿、行动类型、等待时长、进行中回合、排队、选中分支与候选项都在共享状态里。
- 专业外壳是原工作台原样搬出；首次显示时挂载，切到舞台后只隐藏不卸载，所以面板里未完成的表单和进行中的检查不受切换影响，切换本身不发任何请求。原先嵌在中栏的演出开关与 v5“视觉小说回放”按钮改为进入舞台模式。
- 舞台外壳占满会话列表右侧的主区域。`PlayStageActionBar.vue` 提供行动输入（行动类型、等待时长）、回合进行中的“排队 / 插话”、停止、重演上一回合与存档点下拉跳转。“改一改”把选项放进共享草稿，“自己写”保留已有草稿；没有写明时长的等待选项在舞台内补时长，不再跳回工作台。
- 舞台模式固定玩家视角：处于舞台模式时导演视角保持关闭（v5 的排练视角同时切回玩家），隐藏着的专业外壳因此也只持有玩家视角的数据；切回专业模式后不会自动恢复导演视角。
- v5 场景排练在舞台模式只读回放，没有选项和输入。
- 模式偏好按“工作区路径 + 会话”存在 `localStorage` 的 `oan:play:presentation-mode:<工作区路径>`，最多记 200 个会话。没有记录的会话默认专业模式；外部请求（如工坊交接）打开且没有记录的会话进入舞台模式，延续原先交接后直接打开演出的行为。没有数据因本任务失效。
- 键盘：舞台上的其他按钮不再被空格 / 回车的“下一句”抢走；输入框 Cmd/Ctrl+Enter 发送或排队、Alt+Enter 插话、Esc 收起并把焦点还给舞台。

验证：新增 `__test__/desktop-ui/src/play-stage-mode.test.ts`（10 项：偏好读写、回合进行中来回切换只提交一次、舞台内键盘走完选项 / 改一改 / 自己写、排队与插话、停止、重演与存档点跳转、导演视角关闭与隐藏内容不出现、交接会话按偏好进入、v5 只读）。desktop-ui 全量 93 个文件 443 项按 `test:ci` 的单 worker 配置通过；并行运行时 `play-worldline-compare-journey` 的真实 HTTP 用例偶发超时，单独重跑通过。另在本地 Web UI 上用示例工作区的临时副本看过两种模式的布局与草稿互通。没有用真实模型在舞台模式下推进回合，演出观感由作者另行验收。
