## Goal

角色卡里可以写多张立绘，每张有文字描述和可选的图片，并可指定名字牌颜色；舞台直接显示图片资源目录里的原图，不做实时生图。

## Existing Baseline

`characters/<id>/roster-profile.yaml` 的 `looks` 只有一张 `refImagePath`，以及为未来生图预留的 booru tags / LoRA 字段；创建会话时立绘按 [PLAY_LOCAL_SCENERY](../PLAY_LOCAL_SCENERY.md) 冻结为 data URL。名册只由 Forge 生成，没有编辑表单。Tavern 导入只取 PNG 中的 JSON。图片资源目录由 [1630](1630.md) 定义。

代码入口：Core `character-roster.ts`、`character-roster-store.ts`、`play-session.ts`；Backend `forge.ts`；Tools `final-document-validator.ts`；Desktop 角色页面与 `VisualNovelStage.vue`。

## Scope

- `roster-profile.yaml` 增加可选 `portraits: { default, items[] }`；每项含 `id`、`label`、`description`，可选 `usage`、`image`、`prompt`（字段合同见关联计划）。
- 生图提示词：`prompt: { positive, negative?, useCharacterTags? }` 为纯文本，可在表单中编辑保存；同时接受可选的 `generation` 来源记录（由 [1650](1650.md) 写入，字段见 [立绘生图规划 · 3.1](../plans/PORTRAIT_IMAGE_GENERATION_PLAN_2026-11-12.md#31-立绘生图提示词字段扩展-1600)），本任务只做读取、校验与展示。
- `looks` 增加可选 `nameColor`（`#RRGGBB`），在同一张表单里编辑；舞台名字牌优先使用它。
- 兼容：没有 `portraits` 时，`looks.refImagePath` 视为唯一默认立绘；两者并存时以 `portraits` 为准，表单提示迁移。
- `image` 指向图片资源目录（默认 `assets/portraits/<角色 id>/`）里的文件；名册里只有路径。
- 角色页“立绘”表单：列出资源目录里该角色已有的图片供选择，可用 1630 的“导入图片”添加；编辑标签、描述、用途与默认项；保存生成确定性 CandidateChangeSet → PendingAction，候选里只有 YAML 文本。
- Forge 生成角色时可起草立绘描述（不含图片），随现有 Forge 审批写入。
- 会话创建时记录每张立绘的描述、路径与内容哈希，不把图片字节存进会话；每角色最多 8 张，超出跳过并提示。
- 舞台通过 1630 的读取接口显示原图，不缩放、不转码。文件缺失或损坏时显示名字剪影并说明原因；内容与开局时的哈希不同，照常显示并提示“开局后已更换”。
- 舞台显示默认立绘；无图立绘显示名字剪影，可查看描述。
- 更新 FILESYSTEM_SPEC、PLAY_LOCAL_SCENERY 与 final validator。

## Constraints

- 不在本任务中生图、抠图或调用 TTS，不修改任何图片文件；图片内容不进入候选、审批与 Git。
- 名册校验只检查 `image` 的路径形状：工作区相对、位于图片资源目录内、扩展名为 PNG / JPEG / WebP、不含隐藏段与越界；不要求文件存在。文件的签名、大小与符号链接检查在读取时由 1630 完成。
- `id` 1–32 位 ASCII 字母数字、`_`、`-`，角色内唯一；`default` 必须指向存在的项；`label` ≤ 16 字，`description` 有上限。
- 已有会话保留创建时记录的立绘清单、描述与路径；修改名册只影响新会话。图片文件本身不随会话保存。
- 既有 `looks.refImagePath` 的读取方式与 256 KiB 冻结保持不变。
- 本任务不改变 Play 冻结前缀与回合请求，写作上下文也不因此多读内容；立绘描述进入冻结前缀只由 [1610](1610.md) 在启用演出标注的会话中完成。
- 没有 `portraits` 与 `nameColor` 的工作区行为、存储与请求不变。

## Done Criteria

- 合成角色配三张立绘（其中一张无图）：表单编辑 → diff 审批 → Accept 后文件内容正确；新会话舞台显示默认图，无图项显示剪影与描述。
- 资源目录之外的路径、越界路径、重复 id、`default` 指向不存在项、格式不对的 `nameColor` 在候选校验阶段被拒绝。
- 带立绘的名册与不带的名册，新会话的冻结前缀与首回合请求逐字节相同。
- `image` 指向不存在的文件时候选仍可通过校验，表单给出提醒；舞台显示剪影与原因。
- 一张数 MiB 的原图在舞台上按原图显示；会话存储中不出现图片字节。
- 开局后替换图片文件，舞台显示新图并提示已更换；删除后显示剪影。
- 每角色超过 8 张时创建成功并提示被跳过的项。
- 只有 `refImagePath` 的旧名册与旧会话有回归证明无变化。
- Forge 起草的立绘描述出现在审批 diff 中，且不含 `image`。
- 默认 SDK → HTTP → Desktop 的“编辑立绘 → Accept → 新开会话 → 舞台显示”旅程通过。

## Dependencies And Sources

- 依赖 [1630](1630.md) 的图片资源目录与读取接口。复用 1360（名册与舞台）、1460（表单生成 PendingAction 的做法）。
- 后续 [1610](1610.md) 用立绘 `id` 与描述做标注。

## Implementation Notes

2026-11-13 交付。

已交付：

- **名册字段（Core `character-roster.ts`）**：可选 `portraits: { default, items[] }` 与 `looks.nameColor`，字段合同写入 [FILESYSTEM_SPEC · Character Format](../FILESYSTEM_SPEC.md#character-format)。校验在 `normalizeRosterCharacter` 里，final validator、会话读取与表单保存共用；`image` 只查路径形状，不要求文件存在。
- **会话记录（Core `character-roster-store.ts`）**：创建会话时写 `metadataExtensions.characterPortraitSets`，默认项排第一，每角色最多 8 张，其余的 `id` 记在 `skipped`；有图且文件可读时记 SHA-256，不存图片字节。有立绘集的角色不再把 `looks.refImagePath` 的图片存进会话。没有立绘集的会话不写这个键。
- **保存（Tools `roster-portraits-change-producer.ts`，Backend `character-portraits.ts`）**：`GET /api/workspace/characters/:id/portraits` 读表单，`POST …/portraits/propose` 生成确定性候选并建 PendingAction。候选只改 `characters/<id>/roster-profile.yaml`，只动 `portraits` 与 `looks.nameColor` 两处，作者的注释和其余内容保持原样；没有新增 PendingAction 的 origin 类型。名册文件不存在、文件在载入后被改过、工作区已切换、没有实际改动时分别拒绝并说明原因。
- **Client**：`getCharacterPortraits`、`proposeCharacterPortraits`、`readPlaySessionPortraitSets`，返回值校验归属与形状。
- **表单（Desktop `CharacterPortraitForm.vue`）**：放在 Play 顶栏“图片资源”面板里选中角色之后（目前没有独立的角色页）。可增删立绘，编辑名称、编号、描述、适用场合、提示词与反向提示词，从该角色资源目录的图片里选图，指定默认项和名字牌颜色。图片读不到时给提醒但照常保存；只有 `refImagePath` 的角色会看到迁移说明。`generation` 只保留不编辑，立绘改指向别的图片时丢弃。
- **舞台（`VisualNovelStage.vue`、`ImageAssetView.vue`、`PlayStageShell.vue`）**：角色有立绘集时显示默认项，图片经 1630 的读取接口取原文件；内容哈希与开局记录不同时标“开局后已更换”；缺失、损坏或无图时显示剪影，描述在悬停提示里，原因写在名字下方；有立绘被跳过时舞台给一条可关闭的提示。名字牌颜色在 1590 已接好，这里补上了写入入口。
- **Forge**：计划里的角色可带可选 `portraits`（`id / label / description / usage`，最多 4 项），随现有 Forge 审批写入名册，不含 `image`；格式不对的条目被丢弃而不让整份计划失败。没有该字段的计划输出不变。
- **模型边界**：Play 冻结前缀与回合请求不读名册的这两项。写作设定来源里选了 `roster-profile.yaml` 时，`portraits` 与 `looks.nameColor` 会先被去掉（Tools `stripRosterStageFields`），没有这两项的文件逐字节不变。

与原定范围的差异：

- 表单在“图片资源”面板里，不在角色页，因为目前没有角色页。
- 舞台把图片按舞台现有的立绘尺寸等比显示（文件本身不缩放、不转码、不另存）。
- 舞台只显示默认立绘；按剧情切换立绘属于 [1610](1610.md)。

会失效的数据：无。已有会话没有 `characterPortraitSets`，舞台沿用原来的显示。
