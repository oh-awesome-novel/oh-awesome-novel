## Goal

角色卡里可以写多张立绘，每张有文字描述和可选的图片，并可指定名字牌颜色；舞台使用作者预先准备好的图片，不做实时生图。

## Existing Baseline

`characters/<id>/roster-profile.yaml` 的 `looks` 只有一张 `refImagePath`，以及为未来生图预留的 booru tags / LoRA 字段；创建会话时立绘按 [PLAY_LOCAL_SCENERY](../PLAY_LOCAL_SCENERY.md) 冻结为 data URL。名册只由 Forge 生成，没有编辑表单。Tavern 导入只取 PNG 中的 JSON。Sandbox Change Engine 只处理 UTF-8 文本。

代码入口：Core `character-roster.ts`、`character-roster-store.ts`、`play-session.ts`；Backend `forge.ts`；Tools `final-document-validator.ts`；Desktop 角色页面与 `VisualNovelStage.vue`。

## Scope

- `roster-profile.yaml` 增加可选 `portraits: { default, items[] }`；每项含 `id`、`label`、`description`，可选 `usage`、`image`、`prompt`（字段合同见关联计划）。
- 生图提示词：`prompt: { positive, negative?, useCharacterTags? }` 为纯文本，可在表单中编辑保存；同时接受可选的 `generation` 来源记录（由 [1650](1650.md) 写入，字段见 [立绘生图规划 · 3.1](../plans/PORTRAIT_IMAGE_GENERATION_PLAN_2026-11-12.md#31-立绘生图提示词字段扩展-1600)），本任务只做读取、校验与展示。
- `looks` 增加可选 `nameColor`（`#RRGGBB`），在同一张表单里编辑；舞台名字牌优先使用它。
- 兼容：没有 `portraits` 时，`looks.refImagePath` 视为唯一默认立绘；两者并存时以 `portraits` 为准，表单提示迁移。
- 角色页“立绘”表单：列出该角色目录下已有的 PNG / JPEG / WebP 供选择，编辑标签、描述、用途与默认项；保存生成确定性 CandidateChangeSet → PendingAction。
- Forge 生成角色时可起草立绘描述（不含图片），随现有 Forge 审批写入。
- 会话创建冻结立绘描述与图片：每角色最多 8 张、单张 256 KiB，全会话立绘合计默认不超过 8 MiB（实施计划按 [1260](1260.md) 的存储成本实测调整）；超出跳过并提示。
- 舞台显示默认立绘；无图立绘显示名字剪影，可查看描述。
- 更新 FILESYSTEM_SPEC、PLAY_LOCAL_SCENERY 与 final validator。

## Constraints

- 不在本任务中生图、抠图或调用 TTS；系统不创建、复制或修改任何图片文件，图片由作者自己放入工作区（生图与经审批的图片写入见 [1630](1630.md)–[1650](1650.md)）。
- `image` 路径规则与现有 `refImagePath` 相同：工作区相对、仅 PNG / JPEG / WebP、校验栅格签名、拒绝符号链接、隐藏路径与越界。
- `id` 1–32 位 ASCII 字母数字、`_`、`-`，角色内唯一；`default` 必须指向存在的项；`label` ≤ 16 字，`description` 有上限。
- 已有会话保留创建时冻结的字节；修改名册只影响新会话。
- 本任务不改变 Play 冻结前缀与回合请求，写作上下文也不因此多读内容；立绘描述进入冻结前缀只由 [1610](1610.md) 在启用演出标注的会话中完成。
- 没有 `portraits` 与 `nameColor` 的工作区行为、存储与请求不变。

## Done Criteria

- 合成角色配三张立绘（其中一张无图）：表单编辑 → diff 审批 → Accept 后文件内容正确；新会话舞台显示默认图，无图项显示剪影与描述。
- 引用不存在的图片、越界路径、重复 id、`default` 指向不存在项、格式不对的 `nameColor` 在候选校验阶段被拒绝。
- 带立绘的名册与不带的名册，新会话的冻结前缀与首回合请求逐字节相同。
- 超出单张 / 每角色 / 会话总量预算时创建成功并提示被跳过的项。
- 只有 `refImagePath` 的旧名册与旧会话有回归证明无变化。
- Forge 起草的立绘描述出现在审批 diff 中，且不含 `image`。
- 默认 SDK → HTTP → Desktop 的“编辑立绘 → Accept → 新开会话 → 舞台显示”旅程通过。
