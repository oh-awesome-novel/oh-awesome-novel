## Goal

裁判写对白时直接标出谁在说、用哪张立绘；舞台按标注显示名字牌和立绘，不再依赖推断。

## Existing Baseline

`parseTextBeats` / `inferSpeaker` 用正则、名册别名、行当称谓和排除表推断说话人，多人对话、省略主语或代词开头时容易错配。`StageSnapshot.beats` 只有 `speaker`、`text`、`isDialogue`。冻结前缀与 settlement 协议没有演出相关规则。`canonBeats`（[1480](1480.md)）已建立“创建时决定、未启用逐字节不变”的可选扩展做法。

代码入口：Core `text-speaker-parser.ts`、`play-referee-protocol.ts`、`play-turn-prompt.ts`、`play-turn-artifact.ts`、`play-session.ts`；Desktop `VisualNovelStage.vue`。

## Scope

- 会话创建时可选“演出标注”，保留键暂名 `vnStageMarkup: { version: 1 }`；旧会话不能追加启用。
- 启用后冻结前缀追加：标注规则，以及会话名册中角色的 `id`、显示名与立绘 `id / label / description / usage`（来自 [1600](1600.md) 冻结的数据）。
- 对白行格式：`@<角色 id 或名册名/别名>[可选立绘 id] 台词`；旁白不加标记。
- 宿主在回合提交时解析标记：写入 `StageSnapshot.beats[].speakerId`、`portraitId`、`source: 'markup' | 'inferred'`；transcript 正文存剥离标记后的纯文本。
- 降级：未知角色回落启发式推断，未知立绘回落默认立绘，格式错乱行按旁白处理；每类降级在上下文追踪记一条提示，回合不失败。
- 专业模式可在正文旁显示说话人 / 立绘小标签。
- 模型历史：启用会话在组装后续回合的历史时，由宿主按已保存的 `speakerId / portraitId` 把标记加回 `source: 'markup'` 的对白行，使模型看到的历史与规则一致；不另存带标记的正文。
- 草稿：专业模式的流式草稿在显示前剥离标记（舞台模式由 [1620](1620.md) 处理）。

## Constraints

- 标记只描述说话人与立绘，不承载事实、状态或隐藏信息；`isSafePlayNarrativePrefix` 检查继续生效；settlement 协议不变。
- 未启用会话的冻结前缀、回合请求与存储与基线逐字节一致。
- `StageSnapshot` 新字段可选；旧快照照常读取。
- 写作交接（1420）、角色贴合度引文（1510）、阶段归档（1400）只看到剥离后的正文。
- 不新增事实域，不写正式文件。
- 实施前核对现有历史组装路径，确认重新加回标记不改变冻结前缀的缓存布局；做不到时在实施计划中另定方案并回写本任务。

## Done Criteria

- 启用会话中，三人对白（含代词开头与连续引号）的快照说话人与立绘正确，transcript 不含标记。
- 未知角色、未知立绘、格式错乱三类输入不导致回合失败，降级结果与追踪提示符合预期。
- 未启用会话的冻结前缀与请求在测试中逐字节等于基线。
- 1510 引文核对与 1420 推演转章节在启用会话上通过。
- Retry / Restore / 阶段归档后快照中的标注字段保持各自节点的值。
- 启用会话第二回合起，发给模型的历史对白行带标记；任何模式的草稿与已保存正文都不出现原始标记。

## Implementation Notes

2026-11-13 交付，按 [实施计划](../superpowers/plans/2026-11-13-play-stage-markup.md) 实现。

- 开关是创建请求里的 `stageMarkup: true`，宿主写入 `metadataExtensions.vnStageMarkup: { version: 1 }`；只对沉浸推演开放，没有事后增删的接口。两个开局表单各有一个勾选项。
- Core `play-stage-markup.ts` 负责前缀块、提交时解析、草稿剥离与历史还原；`StageSnapshot.beats[]` 新增可选的 `speakerId / portraitId / source`。
- 历史组装路径核对结果：冻结前缀只生成一次，历史在其后且只依赖已提交回合，加回标记后仍是只追加的，窗口推进规则不变；Backend 测试断言下一回合的历史以上一回合的历史为前缀。
- 三类降级写入上下文追踪的 `stageMarkupNotices`，专业模式“回合上下文”里显示。
- 专业模式在裁判消息下列出标注过的“说话人 · 立绘 id”。

与任务原文的出入：

- 角色贴合度检查原先只按名字在正文里找在场角色。标注后说话人名字可能不在正文里，所以现在也把快照里被标注的 `speakerId` 算作在场；送检和核对引文用的仍是干净正文。模型在送检文本里看不到每句是谁说的，这一点没有处理。
- 没有立绘集的角色被标了立绘 id 时，不记立绘（没有默认可回落），仍记一条提示。
- 标记只在行首识别；一行里写了第二个标记时，后一个会留在正文里。

会失效的数据：无。

验证：

- 新增测试：Core 8 项（前缀、三人对白、三类降级与追踪、未启用时存储不变、历史还原、Retry / Restore / 阶段归档、草稿剥离、快照校验）；Backend 3 项（创建与基线对比、草稿 / 保存 / 追踪 / 历史、1510 在标注行上取引文）外加 1420 在启用会话上生成并 Accept 一章；Client 与 Desktop 的用例见 [1620](1620.md)。
- 全量 build、lint、typecheck、docs:check 通过；`--maxWorkers=1` 下 core 727、runtime 31、tools 340、agent 157、backend 347、client 233、desktop-ui 486 项全部通过。
- 在本地 Web UI 上用脚本化的裁判（`streamPlayTurn` 按 0.9 秒一段吐出带标记的回复）实测了一回合：舞台发出的请求带 `presentation: 'stage'`；首句在 settlement 到达前约 5 秒开始演出，其后逐句播放；带标记的行显示正确的名字牌，米拉从默认立绘换成“生气”；名册外的“路人”一行没有名字牌；提交后舞台停在原句、不重播整段。没有接真实模型验证遵循率。
