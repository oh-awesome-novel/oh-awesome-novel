## Goal

舞台模式下，裁判写完第一句就开始演出，后续句子排队打字；专业模式保持现有的 fail-closed 行为。

## Existing Baseline

Backend `streamPlayRefereeText` 每回合创建一次 `createPlayNarrativeStreamFilter`：settlement 围栏（或任意围栏）出现前叙事全部隔离，出现后才把前缀一次性作为 provisional 文本放出；省略围栏或输出裸 JSON 的回复不会出现在界面上。舞台拿到的是整段草稿。

代码入口：Core `play-narrative-stream.ts`；Backend `index.ts` `streamPlayRefereeText` 与回合请求类型；Client 回合请求；Desktop `usePlayTurnStream.ts`、`VisualNovelStage.vue`、`VisualNovelTextBox.vue`。

## Scope

- 回合请求增加可选 `presentation: 'stage' | 'workbench'`，缺省为 `workbench`；后端按值选择过滤器，请求发出时固定，中途切换模式只改显示。
- 新增整句放行过滤器：围栏前只放出已完整结束（句末标点或换行）且通过 `isSafePlayNarrativePrefix` 的句子；遇到可疑片段立即停止放行，余下内容走现有隔离路径。
- 启用 [1610](1610.md) 标注时，标记行整行到齐才放行，放行文本已剥离标记并带说话人 / 立绘。
- 前端显示队列：按句排队，以 1590 的字速设置逐句播放，与网络到达节奏解耦；新句不打断当前句。
- 放出内容始终标为“草稿 · 尚未保存”；最终解析失败、停止、重演时整体撤下。

## Constraints

- `workbench` 与缺省请求的行为、事件序列与现在一致。
- 结构化片段（花括号、围栏、settlement 字段名）不得出现在任何草稿中，即使之后出现合法围栏。
- 最终提交仍由现有解析器完成；放行文本与最终 transcript 不一致时以最终结果为准并替换草稿。
- 不改变 settlement 协议与回合事务。
- 这是对现有 fail-closed 流式边界的有意放宽，只在 `stage` 请求上生效；放宽后哪些保证仍成立见关联计划 3.5。实施时同步更新 `play-narrative-stream.ts` 的说明与 [PLAY_MODE_SPEC](../PLAY_MODE_SPEC.md)。
- 逐句检查只针对结构化片段，不判断一句普通叙述是否泄露了应隐藏的信息；该风险与现有整段放出的路径相同，不在本任务内解决。

## Done Criteria

- 舞台模式下首句在 settlement 到达前上屏；专业模式下首句仍在围栏后出现。
- 在句中、句末、围栏前分别注入 JSON / 围栏片段的回复：可疑片段之前的整句可见，片段本身与之后内容不可见。
- 解析失败、停止、重演后草稿撤下，界面与现在一致。
- 回合中途切换模式不改变该回合的过滤方式。
- 显示队列在快速到达与慢速到达两种节奏下逐句播放，不跳句、不重复。

## Implementation Notes

2026-11-13 交付，按 [实施计划](../superpowers/plans/2026-11-13-play-stage-sentence-streaming.md) 实现。

- 回合请求与重演请求接受 `presentation`；Desktop 只在舞台模式发 `'stage'`，专业模式的请求体与以前相同。
- Core `createPlaySentenceStreamFilter`：围栏前按整句放行，每句连同刚放出的 256 个字符一起检查；不通过即关闭，之后不再放行。`play-narrative-stream.ts` 的说明与 PLAY_MODE_SPEC 已写明放宽后哪些保证仍成立。
- 启用 1610 的会话里，`@` 开头的行整行到齐才放行，放出前剥离标记，`play.narrative.delta` 带 `markup`。
- 舞台草稿队列：当前句显示完且后面有句子时自动前进，没有就停在最新一句；开着打字效果时句间停顿 `min(自动间隔, 600ms)`，关着时用“自动间隔 + 句长”。

与任务原文的出入：

- 草稿队列对舞台上的任何草稿都生效，包括从专业模式发出、中途切到舞台的回合（那种情况下草稿在围栏后一次到齐，然后逐句播放）。
- 一句话写完的判定需要看到它后面的下一个字符，所以每句比模型写出它晚一个分片上屏。
- 提交时正式回合替换草稿，舞台停在原来那一句，但这一句会重新打一遍字（1590 起就是这样，本任务没有改）。

会失效的数据：无。

验证：

- 新增测试：Core 8 项（首句先于围栏、任意分片位置与 fail-closed 过滤器结果一致、句中 / 句末 / 字段名三种注入、各种围栏写法、无围栏回复、标注行整行放行、reset）；Backend 3 项（stage 与 workbench 的事件对比及非法值、注入片段后回合失败且不提交、标注行与重演）；Client 3 项；Desktop 10 项（请求字段在发出时固定、标注行随草稿清空、快 / 慢两种到达节奏不跳句不重复、新句不打断当前句、失败后撤下、舞台按标注换名字牌与立绘、专业模式标签与追踪文案、开局勾选项）。
- 全量 build、lint、typecheck、docs:check 通过；`--maxWorkers=1` 下 core 727、runtime 31、tools 340、agent 157、backend 347、client 233、desktop-ui 486 项全部通过。
