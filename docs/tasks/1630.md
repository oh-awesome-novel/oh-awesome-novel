# 1630 Approved Binary Image Changes

> Status: Planned
> Priority: P0
> Updated: 2026-11-12

## Related Plans

- [角色立绘生图模块规划 · 3.2](../plans/PORTRAIT_IMAGE_GENERATION_PLAN_2026-11-12.md#32-经审批的图片文件变更1630)

## Goal

图片文件也能通过 CandidateChangeSet → PendingAction → Git diff 审批写入工作区，供生图采纳等确定性流程使用。

## Existing Baseline

[SANDBOX_CHANGE_ENGINE](../SANDBOX_CHANGE_ENGINE.md) 只接受无 NUL 的 UTF-8 文本；create 固定 mode `0o644`；draft、PendingAction 与 recovery 数据位于 `.workspace/change-engine/v1`。materializer 已有 CAS、staged write 与崩溃恢复。系统目前没有任何方式经审批写入图片。

代码入口：Core change-set 类型与校验；Tools materializer、`final-document-validator.ts`；Backend PendingAction 接口；Desktop diff / 审批视图。

## Scope

- 先写 ADR 0005，并更新 SANDBOX_CHANGE_ENGINE 与 HUMAN_APPROVAL_AND_GIT。
- CandidateChangeSet 增加二进制图片条目：PNG / JPEG / WebP；仅 create 与 update；记录 sha256、字节数、媒体类型、像素尺寸。
- 允许路径限定为 `characters/<id>/portraits/*.{png,jpg,jpeg,webp}`。
- draft 以内容寻址 blob 存放于 `.workspace/change-engine/v1`；materializer 复用 CAS / staged write / 恢复路径。
- 审批视图显示图片预览、尺寸与大小，update 时新旧并排；与同一 action 中的文本变更一起审批。
- 只读预览接口：按 action id 与变更序号取候选图片，只在该 action 待审批期间可用；默认直接返回候选图片，由界面缩放。
- ADR 0005 明确两件事：图片条目在严格 `schemaVersion: 1` 下如何表达（默认作为 v1 的新增变更种类，已有纯文本记录无需迁移）；“Renderer 不接收 candidate bytes”如何收窄为只对图片预览开放。
- Accept 后按 `git.autoCommitOnAccept` 处理提交。

## Constraints

- 二进制条目只能由宿主确定性 producer 生成；模型与 just-bash 投影看不到、不能编辑二进制内容；Accept 不重放命令。
- 校验魔数、扩展名与媒体类型一致、像素尺寸上限、单文件与单 action 总量上限；拒绝符号链接、越界与隐藏路径。
- create 要求目标不存在；update 要求 baseline hash 一致；不支持二进制 delete（删除仍由作者自行处理或后续扩展）。
- 文本变更的合同、存储与行为保持不变；不得引入第二套写入引擎、兼容 reader 或旧记录迁移器。已保存的纯文本 PendingAction 在升级后原样可读、可 Accept。
- Renderer 仍不接收 artifact 路径与文本候选的原始字节；预览接口不接受路径参数，action 进入终态后即不可用。
- 搜索、导出、修改影响分析、Agent 投影等只处理文本的功能遇到这些图片时跳过，行为不变。
- 关闭自动提交时不 commit / sync。

## Done Criteria

- 合成 producer 生成“新图片 + YAML 更新”的 action：diff 显示缩略图，Accept 后文件字节与 sha256 一致并按配置提交。
- 魔数不符、路径越界、超限、baseline 漂移在候选或 Accept 阶段被拒绝且不留下部分写入。
- 在 staged write 中途模拟崩溃，恢复后结果与正常 Accept 一致。
- 现有文本变更回归全部通过；just-bash 投影中不出现二进制条目。
- 升级前保存的纯文本 PendingAction 可正常读取与 Accept；预览接口在 action 被接受或拒绝后返回不可用，且拒绝任何路径形式的参数。
