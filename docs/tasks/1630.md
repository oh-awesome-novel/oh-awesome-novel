## Goal

图片资源单独存放、不进 Git；正式文件里只记录图片路径，变更引擎只审批路径的修改，不接触图片内容。

## Existing Baseline

[SANDBOX_CHANGE_ENGINE](../SANDBOX_CHANGE_ENGINE.md) 只接受无 NUL 的 UTF-8 文本，本任务不改变这一点。立绘与场景图目前由作者放在工作区任意位置，以 `looks.refImagePath` 等工作区相对路径引用；创建会话时由 [PLAY_LOCAL_SCENERY](../PLAY_LOCAL_SCENERY.md) 的有界读取器读成 data URL 存进会话，单张上限 256 KiB。工作区初始化时会写一份 `.gitignore`。系统没有专门的图片目录，也没有任何写图片的入口。

代码入口：Core `workspace.ts`（初始化与 `.gitignore`）、`character-roster-store.ts` 与场景图读取器；Backend 会话与资源接口；Desktop 舞台与角色页。

## Scope

- 定义工作区内的图片资源目录（默认 `assets/`，立绘在 `assets/portraits/<角色 id>/`），写入 [FILESYSTEM_SPEC](../FILESYSTEM_SPEC.md)：它是作者可见的普通文件夹，被 Git 忽略，不属于正式小说内容，不参与变更引擎。
- 新工作区初始化时把该目录写入 `.gitignore`；已有工作区的补充方式在实施计划中确定。
- 宿主的图片资源接口：
  - 列出某角色的立绘图片（供 [1600](1600.md) 的表单选择）；
  - 导入：把作者选中的本机图片复制进资源目录；
  - 存入：把宿主产生的图片（[1650](1650.md) 采用的生成图）写进资源目录；
  - 读取：按路径把原图提供给界面显示，不缩放、不转码。
- 写入规则：只新增，不覆盖。文件名冲突时自动改名；同一内容重复存入时复用已有文件。
- 未被任何正式文件引用的图片可列出，由作者决定是否删除；系统不自动删除。
- 更新 PLAY_LOCAL_SCENERY 中与立绘相关的说明。

## Constraints

- 不修改 Sandbox Change Engine、CandidateChangeSet、PendingAction 与 materializer 的任何合同；不新增 ADR。图片路径的修改是普通的 YAML 文本变更，照常经 PendingAction 审批。
- 图片内容不进入 Git、不进入候选、不进入 Agent 的读取与枚举范围，也不发给任何模型。
- 只接受 PNG / JPEG / WebP，校验栅格签名与扩展名一致；拒绝符号链接、隐藏路径与越出资源目录的路径；单文件大小有上限（默认 16 MiB）。
- 导入与存入都是作者在界面上显式触发的动作；宿主不在后台写图片。
- 因为只新增不覆盖，路径变更被拒绝时原来引用的图片不受影响；被拒绝的新图片留在资源目录，成为未引用文件。
- 资源目录缺失、图片缺失或损坏不是错误：引用处显示占位并说明原因。换一台机器克隆工作区后图片不会跟来，这是有意的取舍，界面需要说明。
- 既有 `refImagePath` 与场景图的读取方式、位置与上限保持不变；本任务不迁移它们。

## Done Criteria

- 新建工作区后资源目录被 Git 忽略；导入一张图片后 `git status` 不出现它。
- 同名文件导入两次得到两个文件；同内容存入两次只有一个文件。
- 非图片、签名与扩展名不符、超限、符号链接与越界路径被拒绝并说明原因。
- 导入与存入期间正式文件、候选与 PendingAction 均无变化；Agent 投影看不到资源目录。
- 引用的图片被删除后，角色页与舞台显示占位和原因，不报错。
- 变更引擎现有回归全部通过，且其文档与类型没有改动。

## Implementation Notes

2026-11-12 交付目录、接口与管理界面；当时剩一项验收要等 1600，标为 Needs Review。2026-11-13 随 1600 关闭该项，转为 Completed。

已交付：

- **目录与规范**：`assets/`，立绘在 `assets/portraits/<角色 id>/`，已写入 [FILESYSTEM_SPEC](../FILESYSTEM_SPEC.md#image-asset-directory) 与 [PLAY_LOCAL_SCENERY](../PLAY_LOCAL_SCENERY.md)。
- **Git 忽略**：新工作区的 `.gitignore` 增加 `/assets/`。已有工作区的 `.gitignore` 不改写；作者第一次导入时如果 Git 还没有忽略该目录，宿主把 `/assets/` 追加到本机的 `.git/info/exclude`（Tools `ensureGitLocalExclude`）。已经提交进 Git 的图片不受影响。
- **Core `image-assets.ts`**：路径形状校验、签名识别、按角色列出、存入、读取原图、列出未引用、删除未引用。存入以独占方式创建文件，同名加 `-2`、`-3`…，同目录内容相同则复用；文件名统一成 ASCII。“导入”和 1650 将用的“存入”是同一个函数 `addPortraitImage`。
- **Backend**：`GET/POST /api/workspace/image-assets/portraits/:characterId`、`GET/DELETE /api/workspace/image-assets/file?path=`、`GET /api/workspace/image-assets/unreferenced`。导入用原始字节，不走 base64 JSON；拒绝时返回原因与错误码（400 / 404 / 409 / 413 / 415 / 422）。
- **Client**：对应五个方法，返回值校验路径必须在 `assets/` 内且属于所请求的角色。
- **Desktop**：Play 顶栏新增“图片资源”，可按角色查看、导入图片、复制路径、检查并逐张确认删除未引用的图片；`ImageAssetView.vue` 按路径显示原图，缺失或损坏时显示占位与原因，供 1600 的表单和舞台复用。
- **未引用的判定**：在 chapters、characters、world、state、timeline、foreshadow、summaries、outline 下的 Markdown / YAML 里按路径文本查找；仍被引用的图片不能通过界面删除。
- **变更引擎没有改动**：`assets/` 不在投影的固定目录内，全局搜索同理；只在 `git-integration.ts` 增加了一个独立的辅助函数。SANDBOX_CHANGE_ENGINE 文档与引擎类型未改。
- 没有数据因本任务失效。
