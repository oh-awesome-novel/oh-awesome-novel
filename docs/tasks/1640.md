## Goal

作者可以配置本地 ComfyUI 或在线生图 API，测试连通，并通过统一接口出图。

## Existing Baseline

LLM provider 配置是应用级全局 `llm-providers.json`，`apiKey` 对前端脱敏为 `hasApiKey`（[0540](0540.md)）。模型调用统一走 Vercel AI SDK，`ai@7` 提供 `generateImage`。名册 `looks` 预留了 booru tags 与 LoRA 字段，但没有任何生图调用方。

代码入口：Core `llm-provider.ts`（参照）；Backend provider 配置接口；Desktop `LauncherModelView.vue` / 设置页。

## Scope

- 全局配置 `image-providers.json`：服务 id、显示名、类型（`comfyui` / 在线 provider）、地址、模型、默认尺寸、默认负面词、超时；API Key 脱敏。
- Core 定义 `PortraitImageRequest` / `PortraitImageResult` 类型与提示词组合纯函数；网络调用在 Backend。
- ComfyUI 适配器：导入 API 格式工作流 JSON 与占位映射（正向 / 负向提示词、种子、宽高、批量、LoRA）；`POST /prompt` → 轮询 `GET /history/{id}` → `GET /view`；`POST /interrupt` 取消；`GET /system_stats` 连通测试。
- 在线适配器：通过 AI SDK `generateImage` 接入；首批服务在实施计划中确定。
- 设置页：增删改服务、导入工作流、测试连通、显示最近一次错误。
- 每次生图请求写一条用量与外发记录（沿用 [1110](1110.md) 的做法）：服务 id 与类型、模型、地址 origin、张数与尺寸、耗时与结果；本机 ComfyUI 标为本地。

## Constraints

- 配置、API Key、工作流文件只存全局配置目录，不写小说工作区、不进 Git、不发给渲染进程明文。
- ComfyUI 默认只允许 loopback 地址；远程地址需显式开启。
- 在线服务不得手写私有 HTTP 客户端，统一走 AI SDK；新增 provider 依赖固定版本，许可信息进入 notices。
- 请求超时、单次张数上限、返回字节上限、魔数校验；错误分类为不可达、鉴权失败、超时、内容被拒、返回格式错误。
- 外发记录不含提示词原文、图片内容、API Key、请求头或完整地址。
- 导入的 ComfyUI 工作流会在作者自己的 ComfyUI 上原样执行，其中的节点能做什么由该 ComfyUI 决定；导入时提示这一点，系统只替换已声明的占位，不改写其他节点。
- 本任务不写任何小说正式文件，也不被 Play 调用。

## Done Criteria

- 用本地 mock ComfyUI 服务：提交、轮询、取图、取消、超时、工作流占位缺失均按预期。
- 用 mock 在线 provider：经 `generateImage` 出图，鉴权失败与内容被拒有对应错误。
- 前端拿到的配置不含 API Key；远程 ComfyUI 地址未开启时被拒绝。
- 成功与失败的请求各有一条外发记录，记录中不出现提示词与密钥。
- 提示词组合纯函数对“角色 tags + 服装 tags + LoRA 触发词 + 立绘 prompt”的输出稳定可测。

## Implementation Notes

2026-11-13 交付，按 [实施计划](../superpowers/plans/2026-11-13-image-generation-providers.md) 实现。

- Core `image-provider.ts`：配置规范化与脱敏、请求约束、`composePortraitPrompt`、ComfyUI 工作流检查与填充、请求记录校验。
- Agent `createAiSdkImageModelResolver`；Backend `image-generation.ts`：配置读写、ComfyUI 适配器、经 `generateImage` 的在线适配器、请求记录与 HTTP 接口。
- Client `image-providers.ts`；Desktop 启动页“模型”下方的“生图服务”区。
- 首批在线服务定为 `openai` 与 `openai-compatible`，用已安装的 provider 包，没有新增依赖。

与任务原文的出入：

- 请求记录没有写进 1110 的 `usage-stats.jsonl`，而是全局配置目录下单独的 `image-generation-log.jsonl`：1110 的记录按工作区和会话存放、以 token 为单位，生图设置不属于任何工作区。记录字段有白名单，带提示词或 Key 的记录写不进去。目前没有查看这份记录的界面，只有 `GET /api/image-generation/log`。
- 在线服务的“测试连通”不发真实请求（按张计费），只确认配置完整；地址与 Key 到第一次出图才验证。界面上有说明。
- 负面词不发给在线服务。
- 出图接口 `POST /api/image-providers/:id/generate` 已提供并有测试，但还没有界面调用它；那是 [1650](1650.md)。
- 设置页放在启动页“模型”页内，没有单独的设置入口。

会失效的数据：无。
