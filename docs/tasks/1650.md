# 1650 Character Portrait Generation Workbench

> Status: Planned
> Priority: P1
> Updated: 2026-11-12

## Related Plans

- [角色立绘生图模块规划 · 3.4](../plans/PORTRAIT_IMAGE_GENERATION_PLAN_2026-11-12.md#34-角色立绘生图工作台1650)

## Goal

在独立的“立绘生图”页面为角色的某张立绘生成候选图，挑一张后经审批写入角色卡。

## Existing Baseline

[1600](1600.md) 规划了 `portraits` 立绘描述与 `prompt` 字段；[1630](1630.md) 规划了经审批的图片写入；[1640](1640.md) 规划了生图服务与适配器。目前没有生图入口。

代码入口：Backend 生图任务接口；Desktop 新页面与角色页立绘表单入口。

## Scope

- 页面入口：工作区导航；角色页立绘表单的“生成”按钮（带入角色与立绘项）。
- 选择角色与立绘项（或新建立绘项）→ 预览组合提示词（可临时修改）→ 选服务、尺寸、张数、种子 → 生成。
- 可选“根据描述起草提示词”：用已配置 LLM 起草，只填入表单；发出前说明会发送哪些角色资料，调用计入现有用量记录。
- 结果暂存 `.workspace/portrait-gen/<job-id>/`，画廊浏览、重新生成、固定种子微调；该内部目录写入 [FILESYSTEM_SPEC](../FILESYSTEM_SPEC.md)，不进 Git。
- 采用：宿主生成 PendingAction，包含图片 create / update 与 `roster-profile.yaml` 中该立绘 `image`、`prompt`、`generation` 的更新 → Git diff 审批 → Accept。
- 任务管理：每工作区同时最多一个任务，可取消；重启后未完成任务标为中断；暂存区按数量与天数上限清理。
- 舞台用图尺寸按关联计划 §4 的默认处理：采纳时缩放转码为不超过会话冻结上限的舞台版本，只把舞台版本写入工作区，原图留在暂存区。作者改变该默认时先回写 1600 与 1630。

## Constraints

- 生成结果在 Accept 前不得进入 `characters/` 或任何正式文件；暂存区不被 Agent 读取或枚举。
- 不自动采用；一次采用只生成一个 PendingAction。
- `generation` 不记录 API Key、服务地址或工作流全文。
- Play 不感知生图：已有会话保留冻结字节；Play 运行中不能触发生图。
- 起草提示词与生图都需作者点击触发，不在后台自动发生。

## Done Criteria

- 用 mock 服务：选角色立绘 → 生成 3 张 → 采用第 2 张 → diff 显示图片与 YAML 变更 → Accept 后文件与 `generation` 记录正确。
- 取消、超时、服务不可达时界面给出原因，除暂存区外不产生任何文件。
- 拒绝 PendingAction 后工作区无变化；暂存图片仍可再次采用。
- 新建 Play 会话使用新立绘，已有会话不变。
- 默认 SDK → HTTP → Desktop 的“生成 → 采用 → Accept → 舞台显示”旅程通过。
