## Goal

在独立的“立绘生图”页面为角色的某张立绘生成候选图，挑一张存入图片资源目录，并经审批把它的路径写进角色卡。

## Existing Baseline

[1600](1600.md) 规划了 `portraits` 立绘描述与 `prompt` 字段；[1630](1630.md) 规划了图片资源目录与存入接口；[1640](1640.md) 规划了生图服务与适配器。目前没有生图入口。

代码入口：Backend 生图任务接口；Desktop 新页面与角色页立绘表单入口。

## Scope

- 页面入口：工作区导航；角色页立绘表单的“生成”按钮（带入角色与立绘项）。
- 选择角色与立绘项（或新建立绘项）→ 预览组合提示词（可临时修改）→ 选服务、尺寸、张数、种子 → 生成。
- 可选“根据描述起草提示词”：用已配置 LLM 起草，只填入表单；发出前说明会发送哪些角色资料，调用计入现有用量记录。
- 结果暂存 `.workspace/portrait-gen/<job-id>/`，画廊浏览、重新生成、固定种子微调；该内部目录写入 [FILESYSTEM_SPEC](../FILESYSTEM_SPEC.md)，不进 Git。
- 采用：宿主通过 1630 的存入接口把选中的原图写进图片资源目录（新文件，不覆盖），再生成 PendingAction，更新 `roster-profile.yaml` 中该立绘的 `image` 路径、`prompt` 与 `generation` → Git diff 审批 → Accept。候选里只有 YAML 文本；审批界面在路径旁显示新旧图片对照。
- 任务管理：每工作区同时最多一个任务，可取消；重启后未完成任务标为中断；暂存区按数量与天数上限清理。

## Constraints

- 作者点击“采用”之前，生成结果只在暂存区；Accept 之前角色卡等正式文件不变。暂存区与图片资源目录都不被 Agent 读取或枚举。
- 存入的是原图，不缩放、不转码，不引入图片编解码依赖；图片不进 Git。
- 不自动采用；一次采用只生成一个 PendingAction。
- `generation` 不记录 API Key、服务地址或工作流全文。
- Play 不感知生图：已有会话仍按开局时记录的路径显示；Play 运行中不能触发生图。
- 起草提示词与生图都需作者点击触发，不在后台自动发生。

## Done Criteria

- 用 mock 服务：选角色立绘 → 生成 3 张 → 采用第 2 张 → 原图出现在资源目录且 `git status` 不出现它 → diff 只含 YAML 变更，旁边显示图片对照 → Accept 后 `image` 路径与 `generation` 记录正确。
- 取消、超时、服务不可达时界面给出原因，除暂存区外不产生任何文件。
- 采用同一张图两次，资源目录里只有一个文件。
- 拒绝 PendingAction 后角色卡不变并仍指向原图；已存入的图片留在资源目录，可再次采用。
- 新建 Play 会话使用新立绘，已有会话不变。
- 默认 SDK → HTTP → Desktop 的“生成 → 采用 → Accept → 舞台显示”旅程通过。
