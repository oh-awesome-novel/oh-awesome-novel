## Goal

Play 会话里的重要道具与消耗品有一张带类型的道具表：谁持有、还剩多少、哪一回合得到或用掉，由宿主校验，不再靠裁判自觉。

## Existing Baseline

道具和资源没有自己的结构，只是会话通用状态 `playLocalState` 里的自由键值；裁判每回合用 `stateDelta` 修改，事件可用 `stateDeltaRefs` 指向被改的键。界面上它们与其他状态一起平铺在 `PlayWorldHud` 的状态列表里。唯一的保护是阶段归档时宿主核对状态账本未被模型改动或遗漏（[1400](1400.md)）。没有持有者、数量类型或“用掉了什么”的记录。

Writing 一侧，[FILESYSTEM_SPEC](../FILESYSTEM_SPEC.md) 的目录树曾列出 `state/inventory.yaml`，但没有任何代码读写或校验它；该行已随本任务立项标注为未实现。

[1480](1480.md) 的原作节点表已建立“会话创建时决定、存于会话状态的保留键、未启用逐字节不变”的可选扩展做法。

代码入口：Core `play-types.ts`、`play-referee-protocol.ts`、`play-turn-artifact.ts`、`play-session.ts`、`play-compaction.ts`、`play-canon-beats.ts`（参照）；Desktop `PlayWorldHud.vue`、`components/play/launch/`。

## Scope

- 会话创建时可选启用道具表；旧会话不能追加启用。
- 每件道具：稳定 id、名称、持有者（会话参与者或“无人持有 / 场景中”）、类别（关键道具 / 消耗品 / 普通）、数量（消耗品必填的非负整数，其余可省略）、可选说明、来源回合。
- 开局可预填初始道具：作者在引导开局中手动填写，或从选中的角色资料里挑选；预填内容冻结在 Launch Package。
- 结算增加专门的道具变更字段：获得、消耗、转移、丢失、改说明。每条变更引用本回合的事件作为依据。
- 宿主校验：不能消耗或转移不存在的道具；数量不能为负；消耗量不超过持有量；关键道具的丢失与转移必须有事件依据；未知持有者被拒绝。校验失败时本回合失败并说明原因，与现有结算错误的处理一致。
- 启用后，冻结前缀给出规则，每回合的消息尾部给出当前道具表（按视角过滤）；道具不再写进自由的 `stateDelta`。
- 道具表属于分支快照：Retry / Restore 回到对应节点的状态；阶段归档完整带入，由宿主携带，不要求模型复述。
- Desktop 道具面板：按持有者分组，显示数量与类别；每件可展开查看获得、消耗的回合记录并跳转到该回合。舞台模式（[1580](1580.md)）提供只读的简版入口。
- 导演可手动增删改道具，作为显式的导演操作记录在案。
- Outcome Report 列出本局道具的最终状态与关键变化，供作者决定是否带回 Writing。

## Constraints

- 道具表只属于 Play 会话，不是正式事实；不新增正式文件类型，不实现 `state/inventory.yaml`。带回 Writing 走现有采纳与转写流程，由作者选择。
- 未启用的会话在冻结前缀、回合请求与存储上与基线逐字节一致。
- 视角隔离：玩家视角只看到玩家角色已知的道具；他人持有且玩家不知道的道具不进入玩家可见的叙述提示、候选项与面板。
- 宿主只做结构与数量校验，不判断某件道具在剧情上是否“应该”存在或有多强。
- 不做装备栏、属性加成、合成、商店、掉落表等游戏系统；不做数值战斗。
- 道具数量有上限（每会话默认 200 件，每件说明有长度上限），超出时拒绝新增并提示。
- 结算协议新增字段与保留键的版本规则先写入 PLAY_MODE_SPEC；这是内部会话数据，按 AGENTS.md 的内部 schema 规则处理，不写旧会话迁移器。

## Done Criteria

- 启用会话：开局带三件道具（关键、消耗品、普通各一），经过获得、消耗、转移后，道具表与每件的回合记录正确。
- 消耗不存在的道具、消耗超量、数量为负、关键道具无依据丢失、未知持有者各有回归，回合失败且会话状态不变。
- Retry / Restore 后道具表回到对应节点；阶段归档后道具表完整，后续回合继续可用。
- 玩家视角的请求与面板中不出现玩家不知道的道具；导演视角可见全部。
- 未启用会话的冻结前缀与请求在测试中逐字节等于基线。
- 默认 SDK → HTTP/SSE → Desktop 的“开局预填 → 回合中消耗 → 面板查看记录 → 跳到来源回合”旅程通过。
