# 常见问题

下面的说明以当前桌面界面为准。报错时先记下具体提示、当前工作区和正在执行的操作，再按对应条目处理。文中的 Review 是审阅流程，具体入口是右侧 **Approval** 与 **Diff** 页签。

## 浏览器预览打不开或端口被占用怎么办？

先确认后端和前端两个终端都在运行。后端默认端口为 `3210`，前端通常为 `5173`，以各终端实际输出为准。文档站的 `5174` 是阅读指南的地址，不是小说应用。

后端提示端口占用时，可以在仓库根目录另选端口，例如 `3211`：

```sh
npm run dev --workspace @oh-awesome-novel/http-backend -- \
  --workspace-root "$(pwd)/examples/simple-novel" \
  --global-config-dir "$(pwd)/.temp/oan-global" \
  --port 3211
```

在另一个终端同步调整前端代理，以下示例使用 `5175` 作为界面端口：

```sh
VITE_OAN_BACKEND_PROXY_TARGET=http://127.0.0.1:3211 \
  npm run dev --workspace @oh-awesome-novel/desktop-ui -- \
  --host 127.0.0.1 --port 5175 --strictPort
```

然后打开 `http://127.0.0.1:5175/`。只改浏览器地址不会改变前端的后端连接；更改代理后需要重启前端。

如果终端仍在构建或提示编译失败，先处理终端中的具体错误。并行开发期间，文档可以通过 `npm run docs:dev` 独立阅读。

## 为什么能打开工程，却不能让 AI 写作？

未配置 Provider 时，工程仍可进入只读模式，查看文件与已有内容。Copilot 写作、参考资料的模型分析和 Play 生成需要可用模型。

打开应用级模型设置，核对 Provider、Model ID、Base URL（如适用）与 API Key，保存后返回工程。详见[模型与写作配置](./settings.md)。

模型凭据属于应用设置，不需要复制到小说文件里。

## 为什么打开章节后不能直接输入？

当前右侧 `File` 视图标记为 **Read only**，用于阅读和核对原文件。AI 修改通过 Copilot 提出，再到 Review 接受；直接手写可以通过外部编辑器入口打开工作区。

使用外部编辑器改动后，返回应用重新读取文件。旧提案不会自动吸收外部修改，如果出现过期或冲突，基于当前内容重新生成提案。

## AI 已经回复“完成”，为什么正文没变？

聊天回复不等于文件写入。先检查是否生成了 PendingAction，再打开 Review 查看目标文件和 diff，确认后点击 **Accept**。

如果没有 PendingAction，可能这次只是讨论、分析，或者没有形成实际文件差异。可以明确提出目标，例如「请修改当前章节的争执场景并生成可审阅的改动」。操作见[写作与 Copilot](./writing.md)。

## Accept 失败，是否要直接再点一次？

先看错误并刷新状态。常见原因包括：目标文件已变化、分支或 HEAD 已变化、来源材料过期、存在其它暂存内容，或文件内容未通过校验。

如果当前内容已经改变，重新生成提案再审阅。请求中断时，先确认 PendingAction 是否已经变为 accepted；不要把「没有收到成功响应」当作「肯定没有写入」。

如果状态已经 accepted，但 Git 显示失败，处理的是提交问题，参见[Git 指南](./git.md)，不需要再次接受正文。

## 为什么一份旧提案突然过期？

提案基于生成时的文件和 Git 状态。接受另一份提案、手动编辑文件、切换分支或外部 Git 提交，都可能使旧提案不再对应当前内容。

先检查现有修改是否应保留，再重新发起请求。多个对话同时操作同一部小说时，依次处理会改动相同文件的提案更容易核对。

## Git 自动提交关闭了，AI 会绕过审批吗？

不会。`git.autoCommitOnAccept` 只控制批准后的 Git 提交。关闭后，仍需在 Review 中 Accept 才能写入 AI 提出的文件修改；批准的内容会以未提交修改的形式保留。

设置位置与手动提交方法见[Git 指南](./git.md)。

## Search 为什么搜不到正文中的一句话？

工作台顶部的 **Search** 现在支持搜索正文、标题和路径；启动器搜索仍用于查找工作区名称、小说名称或路径。

没有结果时，先确认外部编辑器已保存文件，再点击「刷新结果」。搜索按连续文字匹配，不支持跨行句子、模糊匹配或正则表达式；可以缩短为一个人名或句中的短语。

搜索只覆盖当前工程中的小说内容目录及指定创作约束文件，不包含参考资料、Play、聊天记录或其他隐藏配置。每个文件只显示首个命中，最多显示 100 个匹配文件。范围和限制见 [搜索与导出](search-and-export.md)。

若显示错误而不是空结果，先检查相关文本是否过大、是否使用链接文件或是否为有效 UTF-8，再重试；报错不代表工程内没有命中。

## Import workspace、References 导入和旧稿导入有什么区别？

| 操作 | 当前含义 |
| --- | --- |
| Import workspace | 把已有工程目录加入启动器列表 |
| Import reference | 保存外部参考文本，供分析、技巧参考和素材采纳 |
| 旧稿导入为正式章节 | 当前没有完整的桌面导入向导 |

不要用 References 导入来替代章节整理。参考资料不会自动成为 `chapters/` 中的正文。现有工程的目录组织见[工作区与文件](./workspace.md)。

## 支持直接导入 PDF、Word、EPUB 吗？

当前 References 的文件路径按 UTF-8 文本读取，没有这些格式的转换入口。先将需要分析的内容整理为 TXT 或 Markdown，或粘贴文本，再导入。

## 参考资料已经启用，为什么仍显示 Not eligible？

启用只是偏好。新导入资料要经过分析、发布提案和 Review Accept，发布结果有效后，才可能用于写作上下文。

如果只选择 Story Materials 输出，Technique 上下文会显示 **Not generated**；它仍可用于素材采纳。来源发生变化、结果过期或当前预算不足时，也可能不被选入某次请求。先在 References 中 Refresh，查看 readiness reason 与上下文选择结果。

完整步骤见[参考资料](./references.md)。

## 完整分析为什么没有自动继续？

当前 Reference 分析每次 **Run next unit** 最多运行一个有范围限制的单元。确认完整分析只建立计划，不会自动跑完全部内容。

有失败单元时用 **Retry failed unit**；暂停后用 **Resume full analysis**。请求结果不明时先 **Reconcile run**，确认状态后继续。

## 分析有 Warned 就不能发布吗？

**Warned** 表示有非阻断提醒。展开提醒，检查不确定结论、缺失类别或措辞重合等问题，再决定是否发布。界面要求先展开提醒列表。

结构完整性错误属于阻断问题，不能用展开提醒代替修正。发布分析与采纳素材都仍需到 Review 接受。

## 在 Play 点过 Accept，为什么章节没更新？

Scene Rehearsal 的 Accept 只选择一个角色步骤，Finish 只结算到 Play 会话。写入正式小说需要走 **Bring to writing → Preview canonical diff → Confirm and create PendingAction → Review → Accept**。

如果只想把结果作为下一次创作请求的素材，可以创建 Writing Reference 附件。两条路径见[Play 指南](./play.md)。

## Play 附件为什么消失了？

Copilot 中勾选的 **Play Writing References** 只附到下一次请求。发送成功或切换对话会清空选择，需要使用时重新勾选。

如果附件显示非 active，或 Outcome Report 已过期，先回到 Play 核对当前分支和来源，再刷新或重新生成报告。

## Play 中断后按钮不可用怎么办？

先看是否存在结果未知、恢复要求或版本冲突提示。按页面提供的恢复或刷新操作，核实服务端状态，再继续生成。试演尚未 Finish 或 Cancel 时，Outcome 的部分操作也会被禁用。

生成中的文本尚未保证结算成功；恢复前不要连续重发相同动作。

## 在外部编辑器中打开失败怎么办？

外部编辑器入口需要对应编辑器和命令可用。先确认已安装所选编辑器及其命令行启动工具；也可以直接从编辑器里打开当前小说工程目录。

返回应用后刷新文件和 Git 状态。不要把外部编辑器中未保存的内容当作应用已经读取到的正文。

## 怎样导出整本小说？

在写作工具栏点击 **Export manuscript** 下载图标，选择「下载 Markdown」或「下载 TXT」。应用会按卷号和章节号合并已保存的正文章节，下载带时间戳的新文件，不修改小说工程。

导出不包括 `0000.md` 卷信息、YAML 元数据、摘要、设定、参考资料、Play 或尚未接受的草稿。TXT 只去除 Markdown 标题前缀，正文里的加粗、链接等标记会保留。详见 [搜索与导出](search-and-export.md#导出整本正文)。

## 点了导出，为什么找不到文件？

「已发起下载」表示应用已经请求下载，不等于已确认文件保存到某个位置。查看浏览器或应用的下载提示、默认下载目录，以及可能弹出的保存对话框；保存位置和同名文件处理由下载设置决定。

如果窗口显示错误，确认 `chapters/` 中已有符合编号规则的已保存章节，例如 `chapters/0001/0001.md`。仅有 `0000.md`、聊天草稿或待审批项时，没有可导出的正式章节。完整检查方法见 [搜索与导出](search-and-export.md#导出失败时)。

## 可以一键回滚历史或导入旧稿吗？

当前尚无完整的旧稿章节导入、Git 历史回滚或分支管理界面。需要恢复历史时，基于当前文件提出新的修改，或在你熟悉的 Git 工具中审阅后恢复对应内容。References 导入不会自动把旧稿整理为正式章节。

## 重启后，历史对话会自动恢复吗？

当前「历史对话」用于切换本次界面会话里的聊天，尚未提供从磁盘恢复完整聊天记录的入口。刷新页面、退出工作区或重启应用后，不应依赖它恢复之前的对话。

需要长期保留的故事内容应确认已写入实际文件，并记录到 Git；已有待审批项可重新进入工作区后从 **Approval** 查看。
