# 快速开始

Oh Awesome Novel（OAN）把小说正文、角色、设定和创作记录保存在本地文件夹里。你可以用 Copilot 讨论故事、提出修改，再逐项查看差异并决定是否写入文件。

第一次使用，建议先完成：启动应用 → 创建或打开工作区 → 配置模型 → 浏览一章 → 提出一项小修改 → 审阅并接受。

## 从源码启动

当前仓库提供 Electron 桌面入口和浏览器开发预览。以下命令都在仓库根目录执行。

准备 Node.js **24.x**、npm 和 Git。可以先检查版本：

```sh
node --version
npm --version
git --version
```

安装依赖：

```sh
npm install
```

### 桌面应用

```sh
npm run dev --workspace @oh-awesome-novel/desktop
```

该命令会先构建桌面入口所需依赖，然后启动 Electron。进入启动器后，用「新建」或「打开」选择本机文件夹。

### 浏览器预览

在第一个终端启动本地后端：

```sh
npm run dev --workspace @oh-awesome-novel/http-backend -- \
  --workspace-root "$(pwd)/examples/simple-novel" \
  --global-config-dir "$(pwd)/.temp/oan-global" \
  --port 3210
```

在第二个终端启动界面：

```sh
npm run dev --workspace @oh-awesome-novel/desktop-ui
```

打开第二个终端输出的 Vite 地址。后端默认监听 `http://127.0.0.1:3210`，前端会把 `/api` 请求转发给它。

上面的命令会登记仓库里的 `examples/simple-novel` 作为示例工作区，并用 `.temp/oan-global` 保存这次开发预览的应用配置。可以先浏览示例；若要练习修改，请使用自己的副本，并按 [Git 与历史](git.md) 检查副本拥有独立 Git 仓库。不要把示例目录所在的项目仓库当作小说自己的 Git 仓库。

浏览器预览通过输入路径打开本机工作区，不提供系统文件夹选择器。路径指向**运行后端的电脑**上的目录；请填完整绝对路径，例如 `/Users/me/novels/雾港来信`，不要填网页地址或只写 `~`。

::: tip 端口冲突
若 `3210` 已被占用，需要同时改后端端口和前端转发目标。具体命令见 [常见问题](faq.md)。
:::

## 创建第一本小说

1. 在启动器的「项目」页点击「新建」。
2. 桌面版选择一个空目录；浏览器预览输入空目录或尚不存在的新目录路径，再点击「创建」。已有稿件的目录不要用来新建。
3. 按引导填写「小说名」「基础灵感」「生成角色」和「开始编写」。可以先用临时代号，也可以点击「跳过」。
4. 在最后一步选择先生成角色卡、规划第一章、写开场或写章节。
5. 已配置模型时，点击「放到 Copilot 输入框」；未配置时，点击「保存并配置 Provider」。检查输入框里的请求，补充要求后再发送。

引导会保存作品名和创作方向，并准备第一条请求；点击完成不会自动发送，也不会自动生成已保存的章节。当前空工作区可以先用于讨论和规划，实际文件修改的范围见 [写作与 Copilot](writing.md#先确认本轮目标)。

新建时应用会初始化小说目录，并尝试建立 Git 仓库和首次提交。如果首页或 Git 页提示身份缺失、Git 不可用或尚无提交，先按 [Git 与历史](git.md) 处理，再进行需要审批落盘的操作。

## 打开已有工作区

1. 在「项目」页点击「打开」，选择或输入已有 OAN 工作区目录。
2. 目录验证通过后，它会加入最近项目列表。
3. 点击该项目的「进入」，或双击项目行。

已有工作区需要包含 `.oan/config.yaml`、`.oan/workflow.yaml` 和小说内容目录。普通 Markdown 文件夹或 Word 稿件不能直接当作 OAN 工作区打开。更多说明见 [工作区与文件](workspace.md)。

## 配置模型，或先只读浏览

没有模型配置时，打开已有项目会出现「配置 LLM Provider」窗口。你有两个入口：

- 填写 Provider、Model 和所需的 API Key，点击「保存并进入」。
- 点击「稍后配置」，先浏览本地文件；Copilot 发送功能会保持不可用。

也可以返回启动器的「模型」页，管理多个 Provider、获取模型列表和检测连接。Ollama 不需要 API Key，但需要已有可运行的本地服务和模型。详细步骤见 [模型与偏好设置](settings.md)。

保存配置表示资料已保存，连接是否可用仍需通过「检测模型」确认。

## 完成第一次修改

使用已有 OAN 工作区中的一章做一个小范围练习：

1. 在左侧「章节」中打开一章，确认右侧 `File` 显示的路径和正文。
2. 在 Copilot 输入以下请求，把路径替换成刚刚打开的章节：

   ```text
   /审稿
   请检查当前章节 chapters/0001/0001.md 的开头。
   保留人物关系、事件顺序和叙述视角，只修改重复措辞。
   如需修改，请提出待审批修改，并说明原因。
   ```

3. 点击发送箭头，等待回复。只有实际产生文件修改时，才会出现 PendingAction（待审批修改）。
4. 点击 `Diff` 查看文件路径和增删内容，再到 `Approval` 点击 `Accept` 接受，或点击 `Reject` 拒绝。
5. 接受后重新查看章节内容，并到 `Git` 页确认提交状态。

接受前，候选修改不会改变小说文件。聊天里出现一段草稿，也不等于已经生成待审批修改或保存完成。完整流程见 [审阅与接受修改](review.md)。

## 修改后整理一章

仍选中刚刚完成的 `chapters/0001/0001.md`，点击「整理本章」或发送 `/整理本章`。应用会要求模型给出有原文引用的观察记录，并将高置信度事实整理为该章摘要和章级状态的同一项 PendingAction。

先核对引文与解释，再到 `Diff` 检查两个输出文件，最后决定是否 `Accept`。这一步不会改写正文，也不会自动更新全局时间线或人物档案。详细步骤见[整理本章](writing.md#整理本章-保存有证据的摘要与状态)。

在 Copilot 消息区下方展开「上下文与用量」，还能检查本轮的来源与 token 数据。刚开始没有记录属于正常情况；`Estimated` 是估算，服务没有返回的实际用量显示为 `unavailable`。详见[上下文与用量](usage.md)。
