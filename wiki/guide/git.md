# Git：记录与检查小说历史

Git 为小说工程记录可回看的文件历史。AI 提案的批准、文件写入和 Git 提交是不同的步骤：**Accept 成功说明文件已写入，Git 提交状态则要单独查看。**

## 打开 Git 面板

在工作台顶部点击 **Git**，再点击 **Refresh** 获取当前状态。

| 区域 | 可以看到什么 |
| --- | --- |
| Source | 使用的 Git 来源；当前依赖电脑上的全局 Git 命令 |
| Branch | 当前分支 |
| Status | 干净、存在修改或状态不可用 |
| Dirty files | 尚未提交的文件数量 |
| 文件列表与 diff | 当前修改及将要提交的内容 |
| 提交列表 | 最近的提交；点击可查看文件列表与差异 |

当前界面展示最近 12 条提交。若要浏览更多历史、管理分支或处理冲突，可以通过工作台的外部编辑器入口打开同一个工程。

## 接受提案后的自动提交

默认情况下，接受 PendingAction 后会尝试自动提交本次批准的文件。自动提交只覆盖该提案的范围，不会顺便把其它文件的修改打包进去。

左侧底部的 **Git 自动提交** / **Git 手动提交** 显示当前工作区的设置。这个状态标记不是开关；当前没有单独的图形化 Git 配置页。

如果需要关闭自动提交，用外部编辑器打开工作区的 `.oan/config.yaml`，在保留其他配置的前提下设置：

```yaml
git:
  autoCommitOnAccept: false
```

如果已经存在 `git` 字段，就修改其中的值，不要重复添加同名字段。恢复默认行为时将其设为 `true`。重新打开工作区后核对底部状态。

关闭自动提交后，Accept 仍会写入批准的文件，但不会自动 commit 或同步。按下面的方法显式提交即可。

## 手动提交当前修改

在 Git 面板操作：

1. 点击 **Refresh**，确认工作区状态和 diff 已成功加载。
2. 阅读完整文件列表与差异，确认每个文件都应进入这次历史记录。
3. 填写 **Commit message**，例如 `完成第三章渡口冲突的修订`。
4. 点击 **Commit reviewed files**。
5. 检查提交结果和刷新后的状态。

此按钮提交当前面板列出的未提交文件，界面目前没有逐文件勾选。若需要拆成几次提交，请使用外部 Git 工具。

提交绑定你刚才看过的预览。预览后如果文件、权限、暂存区或分支发生变化，应用会拒绝旧预览并要求 **Refresh** 后重新审阅。预览超过15分钟或应用重启后也需要刷新。提交过程中才保存的新内容会留为下一次修改，不会混入刚批准的历史记录。

未提交文件为空、说明为空、Git 状态异常或 diff 预览失败时，按钮会不可用。预览失败不能视为「没有差异」。

应用内提交按预览中的原始文件内容记录历史，不运行 Git hooks 或文件转换过滤器。如果你的工程需要这些流程或签名提交，请使用外部 Git 工具；已启用签名时，应用会说明原因并拒绝替你关闭签名。

使用稀疏检出或为文件设置了 `skip-worktree` / `assume-unchanged` 的工程，也需要在外部工具中提交。应用会保留这些既有设置并给出提示。

如果显示“提交已保存，但暂存区收尾失败”，先确认历史中的提交；按提示重试同一操作或在外部工具检查暂存区，不要把它当作正文未保存。

如果只是某个已接受提案的自动提交没有完成，也可以使用该提案在审批面板 **Approval** 中提供的 **Quick commit** 入口；它与 Git 面板的 **Commit reviewed files** 范围不同，以所选提案及其状态为准。

## 同步到远端

**Sync** 是作者主动触发的网络操作。当前按顺序执行：

```text
fetch → pull --ff-only → push
```

使用前需要在外部 Git 工具中配置远端、当前分支的上游和访问凭据。应用不会通过此按钮创建远端仓库，也没有远端地址或登录凭据的设置界面。

`pull --ff-only` 仅接受可快进更新。若本地与远端已分叉，Sync 会失败，应在外部 Git 工具中检查并处理后再重试。同步停止后查看报错中的步骤，区分读取远端、拉取更新或推送失败。

自动提交成功不会自动点击 Sync。只有你明确使用 Sync 才执行上述同步流程。

## Git 不可用时

新建工程会尝试初始化独立仓库并创建初始提交。打开或导入已有工程不会擅自为它初始化或提交。

[![未初始化 Git 的演示工程显示 Workspace is not a Git repository，提交与同步按钮不可用](/screenshots/git.jpg)](/screenshots/git.jpg)

图中演示目录尚未初始化 Git，因此显示 `unknown`；它不是成功提交后的状态。

| 现象 | 下一步 |
| --- | --- |
| 提示全局 Git 不可用 | 在本机终端运行 `git --version` 检查，安装或修复 Git 后重启应用再刷新 |
| 提示没有提交身份 | 在该小说工程中配置 Git 的用户名和邮箱，再完成首次提交；应用不会替你修改身份 |
| 工作区不是 Git 仓库 | 在外部工具中核对打开的目录；确实是要纳入历史的工程时，再显式初始化 |
| 没有初始提交或 HEAD | 完成一次初始提交后重新打开工程 |
| Accept 后显示 Git 失败 | 先查看已接受文件，再修复 Git 并使用 Quick commit；不要重复接受同一提案 |
| 其它工作已暂存，批准被阻止 | 先在外部工具中检查暂存区，完成或取消暂存后重新生成、核对需要的提案 |

自动提交也可能因目标文件在提案生成前已有未提交修改而停止，以免把之前的工作混进这次 AI 修改。此时先核对差异，再选择合适的手动提交方式。

Git 提交失败不会撤销已经成功批准的正文。文件是否已写入与是否已有历史记录，应分别在文件查看器和 Git 面板确认。

## 当前界面的范围

Git 面板支持状态、差异、最近历史、提交详情、手动提交和显式 Sync。当前没有图形化分支管理、冲突编辑、远端配置或历史回滚按钮。需要这些操作时使用外部编辑器或 Git 工具，完成后返回应用刷新；尚未接受的旧提案可能需要重新生成。
