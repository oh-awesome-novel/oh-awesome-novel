# 导入自己的旧稿

旧稿导入用于把你自己的 Markdown 正文整理为工作区章节。它不调用模型；你先核对拆章、卷章编号和差异，再创建待审批项。只有在 `Approval` 中接受后，章节才会写入小说目录。

启动器的「打开」用于已有 OAN 工程，`Refs` 用于参考资料。旧稿导入属于当前小说的正文整理操作。

## 导入步骤

1. 进入目标小说的 `Writing` 模式，打开顶部「导入旧稿」入口。
2. 选择 UTF-8 编码的 Markdown 文件，或粘贴原稿文本。
3. 生成拆章预览，核对章节数、标题、原文范围及目标卷号、章号。
4. 按需要调整每章的卷章编号，再重新生成预览。目标路径形如 `chapters/0001/0002.md`。
5. 检查冲突提示和完整差异；确认原文没有遗漏，也没有被错误拆成多个章节。
6. 点击创建待审批修改，进入既有的差异与审批流程。
7. 接受后刷新章节导航并检查正文；不满意时拒绝，原稿和工作区正文都不会被此次候选改写。

编辑原稿或调整映射会使先前预览失效，需要重新预览后才能创建候选。切换工作区后也需要重新开始，避免把另一本书的原稿导入当前工程。

## 拆章和路径

预览根据支持的 Markdown 标题和中文章节标题识别章节；没有可识别标题的文本作为单章处理。代码围栏中的标题不会被当成章节。预览中的原文行号帮助你核对每段文本归属，最终导入内容以差异为准。

导入保留原有标题、前言与元数据文本，并额外添加规范的 OAN 元数据和映射标题。因此差异中可能同时出现映射标题和原稿标题；这是可审阅的追加，不是删掉原文后重写。首章标题之前的文字保留在第一章内。

卷号与章号均为 1–9999，保存时补齐四位数字。章号 `0000` 保留给卷信息，不能作为正文章节目标。

卷标题保留在原稿位置，初版不会自动按“第一卷、第二卷”分卷；请检查每个切片归属并手动调整卷号。

初版只创建新章节。路径已存在或两章映射到同一路径时，必须调整编号后重新预览；导入不会自动覆盖、合并或替换原有正文。

## 大小、格式与失败处理

- 单次源稿最多 512 KiB，最多 64 章。更大的原稿请先按卷或一组章节分批导入。
- 输入需要合法 UTF-8 文本；Word、PDF、图片与二进制文件不属于此入口支持的格式。
- 解析或格式校验失败时会显示错误，不会把部分可解析内容当成完整导入。
- 如果预览后目标路径出现新文件，或 Git 分支/HEAD 发生变化，创建候选或接受时可能提示过期。重新检查目标并生成预览即可。
- 接受后的 Git 行为遵循当前项目配置；关闭自动提交时，可以在 Git 页显式提交，不会自动同步远端。

原始上传文件不会被改写。导入成功后可使用[正文搜索与导出](search-and-export.md)检查内容，并用[整理本章](writing.md)为已导入章节生成有正文证据的摘要和状态。
