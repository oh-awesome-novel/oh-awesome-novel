# Play：先试演，再带回写作

Play（推演）用来试走角色的行动、对话和事件后果。你可以先在独立会话里验证一场戏，再选择有用的结果带回 Writing。

Play 中的行动结果、角色认知和分支都属于该会话。它们不会自动改写正式章节、人物状态或时间线。

[![推演工作区初始状态，左侧可点击“新建会话”](/screenshots/play.jpg)](/screenshots/play.jpg)

## 选择开局方式

从工作台顶部切换到 **Play**，在左侧点击 **新建会话**。先选择用途，再选择开局方式。

| 选择 | 适用场景 |
| --- | --- |
| 场景试演 | 作为作者安排一场戏，逐个检查角色反应，必要时介入调整 |
| 沉浸推演 | 以参与者身份进入世界，通过说、看、走、做和等推进 |
| 快速开局 | 自己填写开场和角色信息，用较短流程开始 |
| 引导开局 | 从真实工作区文件选择资料，确认来源与角色后再开始 |

尚未配置模型时，可以浏览已有会话；生成角色步骤或推进回合前需要完成[模型配置](./settings.md)。

[![新建推演会话时选择沉浸推演或场景试演](/screenshots/play-new-session.jpg)](/screenshots/play-new-session.jpg)

## 用快速开局准备一场戏

选择 **场景试演 → 快速开局**，依次填写三个步骤。

1. **场景**：填写场景标题、地点、开场情境和试演目标。风险与氛围用来补充，世界活跃度与事件密度决定世界活动与事件多少。
2. **人物**：添加参与角色，填写名字、位置、当前目标和初始认知。列表顺序就是角色行动顺序，可上下调整。
3. **确认**：核对场景和角色后点击 **开始场景试演**。

快速开局的 **事件设置** 可设置是否允许幕后事件、隐藏事件，以及每回合 0–6 个自发外部事件。设为 0 仍会结算已到期的计划事件。沉浸模式的快速创建表单也提供这些设置。

例如，开场可以写「暴雨封桥，两名旧识在渡口争夺最后一艘船」，试演目标写「验证双方是否会在不直接坦白秘密的情况下合作」。在初始认知中分别写清每个人知道什么，能减少角色凭空知情的情况。

这些表单内容是你为本次试演提供的材料。创建场景不会把新角色写入正式角色档案。

[![快速开局的场景表单，填写场景标题、地点、开场与试演目标](/screenshots/play-scene-setup.jpg)](/screenshots/play-scene-setup.jpg)

## 用引导开局对齐现有小说

选择 **引导开局**，按下面五步准备：

| 步骤 | 要检查的内容 |
| --- | --- |
| 来源 | 勾选当前工作区已有的文件，确认它们与这次试演相关 |
| 入场 | 填写开场、地点、时间、触发、目标与风险，选择支持开场的来源 |
| 身份 | 沉浸推演填写参与者身份；场景试演填写试演目的 |
| 人物 | 核对参与者、目标、位置、初始认知；可关联正式角色来源，也可使用作者提供的临时角色 |
| 确认 | 阅读开局包的来源依据和诊断，再确认开局 |

到“确认”这一步仍只是预览。来源无效或诊断阻断时，返回对应步骤修正，再重新预览；不要把预览成功当作会话已创建。

需要可比较的绝对世界时间时，在“入场”选择 **带时区的 ISO 日期时间**，填写带时区的时间，例如 `2026-10-07T09:00:00+08:00`。自然语言时间可以作为场景说明；到时自动触发的计划还必须明确使用 ISO 格式。世界面板会说明不能比较或尚未启用的时间触发。

[![引导开局的确认步骤，核对开局包的标题、身份、世界活跃度与来源依据](/screenshots/play-guided-review.jpg)](/screenshots/play-guided-review.jpg)

## 导入本地角色卡

在推演顶部点击 **导入角色卡**，选择本地 JSON 或 PNG 角色卡，再选择用途。

| 模式 | 结果 |
| --- | --- |
| 只用于推演 | 确认预览后创建独立推演会话，不创建小说角色文件 |
| 新建角色 | 预览新角色文件，创建待确认改动；在审阅中接受后写入 |
| 合并到已有角色 | 输入已有角色目录编号，保留已有正式资料，预览新增互动提示和世界书内容 |
| 只预览映射 | 只查看映射和风险提示 |

JSON 最大 1 MiB，PNG 最大 10 MiB；内嵌世界书最多 500 条、256 KiB。超限时先拆分或精简卡片。中文角色名可以保留，文件夹 ID 使用英文字母、数字、下划线或连字符；创建时可留空自动生成。

合并预览会列出被保留的原有事实。点击 **生成待确认改动** 后仍需进入 **审阅改动** 并接受。修改卡片、模式或编号后必须重新预览。“只用于推演”的预览在 15 分钟或后端重启后失效，已确认创建的会话可正常重开。

角色卡中的提示和世界书始终是外部参考，不能覆盖你的创作宪法或正式设定。Play-only 按当前场景和输入选择世界书条目，卡内的系统覆盖指令不会主动加入提示词。已导入正式角色的互动资料，可在 Guided Start 中明确选择 `interaction.md` 和 `lorebook.yaml`。

## 打开旧版会话

遇到旧格式时，Play 显示升级预览，包括回合数量、保留字段和备份位置。可以先展开旧对话只读查看，再点击明确的升级确认。升级使用原始文件备份；若预览后文件发生变化，需要重新预览，不能直接继续写入旧格式。

## 逐步完成场景试演

在试演工作区，左侧是角色行动顺序，中间是 **角色步骤**，右侧的场景检查器可查看感知、事件和场景记忆。

1. 点击 **开始试演** 开始一次尝试。
2. 点击 **生成当前角色步骤** 生成当前角色的反应。
3. 阅读台词、叙述和动作。满意时点击 **采用**；需要另一个版本时点击 **重演**。
4. 按需使用 **修改**、**插入角色** 或 **授予认知**，调整当前试演。
5. 检查已选步骤后点击 **完成试演**，在确认界面完成本次尝试；放弃本次尝试则选择 **取消**。

这里的 **采用** 只接受一个试演步骤。**完成试演** 才把所选步骤结算到推演会话；两者都不等于在全局审批面板中接受对小说文件的修改。下文的“审阅”指这一全局流程。

重演产生的旧版本不会全部进入最终结果。完成试演时使用当前选中的步骤序列。如果界面提示先前版本已被替代，检查留下的版本是否就是你需要的走向。

生成某一步时，想让这一步换个方向，可以在 **角色步骤** 下方的插话框输入一句话并点击 **插话**。正在重试的步骤会立刻停止，并按这句话重写原来的步骤；新步骤会先生成完，再按这句话重写。插话和 **修改** 里的“改变走向”是同一个操作，同样受角色感知范围的限制。

试演连续几步没有实质变化时，界面可能提示停滞。可以明确一个新的行动目标，也可以自然结束，不必为了继续运行而强加冲突。

[![场景试演工作区：左侧角色行动顺序，中间是刚生成、尚未提交的角色步骤，右侧场景检查器](/screenshots/play-rehearsal-steps.jpg)](/screenshots/play-rehearsal-steps.jpg)

生成的步骤下方是导演控制：**采用**、**修改**、**重演**、**插入角色**、**授予认知**、**完成试演** 和 **取消**。

## 用沉浸推演推进一回合

打开沉浸会话，在输入区选择行动类型：

| 操作 | 输入内容 |
| --- | --- |
| 说 | 想对角色说的话 |
| 看 | 想观察或调查的对象 |
| 走 | 想前往的地点或移动方式 |
| 做 | 想执行的行动 |
| 等 | 选择等待时长，可补充等待期间关注的事情 |

点击 **行动** 提交普通行动；“等”使用 **推进时间**。此输入区支持 `Cmd/Ctrl + Enter`。

### 候选行动

每个回合结束后，输入区上方会列出几条带编号的候选行动，方向各不相同。有三种用法：

- **直接选**：点击某一条，或在输入框之外按数字键 `1`–`9`，这条行动立即作为本回合行动提交。输入框里已有的草稿不会被清掉。
- **改一改**：点击该条右侧的 **改一改**，文本进入输入框，修改后照常提交。行动类型沿用这条候选项的类型，可以再改。
- **自己写**：点击列表末尾的 **自己写**，直接输入全新的行动。

每条前面标着行动类型（说、看、走、做、等）。等待类候选项写明了时长时会显示出来，可以直接选；没有写明时长的，点击后会进入输入框，先选时长再提交。回合生成中候选行动不可选。

候选行动由模型每回合给出，偶尔会缺失或不足。此时输入区会提示本回合没有候选行动，你可以直接写，也可以点 **生成候选项**。已经有候选行动但都不合适时，点 **换一批**。

**生成候选项 / 换一批** 是一次只读请求：裁判只按参与者已经知道的内容另给几条，不推进回合，也不保存。新的一批会替换显示中的候选行动，并标注“临时建议”；推进到下一回合、回到存档点或切换分支后就不再显示。生成期间输入区和其他操作暂时不可用，失败只显示原因，不影响会话。旧会话不需要升级也会开始给出候选行动。

生成中的叙述是临时结果。只有回合完成并结算后，世界时钟、事件和状态才成为这个分支的已记录结果。需要停止时使用 **停止** 按钮，并等待界面确认最终状态。

生成时输入区仍然可以输入：

- 点 **排队** 或按 `Cmd/Ctrl + Enter`，这条行动会排在本回合之后，本回合结算完成后自动发送。排队的行动可以编辑、删除、调整顺序。
- 点 **插话** 或按 `Alt + Enter`，本回合未结算的生成会被停止，然后把原行动加上这句补充重新生成。排队中的行动也可以点 **转为插话**。如果本回合已经在结算，插话会改为排在最前的下一条行动。
- 回合没有成功结算、会话被其他操作改动、来源内容有变化需要你决定时，排队会暂停，处理后点 **继续发送**。

在 **世界线** 中可查看存档点、命名、**回到这里** 或 **重演**。回到这里与重演改变当前推演路线，不是回滚小说的 Git 历史。

### 带要求重演

对某一回合的结果不满意时，在世界线里点该回合的 **重演**。确认框中有一栏“这次希望有什么不同（可选）”，例如“别让她这么快妥协”“让对话更紧张一些”，最多 500 字。

- 行动本身不变：重演使用原回合的行动文本和类型，只按你写的要求重新裁定这一回合。
- 要求只用于这一次重演，不会带到之后的回合。
- 新结果和旧结果是同一回合下的两个分支，旧结果保留为“保留的另一结果”，可以随时回到那里。
- 要求会记在新结果上。在导演视角下，世界线会在该存档点下显示“重演要求（导演视角）”，方便日后知道这条分支为什么不同；参与者视角不显示。
- 不写要求直接确认，就是普通重演。

## 理解参与者视角与导演视角

**参与者视角** 按参与者可见的信息展示内容，**导演视角** 用于作者检查更完整的世界信息，包括重演要求。传闻、未知事实和隐藏事件应按它们原有的不确定性理解。

切换到导演视角不会让场内角色知道秘密。需要在试演中赋予认知时，使用对应的导演控制，并核对授予对象与依据。

上下文检查区可查看来源与变动。正式文件后来发生变化时，旧会话可能提示来源漂移。先查看提示，再通过界面提供的选择处理；不要默认旧会话已自动读取最新的设定。

Play 主界面不显示模型的思考过程。需要排查某一回合为什么这样发展时，点击检查区里的 **打开消息日志**：这里按时间列出你的行动、发给模型的完整请求、思考过程、原始输出以及回合是否提交，可按类型和角色筛选。日志只用于调试，保存在工作区 `.oan/sessions/` 下且不进入 Git，删除它不影响会话。

## 把推演结果带回写作

沉浸推演的 **观察笔记 → 记一条观察笔记** 可以记录作者自己的发现：选择一条已提交的来源消息，填写摘要和依据，再保存。未完成的生成内容不能作为来源。保存只增加推演内的笔记，之后仍通过 **带回写作** 准备正式修改。

先结束或取消当前试演尝试，然后在 **结果报告** 点击 **生成报告**。报告只总结当前所选、已经完成的分支，不包含未选择的替代版本和生成中的草稿。

如果报告显示 **报告已过期**，先刷新或重新生成。当前报告失效时，依赖报告的操作会被禁用。

### 方式一：作为下一次写作请求的参考

1. 在结果报告中勾选需要的条目（**作为写作参考**）。
2. 点击 **附加为写作参考**。
3. 切回 **Writing**，在 Copilot 的 **Play Writing References** 中勾选附件。
4. 写明要如何使用，例如「借用这次试演中和解失败的原因，重写当前章节的争执场景」，再发送请求。

附件只用于下一次请求；发送成功或切换对话后，选择会清空。创建附件不会修改正文，后续生成的小说修改仍要经过[审阅与批准](./review.md)。

### 方式二：准备正式文件的采纳提案

1. 从事件、观察笔记或结果条目点击 **带回写作**。
2. 在 **写到哪里** 选择：章节草稿、状态、时间线或伏笔。
3. 按表单填写。每个目标都有自己的字段，不需要手写 JSON：

   | 目标 | 表单 |
   | --- | --- |
   | 章节草稿 | 标题（可选）、正文、写入方式；目标章节由系统推导，只读显示 |
   | 状态 | 状态文件、对象路径，以及可增删的“字段 / 新值”多行 |
   | 时间线 | 世界内时间、事件、参与者（用顿号或逗号分隔）、地点 |
   | 伏笔 | 伏笔描述、埋设位置、预期回收条件 |

   填写有误时，提示会出现在对应字段下方，修正前不能预览。需要排查时展开 **查看 JSON**，看到的是将要提交的数据，只读。
4. 点击 **预览改动**，核对目标文件和完整 diff。系统会对内容做格式整理（例如章节草稿没有标题时补一行标题），表单随之更新为预览中的内容。
5. 点击 **确认并创建待确认改动**，再点 **去审阅**。
6. 在全局审阅中 **接受**，正式文件才会改变。

在推演中点击 **审阅改动 / 去审阅** 会打开旁边的共享审批抽屉，保留当前会话。关闭后可用顶栏 **Pending actions** 重开；接受、拒绝和需要时的快速提交都在该面板完成。

修改目标或任何字段后需要重新预览。若预览报错，根据具体提示修改，不要直接把推演对话粘进结构化文件。

[![带回写作的时间线表单：填写世界内时间、事件、参与者与地点，右侧是实际 diff](/screenshots/play-adoption-form.jpg)](/screenshots/play-adoption-form.jpg)

## 生成中断后

网络中断或窗口重新连接时，先按页面的恢复提示核实服务端状态。出现回合结果未知、需要刷新或需要恢复角色步骤的提示时，完成恢复后再继续生成。重试前先确认上一次是否已经完成，避免把同一个行动提交两次。

保留具体错误信息和会话名称，便于区分模型配置问题、来源变化与生成中断。通用排查见[常见问题](./faq.md)。

## 视觉小说演出

在沉浸推演主区域点击 **视觉小说演出**，将当前叙述按节拍显示。场景试演提供 **视觉小说回放**，用于查看已提交内容，不在这个回放中接受试演步骤。

- 空格或 Enter：先显示当前句全文，再推进下一句；在输入框打字不会触发该快捷键。
- 到达最后一拍后，行动选项出现在中央，可点击或按数字 `1`–`9` 直接选。每条旁边的 **改一改** 和末尾的 **自己写** 会打开输入框，`Cmd/Ctrl + Enter` 确定，`Esc` 取消；在输入框里按数字键只是输入文字。生成中、历史回看或其他操作占用时不会提交选择。没有写明时长的等待选项会带你回到推演工作台选择时长。
- **历史**：查看历史文本；已有更早分页时可以继续加载。点击回看按那条消息保存的场景与角色呈现。
- **返回推演工作台**：回到原来的文本、历史控制与输入框。重演、回到这里、停止、插话与排队仍使用工作台的原有控制。

流式文字只在草稿层演出，提交前不会改动旧分支快照。系统会尝试从中文引语及名册别名识别说话人；无法确定时作为旁白或无名字对白显示。它是启发式识别，仍可能需要作者检查。已启用系统减少动态效果偏好时，文字直接显示；格式标签作为安全文本呈现，不执行 HTML。

### 本地角色图与场景图

角色可在 `characters/<角色ID>/roster-profile.yaml` 中提供标准名、别名、外貌和衣着信息，并用 `looks.refImagePath` 指向工作区内的 PNG/JPEG/WebP 图片。名册还可保存预留声线参数，但不会调用 TTS。

场景图使用 `world/places/<场景ID>.png`（或 `.jpg`、`.jpeg`、`.webp`）。当公开的 Play 当前场景值与文件名中的场景 ID 完全匹配时显示该图；例如当前场景为 `station`，对应 `world/places/station.png`。没有图片时使用日间、黄昏或深夜的颜色背景。

图片在会话初始化时读取一次并保存在会话里，各回合的快照只记录场景 ID 和在场角色，不会重复保存图片；后来替换图片不会改变已有会话。舞台只显示本回合叙述中出现或说话的名册角色，名字牌显示角色的标准名。单张图片上限 256 KiB，角色图和场景图各最多读取 12 张（场景图优先读取开场场景，多出的会被跳过，不会导致创建失败；同一场景 ID 有多张图片时该场景不显示背景）；不接受符号链接、工作区外路径或 SVG。此功能读取你提供的本地图，不会自动生成图片，也没有背景图上传界面。新增名册时仍需保证 ID 与角色目录一致。

## 剧情归档与开启新阶段

沉浸会话有已提交回合后，可点击 **剧情归档**。这会调用模型提炼人物、经过、未完的线、当前场景和文风，并与选中分支的事实引文、资源状态核对。

1. 等待归档预览，检查五个部分及可展开的资源状态。
2. 核验失败时系统最多请求一次定向修正；仍不通过会显示错误，可重新生成。
3. 确认后点击 **确认存档并开启新阶段**，建立独立会话并带入存档与最近两轮原文。
4. 不想继续时关闭窗口。关闭不会创建新阶段，也不会修改小说文件；已经生成的预览可能保留供恢复使用。

旧会话仍可查看。新阶段保留不可变历史引用以维持事件与状态的一致性，只缩减模型需要读取的旧历史。原分支在预览后发生变化时，必须重新生成归档；不会把过期存档接到新分支上。重复确认同一份存档会返回同一个新会话。

“经过”是按时间提炼的关键事实，每条附一小段能在选中分支历史里逐字找到的原文作为依据。当前状态里记录了的人物处境、关系和场景字段必须照抄当前状态，旧历史不能证明角色现在仍健康或仍有旧存量；当前状态没有记录的字段可以从历史提炼，但该人物或场景必须附逐字原文，否则显示“未记录”（人物列表为空表示未记录）。开场地点不会被当作当前地点兜底；若剧情已经移动却未记录当前位置，会显示“未记录”。当前人物证据取自 `characters[角色名]`，场景证据取自 `currentScene` 的对应字段（或同名顶层字段），未结线索取自 `unresolvedThreads` 并同时要求历史逐字引文；字段缺失不从旧叙述推断。完整资源状态仍逐项保留并可展开核对；此检查不等于模型对任意自然语言状态的语义证明。

归档由你手动发起，不会按回合数自动压缩。它仅整理 Play 会话；要纳入小说仍需使用写作参考或正式审批采纳。

## 会话的固定设定与缓存

新沉浸会话会保存固定叙述规则、裁判结算协议、玩家身份及常驻设定；连续回合使用同一份系统前缀。已提交的历史作为之前的消息只追加发送，约每 10 个回合才整体前移一次，期间前缀逐字节不变；本轮消息只带本轮新增的世界设定、当前状态、本轮要求和你的行动，不重复固定规则、已冻结的来源或历史。已有来源漂移提示和选择仍然有效。

这为支持自动前缀缓存的模型提供稳定输入，但缓存是否命中、费用和延迟取决于服务商。选择 Anthropic 提供方时，系统前缀与最近一条稳定回复会附加显式缓存断点；最新行动与动态状态不加断点。实际命中还受服务商的最小长度和缓存有效期限制，尚未验证“降本 80%”等收益。修改正式文件不会悄悄改写旧会话的冻结系统前缀；需要更换常驻事实时，请重新创建并选择最新来源。

需要从想法生成角色与舞台时，可使用 [设定共创工坊](forge.md)，审查入库后直接开演。
