# Play：先试演，再带回写作

Play 用来试走角色的行动、对话和事件后果。你可以先在独立会话里验证一场戏，再选择有用的结果带回 Writing。

Play 中的行动结果、角色认知和分支都属于该会话。它们不会自动改写正式章节、人物状态或时间线。

[![Play 工作区初始状态，左侧可点击 New session 新建会话](/screenshots/play.jpg)](/screenshots/play.jpg)

## 选择开局方式

从工作台顶部切换到 **Play**，在左侧创建一个新 session。先选择用途，再选择开局方式。

| 选择 | 适用场景 |
| --- | --- |
| Scene Rehearsal | 作为作者安排一场戏，逐个检查角色反应，必要时介入调整 |
| Immersive Journey | 以参与者身份进入世界，通过说话、观察、行动和等待推进 |
| Quick Start | 自己填写开场和角色信息，用较短流程开始 |
| Guided Start | 从真实工作区文件选择资料，确认来源与角色后再开始 |

尚未配置模型时，可以浏览已有会话；生成真实角色步骤或 Play 回合前需要完成[模型配置](./settings.md)。

[![创建 Play 会话时选择 Immersive Journey 或 Scene Rehearsal](/screenshots/play-new-session.jpg)](/screenshots/play-new-session.jpg)

## 用 Quick Start 准备一场戏

选择 **Scene Rehearsal → Quick Start**，依次填写三个步骤。

1. **Scene**：填写 Scene title、Location、Opening situation 和 Rehearsal objective。Risk 与 Atmosphere 用来补充风险和氛围，World activity 与 Event density 决定世界活动与事件密度。
2. **Cast**：添加参与角色，填写 Name、Position、Current goal 和 Initial knowledge。列表顺序就是初始角色行动队列，可上下调整。
3. **Review**：核对场景和角色后确认创建。

Quick Start 的 **Event settings** 可设置是否允许场外事件、隐藏事件，以及每回合 0–6 个自发外部事件。设为 0 仍会结算已到期的计划事件。沉浸模式的快速创建表单也提供这些设置。

例如，开场可以写「暴雨封桥，两名旧识在渡口争夺最后一艘船」，试演目标写「验证双方是否会在不直接坦白秘密的情况下合作」。在 Initial knowledge 中分别写清每个人知道什么，能减少角色凭空知情的情况。

这些表单内容是你为本次试演提供的材料。创建场景不会把新角色写入正式角色档案。

[![Quick Start 的 Scene 表单，填写场景标题、地点、开场与试演目标](/screenshots/play-scene-setup.jpg)](/screenshots/play-scene-setup.jpg)

## 用 Guided Start 对齐现有小说

选择 **Guided Start**，按下面五步准备：

| 步骤 | 要检查的内容 |
| --- | --- |
| Sources | 勾选当前工作区已有的文件，确认它们与这次试演相关 |
| Entry | 填写开场、地点、时间、触发事件、目标与风险，选择支持开场的来源 |
| Identity | 沉浸模式填写 Player persona；试演模式填写 Director rehearsal purpose |
| Cast | 核对参与者、目标、位置、初始认知；可关联真实角色来源，也可使用作者提供的临时角色 |
| Review | 阅读 Launch Package 的来源证据和诊断，再确认开局 |

到 Review 仍只是预览。来源无效或诊断阻断时，返回对应步骤修正，再重新预览；不要把预览成功当作会话已创建。

需要可比较的绝对世界时间时，在 Entry 选择 **ISO date-time with timezone**，填写带时区的时间，例如 `2026-10-07T09:00:00+08:00`。自然语言时间可以作为场景说明；到时自动触发的计划还必须明确使用 ISO 格式。World HUD 会说明不能比较或尚未启用的时间触发。

## 导入本地角色卡

在 Play 顶部点击 **Import character**，选择本地 JSON 或 PNG 角色卡，再选择用途。

| 模式 | 结果 |
| --- | --- |
| Play only | 确认预览后创建独立试演会话，不创建小说角色文件 |
| Create a new character | 预览新角色文件，创建待审批修改；到 Review 中 Accept 后写入 |
| Merge into an existing character | 输入已有角色文件夹 ID，保留已有正式资料，预览新增互动提示和世界书内容 |
| Preview mapping only | 只查看映射和风险提示 |

JSON 最大 1 MiB，PNG 最大 10 MiB；内嵌世界书最多 500 条、256 KiB。超限时先拆分或精简卡片。中文角色名可以保留，文件夹 ID 使用英文字母、数字、下划线或连字符；创建时可留空自动生成。

合并预览会列出被保留的原有事实。点击 **Create changes for approval** 后仍需进入 **Review changes** 审阅并 Accept。修改卡片、模式或 ID 后必须重新预览。Play-only 预览在 15 分钟或后端重启后失效，已确认创建的会话可正常重开。

角色卡中的提示和世界书始终是外部参考，不能覆盖你的创作宪法或正式设定。Play-only 按当前场景和输入选择世界书条目，卡内的系统覆盖指令不会主动加入提示词。已导入正式角色的互动资料，可在 Guided Start 中明确选择 `interaction.md` 和 `lorebook.yaml`。

## 打开旧版会话

遇到旧格式时，Play 显示升级预览，包括回合数量、保留字段和备份位置。可以先展开旧对话只读查看，再点击明确的升级确认。升级使用原始文件备份；若预览后文件发生变化，需要重新预览，不能直接继续写入旧格式。

## 逐步完成 Scene Rehearsal

在试演工作区，左侧是角色队列，中间是 **Actor Steps**，旁边可检查感知、事件和场景记忆。

1. 点击 **Begin rehearsal attempt** 开始一次尝试。
2. 点击 **Generate current actor step** 生成当前角色的反应。
3. 阅读对白、叙述和行动。满意时点击 **Accept**；需要另一个版本时点击 **Retry**。
4. 按需使用 **Modify**、**Insert actor** 或 **Grant knowledge**，调整当前试演。
5. 检查已选步骤后点击 **Finish**，在确认界面完成本次尝试；放弃本次尝试则选择 **Cancel**。

这里的 **Accept** 只接受一个试演步骤。**Finish** 才把所选步骤结算到 Play 会话；两者都不等于全局审批面板 **Approval** 中批准修改小说文件。下文的 Review 指向这一全局审阅流程。

重试产生的旧版本不会全部进入最终结果。Finish 使用当前选中的步骤序列。如果界面提示先前版本已被替代，检查留下的版本是否就是你需要的走向。

生成某一步时，想让这一步换个方向，可以在 **Actor Steps** 下方的插话框输入一句话并点击 **插话**。正在重试的步骤会立刻停止，并按这句话重写原来的步骤；新步骤会先生成完，再按这句话重写。插话和 **Modify** 里的重定向是同一个操作，同样受角色感知范围的限制。

试演连续几步没有实质变化时，界面可能提示停滞。可以明确一个新的行动目标，也可以自然结束，不必为了继续运行而强加冲突。

## 用 Immersive Journey 推进一回合

打开沉浸会话，在输入区选择行动类型：

| 操作 | 输入内容 |
| --- | --- |
| Say | 想对角色说的话 |
| Look | 想观察或调查的对象 |
| Move | 想前往的地点或移动方式 |
| Do | 想执行的行动 |
| Wait | 选择等待时长，可补充等待期间关注的事情 |

点击 **Act** 提交普通行动；Wait 使用 **Advance**。此输入区支持 `Cmd/Ctrl + Enter`。建议行动按钮会填入输入框，你仍可修改后再发送。

生成中的叙述是临时结果。只有回合完成并结算后，世界时钟、事件和状态才成为这个 Play 分支的已记录结果。需要停止时使用可用的 **Stop** 按钮，并等待界面确认最终状态。

生成时输入区仍然可以输入：

- 点 **排队** 或按 `Cmd/Ctrl + Enter`，这条行动会排在本回合之后，本回合结算完成后自动发送。排队的行动可以编辑、删除、调整顺序。
- 点 **插话** 或按 `Alt + Enter`，本回合未结算的生成会被停止，然后把原行动加上这句补充重新生成。排队中的行动也可以点 **转为插话**。如果本回合已经在结算，插话会改为排在最前的下一条行动。
- 回合没有成功结算、会话被其他操作改动、来源内容有变化需要你决定时，排队会暂停，处理后点 **继续发送**。

在历史控制中可查看检查点、重命名、恢复或重试。恢复与重试改变所选 Play 路线，不是回滚小说的 Git 历史。

## 理解 Player 与 Director 视角

**Player** 按参与者可见的信息展示内容，**Director** 用于作者检查更完整的世界信息。传闻、未知事实和隐藏事件应按它们原有的不确定性理解。

切换到 Director 不会自动让场内角色知道秘密。需要在试演中赋予认知时，使用对应的导演控制，并核对授予对象与依据。

上下文检查区可查看来源与变动。正式文件后来发生变化时，旧会话可能提示来源漂移。先查看提示，再通过界面提供的选择处理；不要默认旧会话已自动读取最新的设定。

Play 主界面不显示模型的思考过程。需要排查某一回合为什么这样发展时，点击检查区里的「打开消息日志」：这里按时间列出你的行动、发给模型的完整请求、思考过程、原始输出以及回合是否提交，可按类型和角色筛选。日志只用于调试，保存在工作区 `.oan/sessions/` 下且不进入 Git，删除它不影响会话。

## 把试演结果带回 Writing

沉浸会话的 **Observations → Add observation** 可以记录作者自己的发现：选择一条已提交的来源消息，填写摘要和依据，再保存。未完成的生成内容不能作为来源。保存只增加 Play 笔记，之后仍通过 **Bring to writing** 准备正式修改。

先结束或取消当前试演尝试，然后在 **Outcome Report** 点击 **Generate report**。报告只总结当前所选、已经完成的分支，不包含未选择的替代版本和生成中的草稿。

如果报告显示 **Report stale**，先刷新或重新生成。当前报告失效时，依赖报告的操作会被禁用。

### 方式一：作为下一次写作请求的参考

1. 在 Outcome Report 中选择需要的条目。
2. 在 **Use as Writing Reference** 中点击 **Create attachment**。
3. 切回 **Writing**，在 Copilot 的 **Play Writing References** 中勾选附件。
4. 写明要如何使用，例如「借用这次试演中和解失败的原因，重写当前章节的争执场景」，再发送请求。

附件只用于下一次请求；发送成功或切换对话后，选择会清空。创建附件不会修改正文，后续生成的小说修改仍要经过[审阅与批准](./review.md)。

### 方式二：准备正式文件的采纳提案

1. 从事件、观察或结果条目进入 **Bring to writing**。
2. 选择 **Canonical target**：Chapter draft、State、Timeline 或 Foreshadow。
3. 检查系统建议的目标与内容。当前表单使用 **Editable JSON payload** 表达待采纳数据，修改时保留合法的 JSON 对象格式。
4. 点击 **Preview canonical diff**，核对目标文件和完整差异。
5. 点击 **Confirm and create PendingAction**，再进入 **Review PendingAction**。
6. 在全局 Review 中 **Accept**，正式文件才会改变。

在 Play 点击 **Review changes / Review PendingAction** 会打开旁边的共享审批抽屉，保留当前会话。关闭后可用顶栏 **Pending actions** 重开；Accept、Reject 和需要时的 Quick commit 都在该面板完成。

修改目标或 payload 后需要重新生成预览。章节、状态、时间线和伏笔各有自己的格式约束；若预览报错，根据具体提示修改，不要直接把 Play 对话粘进结构化文件。

## 生成中断后

网络中断或窗口重新连接时，先按页面的恢复提示核实服务端状态。出现回合结果未知、需要刷新或 actor-step recovery 的提示时，完成恢复后再继续生成。重试前先确认上一次是否已经完成，避免把同一个行动提交两次。

保留具体错误信息和会话名称，便于区分模型配置问题、来源变化与生成中断。通用排查见[常见问题](./faq.md)。

## 视觉小说演出

在沉浸推演主区域点击 **视觉小说演出**，将当前叙述按节拍显示。试演模式提供 **视觉小说回放**，用于查看已提交内容，不在这个回放中接受试演步骤。

- 空格或 Enter：先显示当前句全文，再推进下一句；在输入框打字不会触发该快捷键。
- 到达最后一拍后，行动选项出现在中央，可点击或按数字 `1`–`9`。生成中、历史回看或其他操作占用时不会提交选择。
- **Log · 历史**：查看历史文本；已有更早分页时可以继续加载。点击回看按那条消息保存的场景与角色呈现。
- **返回推演工作台**：回到原来的文本、历史控制与输入框。Retry、Restore、Stop、插话与排队仍使用工作台的原有控制。

流式文字只在草稿层演出，提交前不会改动旧分支快照。系统会尝试从中文引语及名册别名识别说话人；无法确定时作为旁白或无名字对白显示。它是启发式识别，仍可能需要作者检查。已启用系统减少动态效果偏好时，文字直接显示；格式标签作为安全文本呈现，不执行 HTML。

### 本地角色图与场景图

角色可在 `characters/<角色ID>/roster-profile.yaml` 中提供标准名、别名、外貌和衣着信息，并用 `looks.refImagePath` 指向工作区内的 PNG/JPEG/WebP 图片。名册还可保存预留声线参数，但不会调用 TTS。

场景图使用 `world/places/<场景ID>.png`（或 `.jpg`、`.jpeg`、`.webp`）。当公开的 Play 当前场景值与文件名中的场景 ID 完全匹配时显示该图；例如当前场景为 `station`，对应 `world/places/station.png`。没有图片时使用日间、黄昏或深夜的颜色背景。

图片在会话初始化时读取并随叙述快照冻结，后来替换图片不会改变旧回合。单张图片上限 256 KiB，角色图和场景图各最多读取 12 张；不接受符号链接、工作区外路径或 SVG。此功能读取你提供的本地图，不会自动生成图片，也没有背景图上传界面。新增名册时仍需保证 ID 与角色目录一致。

## 剧情归档与开启新阶段

沉浸会话有已提交回合后，可点击 **剧情归档**。这会调用模型提炼人物、经过、未完的线、当前场景和文风，并与选中分支的事实引文、资源状态核对。

1. 等待归档预览，检查五个部分及可展开的资源状态。
2. 核验失败时系统最多请求一次定向修正；仍不通过会显示错误，可重新生成。
3. 确认后点击 **确认存档并开启新阶段**，建立独立会话并带入存档与最近两轮原文。
4. 不想继续时关闭窗口。关闭不会创建新阶段，也不会修改小说文件；已经生成的预览可能保留供恢复使用。

旧会话仍可查看。新阶段保留不可变历史引用以维持事件与状态的一致性，只缩减模型需要读取的旧历史。原分支在预览后发生变化时，必须重新生成归档；不会把过期存档接到新分支上。重复确认同一份存档会返回同一个新会话。

归档由你手动发起，不会按回合数自动压缩。它仅整理 Play 会话；要纳入小说仍需使用写作参考或正式审批采纳。

## 会话的固定设定与缓存

新沉浸会话会保存固定叙述规则、玩家身份及常驻设定；连续回合使用同一份系统前缀，临时来源、当前状态和行动放在本轮消息中。已有来源漂移提示和选择仍然有效。

这为支持自动前缀缓存的模型提供稳定输入，但缓存是否命中、费用和延迟取决于服务商。当前没有 Anthropic 专用缓存适配，也没有验证“降本 80%”等收益。修改正式文件不会悄悄改写旧会话的冻结系统前缀；需要更换常驻事实时，请重新创建并选择最新来源。

需要从想法生成角色与舞台时，可使用 [设定共创工坊](forge.md)，审查入库后直接开演。
