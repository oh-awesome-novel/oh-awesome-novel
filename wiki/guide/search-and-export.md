# 搜索与导出

工作区搜索可以定位正文中的一句话、人物名或设定；正文导出可以把已保存章节合并为 Markdown 或 TXT 文件。这两项操作读取本地文件，不需要模型，也不会改写小说工程。

## 搜索正文、标题与路径

1. 进入工作区的 `Writing` 模式，点击顶部放大镜图标 `Search`。
2. 在「搜索正文、标题或路径」输入框中输入关键词，例如角色名、`十年前` 或 `chapters/0001`。
3. 输入后稍等，或按 Enter 立即查询。界面显示匹配文件数、已扫描文件数与扫描时间。
4. 查看结果中的文件名、路径、首个命中行号和文字片段。
5. 点击结果。搜索窗口关闭，左侧文件树选中该文件，右侧 `File` 打开并滚动、高亮对应行。

搜索不会自动发送 Copilot 请求，也不会把结果自动附为聊天素材。找到需要修改的文件后，再按 [写作与 Copilot](writing.md) 明确提出本轮要求。

搜索弹窗支持 Tab 切换输入框、结果与按钮，Esc 关闭。

### 怎样输入更容易找到

搜索按连续文字匹配，英文不区分大小写，支持连续汉字以及中英文混排。例如 `林照` 可以找到该人物的提及，`AI助手` 可以匹配正文中的同样文字。

它不提供语义搜索、正则表达式或多个独立关键词的组合查询。输入一整句话却没有命中时，缩短为其中连续的一段；不要把换行两侧的文字合成一句去搜索。

每个文件只显示第一个正文命中位置。如果仅文件名或路径命中，打开的是该文件第一行。命中文件超过 100 个时，会提示「仅显示前 100 个匹配文件」；此时缩短结果范围，例如改用更具体的短语。

### 搜索范围

搜索以下位置中的 Markdown、YAML 和 TXT 文本：

| 位置 | 内容 |
| --- | --- |
| `chapters/` | 正文章节和卷信息 |
| `characters/`、`world/` | 人物和世界设定 |
| `state/`、`timeline/`、`foreshadow/` | 当前状态、事件与伏笔 |
| `summaries/`、`outline/` | 摘要与规划 |
| `.oan/constitution/`、`.oan/workflow.yaml` | 指定的创作约束和工作流文件 |

搜索不包括其他工作区、Git 历史、内部审批数据、聊天记录、参考资料、Play 会话或模型凭据。启动器的项目搜索只用来找工作区，不是这里的正文搜索。

### 文件修改后刷新

每次查询都会重新读取已保存文件。外部编辑、删除或重命名之后，先在编辑器保存，再点击「刷新结果」。接受 AI 修改后，应用也会刷新相关状态。

如果你在查询后又修改了文件，之前显示的行号可能不再对应原位置，重新查询即可。一次扫描会依次读取多个文件；需要核对某个固定版本时，先完成并保存当前编辑，再查询。

## 导出整本正文

1. 保存外部编辑器中的正文；需要包含 AI 修改时，先在 `Approval` 中接受它。
2. 在 `Writing` 顶部工具栏点击下载图标 `Export manuscript`。
3. 在「导出正文」窗口阅读包含范围，选择「下载 Markdown」或「下载 TXT」。
4. 等待「已发起下载」提示，核对其中的章节数和文件名。
5. 按浏览器或应用的下载提示保存，再打开下载文件检查内容。

导出只读取已经存在于磁盘的章节，不要求这些章节已经提交到 Git。外部编辑器里未保存的文字，以及尚未接受的 AI 草稿，不会进入导出结果。

[![导出正文窗口中的下载 Markdown、下载 TXT 按钮和导出范围说明](/screenshots/manuscript-export.jpg)](/screenshots/manuscript-export.jpg)

### 导出哪些章节

导出读取 `chapters/NNNN/NNNN.md` 形式的四位编号文件，按卷号、章节号排列。例如：

```text
chapters/0001/0001.md
chapters/0001/0002.md
chapters/0002/0001.md
```

每卷的 `0000.md` 属于卷信息，会被排除。各章开头的 YAML 元数据也会去除，正文中的章节标题保留。

导出不包括摘要、角色卡、设定、大纲、参考资料或 Play 内容；不符合上述编号路径的稿件，也不会作为正文章节加入。

### Markdown 与 TXT 的区别

| 格式 | 导出效果 | 适合用途 |
| --- | --- | --- |
| Markdown（`.md`） | 保留正文格式，各章之间加入分隔线 | 继续在 Markdown 编辑器中校对或排版 |
| TXT（`.txt`） | 去掉 `#` 等 Markdown 标题前缀，各章之间留空行 | 以文本形式阅读或交给后续处理工具 |

TXT 会保留正文中的 `**加粗**`、链接等 Markdown 标记；它不是将所有 Markdown 格式转换成纯排版文本。当前直接下载格式为 Markdown 和 TXT，需要 Word、PDF 或 EPUB 时，可以将导出文件交给对应的编辑或排版工具。

### 下载位置与文件名

下载文件名带生成时间，例如 `manuscript-2026-10-02T03-04-05-000Z.md`。保存位置和同名文件的处理方式由浏览器的下载设置或保存对话框决定。

导出窗口不要求填写工程内的目标路径，也不会覆盖你的原始章节文件。「已发起下载」后仍需查看下载状态，确认文件确实保存成功。

### 导出失败时

先检查 `chapters/` 是否包含已保存且符合四位编号规则的正文。如果只有 `0000.md` 卷信息，或内容仍在聊天和待审批项里，还没有可导出的章节。

若章节开头有 YAML 元数据，请确认开头的 `---` 与结束标记成对存在。链接文件、二进制数据、非 UTF-8 文本或过大的文件也会使导出失败；错误不会被当作“导出成功但少了几章”。

## 读取限制

搜索和导出都对读取范围设有限制：单个文本文件最多 2 MiB，一次扫描的文本总量最多 32 MiB，目录条目最多 10,000 个，嵌套深度最多 24 层。遇到超限、链接文件或读取过程中变化的文件时，会显示错误，而不是把部分内容当作完整结果。

正文很长时，按章节拆分保存更便于搜索、审阅和导出。出现错误时先处理提示涉及的文件，再重新查询或下载；其他常见情况见 [常见问题](faq.md)。
