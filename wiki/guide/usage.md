# 上下文与用量

Copilot 的「上下文与用量」帮助你核对一轮写作请求用了哪些来源、预算是否足够，以及模型服务返回了多少 token。它是只读检查面板，不会修改小说文件，也不是服务商账单。

## 打开统计面板

1. 配置可用 Provider，进入工作台的 Writing 模式。
2. 在 Copilot 消息区下方点击「上下文与用量」。有记录时，入口文字会变为模型调用次数、约多少 tokens 与 Actual 状态。
3. 「查看会话」保持 **当前对话 · 实时**，观察正在进行的请求；或选择带时间和 ID 的历史会话。
4. 点击 **刷新历史** 获取最新会话列表，或重新读取当前选中的历史统计。

新对话还没有调用模型时，会显示「此会话暂无用量记录」。发送请求后先出现估算，实际用量要等模型返回；一轮请求中使用工具后再次调用模型，会有多个步骤。

## 区分 Estimated 与 Actual

| 标签 | 含义 |
| --- | --- |
| Estimated | OAN 在本机计算的 token 估算，用于预算和比较 |
| Actual / actual | 模型服务返回的输入、输出和总 token 数；不来自本地估算 |
| partial | 仅拿到部分字段或部分步骤的数据，合计不完整 |
| unavailable | 没有获得这一字段或步骤的实际用量，不能当作 0 |
| 本轮合计 · Actual complete | 本轮各步骤都提供了输入、输出和总量；缓存或 reasoning 字段仍可能缺失 |

例如，「输入覆盖 2/3 步」表示三次模型调用只有两次提供了输入 token 数据。显示的输入合计只是已知部分，不能据此计算完整费用。

输入、输出、总计、缓存读取、缓存写入和 reasoning 各自显示可获得的数字。reasoning 只是服务返回的数量统计，面板不展示模型的内部推理文本。

当前没有单价表、费用换算或账单对账。即使实际用量完整，也应以服务商账单确定费用。请求失败或被停止后，若服务没有返回用量，显示 unavailable 也不代表服务端没有产生用量。

## 看每一步的预算

展开「第 N 步」，可以看到该次模型调用的估算、预算和结果状态。

| 预算提示 | 说明 |
| --- | --- |
| 预算范围内 | 当前估算没有超过已知输入预算，仍不等于精确 tokenizer 测量 |
| 模型上下文预算未知 | 缺少完整容量或输出预留等信息；继续记录估算，不假定一个虚构上限 |
| 必要上下文超出预算；请求未发送 | 在本步调用模型前停止，避免静默删掉必要内容 |

估算按消息和工具定义计算，并加入 20% 余量；它不包含模型服务内部不可见的封装开销。因此 Estimated 与 Actual 输入数字不必相等。

本轮入口显示的估算合计可以累加多次模型调用。同一份背景在多个步骤中再次发送时，会再次计入输入；本轮合计不是一次请求所需的上下文窗口大小，应逐步查看预算。

## 核对来源和省略原因

在某一步展开「N 个来源及省略记录」，查看文件路径、用途、选择结果和原因。

| 来源状态 | 如何理解 |
| --- | --- |
| 已选入消息 | 该来源已映射到本次组装的消息，不代表原文件的每个字都原样发送 |
| 已压缩来源 | 使用已有摘要、蒸馏结果等派生内容，应结合来源和用途理解 |
| 已省略 | 本次消息未纳入该来源；原因可能是预算、上下文选择范围或仅声明而未映射 |
| 已排除 | 根据规则排除的来源，不进入本次模型消息 |

`protected` 表示不能为了满足预算而静默截断的必要内容；`compressible` 允许使用已有摘要或按预算省略。已知预算不足时，会先从允许省略的内容中减少输入，必要内容仍超限则停止本步请求。

点击可用的来源路径，会在文件查看器打开该文件。部分路径只标为「来源记录」，没有跳转按钮；来源较多时点击 **继续显示来源**。

`source` 短 hash 标识来源内容版本，`payload` 短 hash 标识组装后消息内容版本。它们用于核对来源是否变化，不是文字内容。查看器打开的是当前文件，不能把后来修改过的文件误认为当时发出的内容。

看到「工具读取后派生输出」或 `derived` 时，说明工具读过该来源，并由此形成返回内容。它不证明全文都发给了模型。无法精确分摊到单个来源的 token 会计入消息估算，来源上显示 0 也不等于这次工具返回没有消耗上下文。

来源分类的小计用于理解构成，不应再次加到整步 Estimated 上。需要看完整消息规模时，展开「N 条消息估算」，按 system、user、assistant、tool 检查各条消息数量与估算。

## 检查 Provider、Model 与 Endpoint

每一步的发送前摘要显示 Provider、Model 和 Endpoint。Endpoint 只展示协议、主机和端口，不展示请求路径、查询参数、API Key 或请求头值。

这是准备请求时的摘要，不能单凭它证明网络请求已送达或模型已成功执行。应结合预算是否溢出、步骤状态与实际用量判断结果。

云端或远端 Provider 会收到实际模型请求所需的内容；本面板的无正文记录不意味着模型请求也没有正文。Ollama 同样应按实际 Endpoint 判断是否运行在本机。

## 上下文过大时怎么处理

### 章节摘要与状态是否仍有效

章节整理会记录当时正文的内容 hash。之后正文发生变化时，健康提示和上下文选择会区分以下状态；只改变文件修改时间不会被当成剧情变化。

| 来源状态 | 含义与处理 |
| --- | --- |
| current | 当前证据与正文内容版本及可检查引文一致；仍需作者判断解释是否准确 |
| stale | 正文内容已经改变；先核对改稿，再重新「整理本章」 |
| missing | 对应摘要或章级证据不存在 |
| unverified | 手写摘要没有来源记录，或记录缺失、被修改、相互矛盾；不能声称已验证 |

手写摘要仍可作为明确标记的参考。已经过期或损坏的结算证据不会自动作为当前事实放入默认摘要上下文。重新整理也不会自动撤销过去已接受的全局角色状态、时间线或伏笔事实；如果旧事实已不成立，需要明确提出相应修正并审阅差异。

### 长篇如何加载章级历史

默认请求保护当前全局状态；目标章可加载当前证据的派生视图，较早修订记录和其它章节的全部证据不会每轮自动发送。它们仍保存在原文件中，可从本轮固定快照按需读取。明确选择的原文件保持保护，不会为了缩小预算而静默删节。

健康提示与章节覆盖说明仅发送数量汇总和有限样本，因此「报告省略了其它章节」不代表删除了章节或证据。上下文面板的 source hash 对应原文件，payload hash 对应实际组装后的内容；派生视图可能比原文件短。

### 必要上下文仍超限时

看到「必要上下文超出预算」或 `CONTEXT_PROTECTED_OVERFLOW` 时：

1. 展开对应步骤，查看必要来源、消息估算和输入预算。
2. 缩小本轮任务，只保留相关的 Play Writing Reference 附件，避免在一条请求中加入大量无关材料。
3. 如果历史对话很长，开启新对话，重新选择目标文件并简要重述任务。
4. 如仍需较大上下文，核对当前模型是否适合，并在[模型设置](settings.md#模型上下文容量与用量)中选择可用模型。

不要为了消除提示而随意删掉小说约束或状态文件。本步超预算会在发送前停止；若这一轮前面的步骤已调用模型，它们仍可能有实际用量。

## 历史记录与当前范围

历史统计属于当前小说工作区，重新打开应用后可以在下拉框中选择已经保存的会话。它提供统计回看，不等于恢复或重放完整聊天。

历史读取只展示最近的有界记录；出现相应提示时，较早的记录没有包含在本次显示中。部分记录损坏、尾行不完整或读取失败时，界面会说明，不应把缺失记录当成没有使用模型。

若提示「本轮统计未能持久化；实时数据仍可查看」，本轮写作结果仍应按回复和 PendingAction 判断；缺少历史统计不会自动撤销已批准的文件。

当前统计覆盖标准 Writing Copilot 请求。References 的专用分析和 Play 的专用模型回合尚未汇总到此面板，不能用这里的合计代表整个应用的全部模型用量。
