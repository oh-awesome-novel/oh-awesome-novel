# 工作区与文件

一个工作区就是一本小说的本地目录。正文、人物和设定可以在文件管理器中找到，也能由你选择的文本编辑器打开。聊天用于协作，文件保存最终采用的内容。

## 管理项目列表

在启动器的「项目」页，可以按项目名、小说名或路径搜索已有记录。

| 操作 | 作用 |
| --- | --- |
| 新建 | 在空目录中建立 OAN 工作区，随后进入新建引导 |
| 打开 | 验证已有 OAN 目录并加入最近项目列表 |
| 进入 / 双击项目行 | 切换到该工作区 |
| 改名 → 保存 | 修改最近项目列表的显示名称，不移动目录、不重命名正文文件 |
| 移除 | 从最近列表中移除记录，磁盘上的小说目录仍保留 |
| 刷新 | 重新读取项目列表及目录有效性 |

列表出现目录失效提示时，先检查目录是否移动、磁盘是否挂载，以及路径是否仍可读取。需要时使用「打开」重新登记正确位置。

## 认识写作界面

顶部可以在 `Writing` 与 `Play` 模式间切换。写作模式通常包括三个区域：

- **左栏**：新对话、历史对话、文件和章节导航。
- **中央**：Copilot 对话、工具活动与输入框。
- **右栏**：文件预览、修改差异、待审批项、健康提示、Git、写作配置和参考资料。

左右侧栏可以收起；找不到文件或审批按钮时，先用顶部「固定文件栏」或「显示审阅栏」恢复侧栏。

图标按钮的悬浮提示部分使用英文，右栏页签对应如下：

| 页签 | 用途 |
| --- | --- |
| File | 只读查看当前文件 |
| Diff | 查看选中待审批项的修改差异 |
| Approval | 接受或拒绝待审批修改 |
| Health | 查看摘要、状态、时间线和伏笔等提示 |
| Git | 查看工作区变更与提交历史 |
| Profiles | 管理写作偏好与拆书输出配置 |
| Refs | 导入、分析和选择参考资料 |

## 浏览文件和章节

### 文件树

点击左侧「文件」，展开目录，再点击文件名。右侧 `File` 会显示内容和路径。当前文件查看器是**只读预览**，没有直接编辑或保存正文按钮。

你可以通过 Copilot 提出修改，也可以用顶部外部编辑器菜单打开工作区。菜单提供 VS Code、Zed 和 WebStorm；需要本机已安装相应应用并能被启动。手工编辑后，应检查 Git 变更，再继续 AI 写作。

### 章节导航

点击左侧「章节」，或顶部 `Chapters`，按卷浏览正文。章节通常使用以下路径：

```text
chapters/
└── 0001/
    ├── 0000.md    卷信息
    ├── 0001.md    第一章
    └── 0002.md    第二章
```

`0000.md` 是卷信息，不会作为正文章节出现在章节列表中。章节标题和路径同时显示，方便分辨同名章节。

[![章节导航与右侧只读正文预览](/screenshots/chapter-reader.jpg)](/screenshots/chapter-reader.jpg)

新增或手动修改文件后，如果列表显示「需要重新扫描」「未生成索引」或内容未更新，点击「重新扫描章节」。扫描更新导航信息，不会替你改写正文。

### 搜索

顶部 `Search` 打开工作区搜索。输入正文里的中文短语、角色名、标题或文件路径，即可查找当前工作区已经保存的文本。

结果显示文件路径、首个命中的行号和片段。点击结果后，左侧文件树选中对应文件，右侧 `File` 打开并高亮该行。搜索不会自动发送 Copilot 请求。

每次查询都会重新读取文件；外部编辑、删除或重命名后，点击「刷新结果」。完整范围与限制见 [搜索与导出](search-and-export.md#搜索正文、标题与路径)。

### 导入旧稿

顶部「导入旧稿」用于将自己的 Markdown 正文拆成章节、调整卷章编号并预览差异。它只创建新章节，冲突需要重新映射；创建候选后仍需在 `Approval` 接受才会写入。文件格式、限制和操作步骤见[导入自己的旧稿](manuscript-import.md)。

### 导出正文

顶部下载图标的提示为 `Export manuscript`。点击后，在「导出正文」窗口选择「下载 Markdown」或「下载 TXT」，将已保存的正文章节按卷号、章节号合并下载。

导出会保留章节标题，去除 YAML 元数据和卷信息文件，不包括尚未接受的 AI 草稿、设定或参考资料。它不会改动工程文件。格式差异、下载位置和故障处理见 [搜索与导出](search-and-export.md#导出整本正文)。

## 小说内容放在哪里

| 目录 | 主要内容 |
| --- | --- |
| `chapters/` | 按卷组织的正文 |
| `characters/` | 角色档案 |
| `world/` | 地点、组织、规则等世界设定 |
| `outline/` | 大纲与章节规划，存在相关文件时使用 |
| `summaries/` | 章节等摘要 |
| `state/` | 人物与故事当前状态 |
| `timeline/` | 已确认事件与时间顺序 |
| `foreshadow/` | 伏笔及其推进记录 |
| `.oan/` | 工作区配置、创作约束和写作配置等 |

新建工作区会先建立基础目录；空目录并不代表已经写好角色卡、正文或摘要。日常以界面里实际能打开的文件为准。

应用级模型配置和最近项目列表存放在小说目录之外，默认位于用户目录下的 `.oan`。因此，复制一部小说的工作区不会自动复制你的模型 API Key。

## 查看项目健康

打开右侧 `Health`，查看当前作品是否存在缺失摘要、状态陈旧、时间线缺口或待处理伏笔等提示。它们用来提示下一步需要检查的地方，不能替代对故事逻辑的人工判断。

例如，完成章节后出现摘要缺失提示，可以先让 Copilot 总结本章，再审阅它提出的更新。不要仅因为出现健康提示，就接受没有核对来源的修改。

摘要和章级状态的来源会区分 current、stale、missing、unverified。正文改动会使旧来源过期，单纯 touch 文件不会；无来源记录的手写摘要属于未验证参考。状态提示不会自动修改或撤销小说事实，详见[上下文与用量](usage.md#章节摘要与状态是否仍有效)。

## 对话与小说文件的区别

「新对话」用于开始另一个讨论主题，「历史对话」用于在当前界面会话中切换。当前历史列表保存在界面内存中，尚未提供从磁盘恢复完整聊天记录的界面；刷新页面、退出工作区或重启应用后，不应依赖它恢复之前的对话。

需要长期保留的正文、设定和决定，应确认它们已经成为实际文件，并在 [Git](git.md) 中记录。待审批项有独立存储，重新进入工作区时可从 `Approval` 查看；不要为了清空聊天而手动删除工作区内部数据。
