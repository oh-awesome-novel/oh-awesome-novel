# 写作与 Copilot

Copilot 适合讨论人物动机、规划场景、检查章节和提出局部修改。稳定的使用方式是：选定目标 → 说明本轮任务 → 阅读结果 → 审阅文件差异 → 接受后继续下一轮。

## 先确认本轮目标

在左侧文件树或章节导航打开需要处理的文件，确认右侧 `File` 的路径。普通编辑以当前选中文件为目标；`/整理本章` 则将它作为正文证据，生成摘要、状态及相关对象的待审批更新。

::: info 当前写作入口的范围
普通编辑一次向 Copilot 指定一个已选中文件。没有选中文件时，可以讨论和分析，但不会获得普通编辑的文件写入权限。只在聊天里写出另一个文件路径，不会自动把它加入可修改范围。

`/整理本章` 是范围明确的例外：先打开一个已编号的正文章节，系统据此生成摘要、状态、时间线、伏笔及已有角色成长记录的同一项审批。输出由正文证据和既有对象决定，所选正文保持不变。

「写下一章」「生成角色卡」等快捷按钮会准备请求；它们目前不能替代新文件创建或多个目标文件的选择入口。新建空工作区应先完成讨论和规划；不要把聊天生成的草稿当成已经保存的首章。
:::

请求的任务也要与文件匹配：章节审稿选择章节，直接更新人物状态选择相应状态文件，规划大纲选择已有大纲文件。章节整理可以跨上述对象生成受限结算；其它编辑仍需明确选择目标。

## 发送一条明确的请求

确认已在 [模型设置](settings.md) 中保存可用的默认模型，然后：

1. 选择本轮要处理的文件。
2. 点击输入框上方的快捷命令，或直接输入需求。
3. 补充目标、需要保留的事实和本轮范围。
4. 点击发送箭头，或使用输入框显示的发送快捷键。

快捷命令只会填入输入框，不会自动发送；点击时会替换输入框里原有的内容，已有长提示时先保留副本。

下面是针对已打开章节的示例：

```text
/审稿
请检查当前 chapters/0001/0002.md：
1. 林照为什么愿意把信交给顾远，动机是否充分？
2. 对话中有没有角色突然知道未曾获知的信息？
3. 保留剧情顺序，只对明显重复的措辞提出局部修改。
先说明问题和依据；有文件修改时生成待审批项。
```

把「更好一点」改成可以判断的要求，例如保留视角、减少重复信息、加强某处因果或限制修改到一个场景，通常更容易审阅结果。

## 快捷命令适合做什么

| 命令 | 适合提出的任务 |
| --- | --- |
| `/规划大纲` | 梳理全书主线、阶段目标和关键转折 |
| `/规划下一卷` | 讨论下一卷的矛盾升级和收束方向 |
| `/规划下一章` | 明确章节目标、冲突、场景和结尾钩子 |
| `/写下一章` | 根据规划草拟章节；实际可改范围取决于已选中的目标 |
| `/生成角色卡` | 梳理角色动机、关系和行为边界，处理已有角色对象时先选对应文件 |
| `/审稿` | 检查动机、因果、信息顺序和表达问题 |
| `/去AI味` | 针对重复句式、空泛总结等提出局部修订 |
| `/整理本章` | 从当前正文提取有引文证据的观察，提出摘要、状态、时间线、伏笔与已有角色成长记录的合并 |
| `/更新状态` | 更新已选中的故事或人物状态文件 |
| `/补伏笔` | 检查已选中的伏笔记录并提出补充 |

多数命令用于明确本轮任务，不保证每次都产生文件修改。模型可能先提问或返回分析。`/整理本章` 有专门的正文选择与证据校验；没有选对章节时会提示错误，不会退回普通编辑。

## 一个可重复的写作节奏

### 写之前：先规划

围绕本章只回答几个问题：谁想达成什么、阻力是什么、哪些事实需要读者知道、章末发生什么变化。用 `/规划下一章` 提出具体要求；需要持久保存规划时，确认已选中相应规划文件，并审阅待审批项。

### 写之后：先审正文

打开已完成的章节，用 `/审稿` 检查问题。可以先请求只分析，确认方向后再发一次局部修订请求。这样便于分辨你接受的是故事方向还是具体措辞。

### 定稿后：整理连续性

使用下方的 `/整理本章` 流程保存本章有正文证据的变化。阅读观察记录中的引用和置信度，再审阅每份文件的差异；无法确定的解释与合并冲突保留在报告中。

每次接受修改后，查看文件和 Git 状态，再开始依赖该结果的下一轮。刚接受一项修改时，之前生成的其他待审批项可能已经过期，需要重新生成。

## 整理本章：保存有证据的摘要与状态

1. 在「章节」中打开一个正式章节，例如 `chapters/0001/0002.md`。必须选中 `chapters/四位卷号/四位章号.md` 形式的正文；不能选摘要、状态文件或只在聊天里给出路径。
2. 点击「整理本章」，或输入下面的请求并发送。

   ```text
   /整理本章
   请整理当前已打开的章节。
   只记录正文已经发生、能够指出原文位置的事实。
   对角色动机、传闻和未揭晓信息保留不确定性。
   先给出观察记录与引用，再提出摘要、状态、时间线、伏笔和已有角色成长记录的待审批修改。
   ```

3. 阅读返回的 ObservationLog（观察记录），核对每条观察的主体、内容、置信度、原文引句和行号，以及尚未解决的歧义。
4. 出现标题为「整理本章 0001/0002」的 PendingAction 后，打开 `Diff`，逐项检查实际输出。没有新增事实、没有高置信度观察或全部存在冲突时，可能只有报告。
5. 确认后在 `Approval` 点击 `Accept`。不认可某条解释时先 `Reject`，说明问题后重新整理。

| 输出 | 内容与范围 |
| --- | --- |
| `summaries/chapter/0001/0002.md` | 本章摘要，记录高置信度观察、证据行号与来源版本 |
| `state/chapters/0001/0002.yaml` | 本章状态记录，保留同一批观察及逐行引文证据 |
| `state/characters.yaml` | 既有角色的伤势、位置、情绪、持有物等受支持状态字段，核对旧值后更新 |
| `timeline/events.yaml` | 有正文证据的事件，保留既有记录，重复证据不重复新增 |
| `foreshadow/active.yaml`、`foreshadow/resolved.yaml` | 明确区分新增、提及、推进、回收、延期；回收时在同一审批中移动记录 |
| `characters/<角色ID>/growth.md` | 向已有角色追加有证据的成长记录，保留作者原文 |

卷号和章号由所选正文决定，角色必须匹配既有对象，作者不需要手工指定输出路径。仅有实际变化的文件进入同一项审批，一次 Accept 接受其中全部差异。重新整理相同证据不会重复添加；遇到作者改过的结算记录或旧值不匹配时，先查看冲突报告。

系统会校验引句是否逐字匹配正文的完整行、行号是否位于正文范围，以及引用是否来自同一版本。正文开头的 YAML 元数据不作为故事证据。**引文匹配只证明引用来源正确，不证明模型对人物动机、因果或事件性质的解释正确**，这些仍需作者判断。

只有 `high`（高）置信度且没有标记歧义或合并冲突的观察进入文件；`medium`、`low` 和未解决歧义只保留在报告中。本流程不会把大纲、未来计划或外部参考当作已经发生的正文事实。

状态合并支持明确的文本字段，不会覆盖已有列表、字典等复杂值；人物更新限于成长记录，不会重写人设。较早编号章节不能覆盖来自较晚章节的状态；倒叙等特殊时间关系仍需作者判断。

修改正文后重新整理，会区分本章当前证据和历史快照；以前已经接受的全局事件、状态或成长记录不会自动撤销。若正文修订改变了这些事实，请明确提出修正并审阅对应差异。

生成提案后若正文、目标文件、参与合并的人物记录或角色文件清单发生变化，Accept 会拒绝旧依据；新建同名角色也不能悄悄改变身份判断。先确认最新文件，再重新整理；详见[审阅与接受修改](review.md#审阅整理本章的结果)。

## 查看上下文与用量

在 Copilot 消息区下方点击「上下文与用量」，可以查看本轮每次模型调用的输入估算、服务端返回用量、来源记录和预算状态。已有统计时，入口会显示约多少 tokens 和模型调用次数。

`Estimated` 是本地估算，`Actual` 是模型服务返回的数据；`unavailable` 表示没有获得用量，不表示免费。完整读法与预算问题处理见[上下文与用量](usage.md)。

## 参考资料与写作偏好

右侧 `Profiles` 可以选择固定的写作提醒和拆书输出范围；中央 Copilot 顶部会显示当前配置摘要。修改配置从下一次请求生效。详见 [模型与偏好设置](settings.md#写作配置-writing-profiles)。

参考书分析结果通过 `Refs` 管理，使用范围见 [参考资料](references.md)。Play 产生的写作参考可以在 Copilot 的参考选择区明确勾选；选择参考不会自动改写正文。详见 [Play 模式](play.md)。

输入框左下角的 `Attach context` 加号当前处于禁用状态，不要把它当作通用附件上传入口。

## 停止生成与重新开始

生成过程中可以点击「停止」。尚未形成待审批项的草稿不会因此自动保存为小说文件。若停止前已经出现持久化的 PendingAction，它仍需你在 `Approval` 中接受或拒绝。

重试前先看回复和待审批列表，避免针对同一修改连续提交多次。需要换题目时可以点击「新对话」；历史聊天的保存限制见 [工作区与文件](workspace.md#对话与小说文件的区别)。

当模型报错、没有生成修改或审批被拒绝时，按 [常见问题](faq.md) 检查。不要用重复点击 `Accept` 来解决文件已经变化的问题。
